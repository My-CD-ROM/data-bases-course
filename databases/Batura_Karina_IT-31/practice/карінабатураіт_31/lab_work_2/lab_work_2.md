1. Пояснення до Завдання 4 (NULL vs = NULL)

В SQL значення NULL означає, що дані просто відсутні або ще не відомі. Коли ми порівнюємо будь-яку комірку з NULL через звичайне дорівнює (наприклад, description = NULL або price = NULL), система не може відповісти "так" чи "ні", а теж повертає "невідомо". Оскільки команда WHERE відбирає тільки ті рядки, де відповідь чітко "так", такий запит ніколи нічого не знайде і видасть порожній список. Щоб правильно знайти порожні або заповнені комірки, в SQL вигадали спеціальні команди IS NULL та IS NOT NULL.

2. Відповіді на контрольні питання

1. Чому запит WHERE price = NULL завжди повертає порожній результат? Що потрібно написати замість цього?
Тому що SQL працює за потрійною логікою: правда, брехня та невідомо. Звичайне дорівнює при порівнянні з відсутнім значенням дає результат "невідомо", а блок WHERE пропускає тільки точну правду.
Замість цього потрібно використовувати команду WHERE price IS NULL.

2. Чим WHERE принципово відрізняється від HAVING?
Команда WHERE відсіює звичайні рядки з таблиці ще до того, як їх почнуть групувати або рахувати. Вона не вміє працювати з підсумковими функціями на кшталт суми чи середнього значення.
Команда HAVING, навпаки, фільтрує вже готові згруповані блоки даних після виконання GROUP BY.

3. У якому випадку варто уникати SELECT *, і чому саме?
Зірочку краще не використовувати у реальних проектах та робочому коді з двох причин. По-перше, база даних витрачає зайві ресурси та пам'ять на вивантаження непотрібної інформації. По-друге, якщо хтось змінить порядок чи кількість колонок у таблиці, програма може видати помилку, бо очікувала зовсім інші дані.

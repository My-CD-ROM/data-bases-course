## Завдання 1 та 2. Обґрунтування дій ON DELETE

Для товару обрано RESTRICT, тому що не можна видаляти товар із бази, якщо його вже купували. Це зламає фінансову звітність та історію продажів. Якщо товар більше не продається, його просто лишають у базі.
Для покупця обрано CASCADE, бо якщо клієнт вирішить видалити свій акаунт із магазину, то за правилами приватності всі його замовлення мають видалитися разом із ним.

## Завдання 4. Перевірка зовнішнього ключа
Щоб перевірити роботу зовнішніх ключів, виконано спробу додати замовлення з неіснуючим товаром (product_id = 9999):
INSERT INTO orders (product_id, customer_id, order_date, quantity) VALUES (9999, 1, '2026-09-21', 1);
Точне повідомлення про помилку з терміналу:
Error near line 61: FOREIGN KEY constraint failed
Це підтверджує, що команда PRAGMA foreign_keys = ON працює і блокує некоректні дані.

## Відповіді на контрольні питання
1. Навіщо PRAGMA foreign_keys = ON:
В SQLite перевірка зв'язків за замовчуванням вимкнена. Сам по собі FOREIGN KEY лише описує структуру, але без цієї команди база дозволить вставити неіснуючі ID. Налаштування діє тільки на поточну сесію, тому команду треба вводити щоразу при підключенні.
2. Різниця між PRIMARY KEY та FOREIGN KEY:
PRIMARY KEY — це унікальний номер рядка у власній таблиці, який відрізняє його від інших. FOREIGN KEY — це посилання на PRIMARY KEY з іншої таблиці, яке пов'язує їх між собою.
3. Різниця між RESTRICT та CASCADE:
RESTRICT забороняє видаляти запис, якщо на нього є посилання в іншій таблиці, і видає помилку. CASCADE при видаленні головного запису автоматично видаляє й усі залежні записи з іншої таблиці. Вибір залежить від того, чи потрібно зберігати пов'язану історію.

\# Практична робота 10. Відбір груп за допомогою HAVING



\## Мета роботи



Застосувати оператор `HAVING` для фільтрації згрупованих даних за агрегатними значеннями, навчитися розрізняти використання `WHERE` та `HAVING`, а також застосувати `LEFT JOIN` для пошуку груп з малою кількістю пов'язаних записів.



\## Завдання 1. HAVING на COUNT



```sql

SELECT product\_id, COUNT(\*) AS orders\_count

FROM orders

GROUP BY product\_id

HAVING COUNT(\*) > 1;

```



Результат:



```text

(1, 4)

(2, 2)

(3, 2)

```



Запит групує замовлення за `product\_id` та підраховує кількість замовлень для кожного товару. Умова `HAVING COUNT(\*) > 1` залишає тільки товари, які мають більше одного замовлення.



Межею `1` обрано тому, що потрібно знайти товари, які замовляли більше одного разу.



\## Завдання 2. HAVING на іншій агрегатній функції



```sql

SELECT product\_id, SUM(quantity) AS total\_quantity

FROM orders

GROUP BY product\_id

HAVING SUM(quantity) > 3;

```



Результат:



```text

(1, 5)

(3, 5)

```



Функція `SUM(quantity)` визначає загальну кількість одиниць товару в усіх замовленнях. У результаті залишаються товари, загальна кількість яких перевищує 3.



\## Завдання 3. WHERE + GROUP BY + HAVING



```sql

SELECT product\_id, AVG(quantity) AS average\_quantity

FROM orders

WHERE status = 'виконано'

GROUP BY product\_id

HAVING AVG(quantity) > 1.5;

```



Результат:



```text

(2, 2.0)

(3, 3.0)

```



`WHERE status = 'виконано'` відсіює окремі рядки таблиці `orders` та залишає тільки виконані замовлення.



`GROUP BY product\_id` групує залишені замовлення за товарами.



`HAVING AVG(quantity) > 1.5` відсіює вже сформовані групи та залишає тільки ті товари, для яких середня кількість товару у виконаних замовленнях більша за 1.5.



Отже, `WHERE` фільтрує окремі рядки до групування, а `HAVING` фільтрує готові групи за агрегатним значенням.



\## Завдання 4. Свідома помилка WHERE з агрегатом



Було виконано неправильний запит:



```sql

SELECT product\_id, COUNT(\*) AS orders\_count

FROM orders

WHERE COUNT(\*) > 1

GROUP BY product\_id;

```



SQLite повернула помилку:



```text

misuse of aggregate: COUNT()

```



Причина помилки полягає в тому, що `WHERE` виконується до групування та не може використовувати агрегатні функції. Для умов на агрегатні значення потрібно використовувати `HAVING`.



\## Завдання 5. LEFT JOIN + GROUP BY + HAVING



```sql

SELECT products.id, products.name, COUNT(orders.id) AS orders\_count

FROM products

LEFT JOIN orders ON orders.product\_id = products.id

GROUP BY products.id, products.name

HAVING COUNT(orders.id) < 2;

```



Результат:



```text

(4, 'Худі Urban', 1)

(5, 'Куртка Winter', 1)

```



`LEFT JOIN` використано для того, щоб зберегти всі товари з таблиці `products`, навіть якщо вони не мають пов'язаних замовлень.



`GROUP BY` об'єднує замовлення за кожним товаром, а `COUNT(orders.id)` визначає кількість замовлень.



Умова `HAVING COUNT(orders.id) < 2` залишає товари, які мають менше двох замовлень.



Якби замість `LEFT JOIN` використати `INNER JOIN`, товари без замовлень були б вилучені до групування і не могли б потрапити до результату.



\## Контрольні питання



\### 1. Чому не спрацює перенесення COUNT(\*) > 1 після GROUP BY зі словом WHERE?



`WHERE` використовується для фільтрації окремих рядків до групування та не може містити агрегатні функції. Потрібно використовувати `HAVING`:



```sql

GROUP BY product\_id

HAVING COUNT(\*) > 1;

```



\### 2. Що зміниться, якщо LEFT JOIN замінити на INNER JOIN?



При використанні `INNER JOIN` товари без пов'язаних замовлень будуть вилучені ще до виконання `GROUP BY`. Тому `HAVING` не зможе знайти такі групи.



\### 3. У якому порядку використовуються WHERE, GROUP BY і HAVING?



Якщо потрібно прибрати окремі непотрібні рядки та залишити тільки групи із сумою більше певного значення, запит матиме вигляд:



```sql

SELECT product\_id, SUM(quantity) AS total\_quantity

FROM orders

WHERE status != 'скасовано'

GROUP BY product\_id

HAVING SUM(quantity) > 3;

```



Правильний порядок запису команд:



```text

FROM → WHERE → GROUP BY → HAVING → SELECT

```



`HAVING` не можна поставити перед `GROUP BY`.



Логічний порядок виконання запиту відрізняється від порядку його написання. Спочатку визначається джерело даних через `FROM`, потім застосовується `WHERE`, виконується `GROUP BY`, після цього `HAVING`, і лише потім формується результат `SELECT`.



\## Висновок



Під час практичної роботи було застосовано `GROUP BY` та `HAVING` для фільтрації груп за агрегатними значеннями. Було використано функції `COUNT`, `SUM` та `AVG`.



Також було розглянуто різницю між `WHERE` та `HAVING`, зафіксовано помилку `misuse of aggregate: COUNT()` при неправильному використанні агрегатної функції у `WHERE`.



За допомогою `LEFT JOIN` було отримано товари з малою кількістю пов'язаних замовлень, включаючи можливі групи без замовлень.

Відповіді на контрольні питання
1. Чому WHERE price = NULL завжди повертає порожній результат?
У SQL значення NULL означає відсутність або невідомість значення. Його не можна порівнювати за допомогою звичайного оператора =.

Тому умова:

WHERE price = NULL

не працює очікуваним чином, оскільки результат такого порівняння не є TRUE.

Щоб перевірити, чи має стовпець значення NULL, потрібно використовувати:

WHERE price IS NULL

А щоб знайти рядки, де значення не є NULL:

WHERE price IS NOT NULL

Відповідь: замість price = NULL потрібно писати price IS NULL.

2. Чим WHERE принципово відрізняється від HAVING?
WHERE і HAVING використовуються для фільтрації, але працюють на різних етапах виконання запиту.

WHERE фільтрує окремі рядки таблиці до групування.

HAVING фільтрує вже сформовані групи після GROUP BY.

Наприклад:

SELECT category, AVG(price)
FROM products
WHERE price > 100
GROUP BY category;

Тут WHERE спочатку відбирає товари з ціною понад 100, а вже потім вони групуються за категоріями.

Якщо потрібно залишити тільки ті групи, у яких середня ціна більша за 500:

SELECT category, AVG(price)
FROM products
GROUP BY category
HAVING AVG(price) > 500;

Отже: WHERE працює з рядками, а HAVING — з групами результатів.

3. У якому випадку варто уникати SELECT * і чому?
SELECT * варто уникати, особливо в робочих, великих або довготривалих запитах, коли потрібні не всі стовпці, а лише конкретні.

Наприклад, замість:

SELECT *
FROM products;

краще написати:

SELECT id, name, price
FROM products;

Основні причини:

зайві дані — запит повертає стовпці, які можуть бути непотрібними;

нижча ефективність — передається більше даних, особливо якщо таблиця має багато стовпців;

гірша читабельність — з запиту не зрозуміло, які саме дані потрібні;

проблеми при зміні структури таблиці — якщо додати новий стовпець, SELECT * автоматично почне його повертати, що іноді може порушити логіку програми.

Отже: SELECT * зручний для швидкого перегляду даних або навчання, але в реальних запитах краще явно вказувати потрібні стовпці.

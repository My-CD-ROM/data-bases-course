# Практика 4 — звіт (Варіант 6: Готель)

## Завдання 1-2. Обґрунтування ON DELETE

- **room_id → rooms, ON DELETE RESTRICT**: історія бронювань номера — фінансово важлива інформація, яка має зберігатись незалежно від того, чи номер досі в експлуатації. RESTRICT не дозволяє видалити номер, поки на нього є хоч одне бронювання.
- **guest_id → guests, ON DELETE CASCADE**: якщо запис про гостя видаляється (наприклад, за запитом на видалення персональних даних), пов'язані з ним бронювання втрачають самостійну цінність без ідентифікованого гостя і видаляються разом з ним.

## Завдання 4. Текст помилки

При спробі вставити бронювання з `room_id = 9999` (номера, якого не існує), SQLite видала:

Runtime error: FOREIGN KEY constraint failed (19)


Це підтверджує, що `PRAGMA foreign_keys = ON;` справді активна на з'єднанні.

## Завдання 5. Звірка з ER-діаграмою Практики 3

Фактично реалізована структура повністю відповідає ER-діаграмі з Практики 3: назви таблиць (`rooms`, `guests`, `bookings`), назви колонок і напрямки обох зовнішніх ключів (`room_id → rooms.id`, `guest_id → guests.id`) збігаються один в один з тим, що було спроєктовано. Змін не вносилось.

# Практика 15 - звіт (Варіант 6: Готель)

## Завдання 1
План до індексу: SCAN bookings. SQLite переглядає всі рядки таблиці й у кожному перевіряє умову room_id = 3.

## Завдання 2
Після CREATE INDEX idx_bookings_room план змінився на SEARCH bookings USING INDEX idx_bookings_room (room_id=?). Замість повного перегляду SQLite іде в індекс і переходить лише до рядків із потрібним room_id. Результат запиту той самий, змінився спосіб пошуку.

## Завдання 3
До композитного індексу SQLite використовував індекс лише на room_id: за ним знаходив бронювання номера, а умову guest_id перевіряв по черзі в кожному знайденому рядку. Після створення індексу (room_id, guest_id) обидві умови перевіряються прямо в індексі: (room_id=? AND guest_id=?). Індекс лише на першій колонці звужує пошук менше, бо друга умова лишається поза індексом.

## Завдання 4
Без індексу план містив окремий крок USE TEMP B-TREE FOR ORDER BY: SQLite збирав усі рядки й будував тимчасове дерево для сортування. Після індексу на check_in_date цей крок зник: SQLite читає таблицю в порядку індексу (SCAN bookings USING INDEX idx_bookings_checkin), і результат уже відсортований.

## Завдання 5
Після DROP INDEX idx_bookings_room план для room_id = 3 не повернувся до SCAN, бо композитний індекс idx_bookings_room_guest починається з тієї самої колонки room_id, і SQLite використовує його. Запит до sqlite_master підтвердив, що idx_bookings_room зі списку індексів зник.

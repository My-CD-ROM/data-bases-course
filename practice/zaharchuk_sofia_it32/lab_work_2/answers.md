# Практика 2 — письмові відповіді (варіант 6: Готель)

## Чому WHERE status = NULL не працює
Порівняння `= NULL` завжди повертає NULL (не TRUE і не FALSE), бо SQL
розглядає NULL як "невідоме значення" — а порівняти щось із невідомим
неможливо отримати чітку відповідь "так" чи "ні". WHERE залишає в
результаті лише рядки, де предикат дав саме TRUE, тому рядки з
результатом NULL відкидаються так само, як і FALSE — і запит завжди
повертає порожній результат, навіть якщо в таблиці реально є NULL-рядки.
Замість цього потрібно писати `WHERE status IS NULL`.

## Чим WHERE відрізняється від HAVING
WHERE фільтрує окремі рядки таблиці ще до будь-якого групування даних.
HAVING, навпаки, фільтрує вже сформовані групи (результат GROUP BY) —
тобто застосовується після того, як рядки вже об'єднані в групи.

## Коли варто уникати SELECT *
У коді, що виконується регулярно (звіти, застосунки), або в навчальних
завданнях, що перевіряються. Явний перелік стовпців читабельніший (одразу
видно, які дані очікуються), стійкіший до зміни схеми таблиці (новий
стовпець не "проривається" непомітно в результат) і не передає зайві дані,
які ніхто не використовує. SELECT * доречний лише для швидкого ручного
перегляду даних.

## Пояснення щодо status IS NULL
Стовпець status початково був NOT NULL, але для завдання 4 знадобилось
дозволити невизначений статус (наприклад, щойно доданий номер, для якого
ще не визначили стан прибирання) — тому таблицю було перестворено з
status без NOT NULL, зберігши всі попередні дані.

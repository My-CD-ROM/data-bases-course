# Обґрунтування вибору типів — таблиця rooms (Варіант 6: Готель)

- **id — INTEGER PRIMARY KEY**: у SQLite цей стовпець стає синонімом внутрішнього
  rowid, автоматично генерує унікальні цілі значення при вставці без явного
  вказання id, тому логічно використовувати INTEGER для первинного ключа.

- **type — TEXT**: тип номера ("одномісний", "люкс" тощо) — це текстове
  значення змінної довжини, не бере участі в арифметичних операціях,
  тому TEXT — єдиний доречний вибір (affinity TEXT).

- **price_per_night — REAL**: ціна за ніч може містити дробову частину
  (наприклад, 850.50 грн), над нею виконуються обчислення (сума, середнє),
  тому обрано REAL, а не TEXT — щоб SQLite зберігав і опрацьовував значення
  саме як число з плаваючою комою.

- **capacity — INTEGER**: місткість номера — завжди ціле число осіб,
  над яким можливі порівняння й сортування (наприклад WHERE capacity >= 2),
  тому INTEGER, а не TEXT, який ускладнив би такі числові фільтри.

- **status — TEXT**: статус номера ("вільний", "зайнятий", "на прибиранні") —
  це категоріальне текстове значення з обмеженим набором варіантів,
  тому TEXT-affinity відповідає природі даних.

# Практична робота №15

### Завдання 2. Створення індексу за зовнішнім ключем

Було створено індекс `idx_sales_client` для колонки `client_id`.

До створення індексу план показував `SCAN membership_sales`, тобто SQLite переглядав усю таблицю.

Після створення індексу план змінився на `SEARCH membership_sales USING INDEX idx_sales_client (client_id=?)`. Це означає, що SQLite використовує індекс для пошуку записів за клієнтом.

### Завдання 3. Складений індекс

Було створено складений індекс `idx_sales_membership_client` для колонок `membership_id` та `client_id`.

До його створення SQLite використовував індекс `idx_sales_client` і шукав записи за `client_id`, а потім перевіряв `membership_id`.

Після створення складеного індексу план показав використання обох колонок: `membership_id=? AND client_id=?`.

Отже, складений індекс краще підходить для запитів, у яких одночасно використовуються обидві умови.

### Завдання 4. Індекс для сортування

Було створено індекс `idx_sales_purchase_date` для колонки `purchase_date`.

До створення індексу план містив `USE TEMP B-TREE FOR ORDER BY`, тобто SQLite використовував тимчасову структуру для сортування.

Після створення індексу SQLite почав використовувати `idx_sales_purchase_date`. Тимчасове сортування більше не потрібне, оскільки записи читаються в порядку індексу.

### Завдання 5. Видалення індексу

Індекс `idx_sales_client` було видалено командою `DROP INDEX`.

Після видалення план знову показав `SCAN membership_sales`. Це підтверджує, що для пошуку за `client_id` SQLite більше не використовує цей індекс.

Перевірка таблиці `sqlite_master` підтвердила, що індекс видалено. У базі залишилися складений індекс і індекс дати покупки.

## Контрольні питання

**1. Чому `EXPLAIN QUERY PLAN` показує саме план, а не результат запиту, і навіщо перевіряти план окремо?**

`EXPLAIN QUERY PLAN` показує, як SQLite планує виконати запит, а не самі дані. Це потрібно, щоб перевірити ефективність запиту: чи використовується індекс, чи відбувається повне сканування таблиці.

**2. Чому індекс лише на першій із двох колонок дає менший ефект, ніж складений індекс?**

Одноколонковий індекс допомагає шукати лише за однією колонкою. Складений індекс охоплює обидві колонки, тому SQLite може використовувати обидві умови пошуку без додаткової перевірки другої колонки після пошуку.

**3. Яка ціна створення індексу і чому не варто індексувати кожну колонку?**

Індекси займають додаткове місце на диску та сповільнюють додавання, зміну й видалення даних, оскільки їх потрібно оновлювати. Тому варто індексувати насамперед колонки, які часто використовуються в умовах пошуку, з'єднаннях таблиць і сортуванні.

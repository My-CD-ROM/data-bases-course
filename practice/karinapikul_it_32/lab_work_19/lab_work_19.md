# Практична робота №19

## Контрольні питання

### 1. Чим PostgreSQL як клієнт-серверна СУБД відрізняється від SQLite і яка в ньому ієрархія об’єктів?

PostgreSQL — це клієнт-серверна система, у якій сервер окремо зберігає бази даних і обробляє запити клієнтів. SQLite не потребує окремого сервера, оскільки база даних зберігається в одному файлі.

Ієрархія PostgreSQL:
1. Сервер.
2. База даних.
3. Схема.
4. Об'єкти схеми: таблиці, представлення, функції та інші.

### 2. Чому саме GENERATED ALWAYS AS IDENTITY, а не старіший SERIAL, обрано як основний спосіб автоінкременту в цьому курсі і чим вони відрізняються по суті?

GENERATED ALWAYS AS IDENTITY — сучасний стандартний спосіб автоматичної генерації ID. SERIAL — старіший механізм, який створює послідовність і використовує її як значення за замовчуванням.

IDENTITY є спеціальною властивістю стовпця та забезпечує суворіший контроль над генерацією ідентифікаторів.

### 3. Чому таблиці-виміри потрібно перенести (і створити, і заповнити даними) перед фактовою таблицею, а не в довільному порядку?

Таблиці-виміри містять дані, на які посилається фактовa таблиця через зовнішні ключі. Спочатку потрібно створити й заповнити таблиці-виміри, щоб фактовa таблиця могла правильно посилатися на наявні записи. Інакше PostgreSQL не дозволить додати записи з неіснуючими ID.

### 4. Що сталося б, якби завдання 4 (виправлення лічильника) пропустити, і на якому саме кроці це призвело б до помилки?

Після імпорту CSV лічильник автоматичної генерації ID може залишитися на початковому значенні. Під час наступного INSERT без зазначення ID PostgreSQL може спробувати використати вже зайнятий ідентифікатор. Це призведе до помилки порушення унікальності первинного ключа SQLSTATE 23505.

### 5. Для чого потрібні pgAdmin і Query Tool і аналогами яких інструментів DB Browser for SQLite вони є?

pgAdmin — це графічний інструмент для керування PostgreSQL: створення баз даних, таблиць і перегляду записів. Він є аналогом графічного інтерфейсу DB Browser for SQLite.

Query Tool — це редактор для написання та виконання SQL-запитів. Його аналог у DB Browser for SQLite — вкладка Execute SQL.

### 6. Чому після перенесення бази в PostgreSQL для перевірки зовнішніх ключів більше не потрібна команда PRAGMA foreign_keys?

У SQLite зовнішні ключі потрібно окремо вмикати командою PRAGMA foreign_keys = ON для кожного підключення. У PostgreSQL перевірка зовнішніх ключів працює автоматично на рівні сервера, тому додатково вмикати її не потрібно.

Практична робота №5

Завдання 1. NOT NULL

Для поля birth_date таблиці clients встановлено обмеження NOT NULL.

Для перевірки було виконано:

INSERT INTO clients (last_name, first_name, phone) VALUES ('Karina', 'Pikul', '+380000000000');

Отримана помилка:

NOT NULL constraint failed: clients.birth_date (19)

Це означає, що поле birth_date не може бути порожнім.

Завдання 2. UNIQUE

Для поля phone таблиці clients встановлено обмеження UNIQUE.

Для перевірки було виконано вставку клієнта з номером телефону, який уже існує:

INSERT INTO clients (last_name, first_name, phone, birth_date) VALUES ('Karina', 'Pikul', '+380501112233', '2009-03-01');

Отримана помилка:

UNIQUE constraint failed: clients.phone (19)

Це означає, що номер телефону не може повторюватися.

Завдання 3. CHECK

Для поля price таблиці memberships встановлено:

CHECK (price > 0)

При спробі додати від’ємну ціну:

INSERT INTO memberships (type, duration_days, price, description) VALUES ('neznay', 10, -500, 'ww');

отримано помилку:

CHECK constraint failed: price > 0 (19)

Коректне значення було додано без помилки.

Завдання 4. DEFAULT

Для поля description таблиці memberships встановлено:

DEFAULT 'Без опису'

Було додано запис без зазначення description:

INSERT INTO memberships (type, duration_days, price) VALUES ('VIP', 15, 2500);

Після перевірки запису база даних автоматично встановила значення:

Без опису

Завдання 5. Перевірка CHECK через UPDATE

Було виконано:

UPDATE memberships SET price = -100 WHERE id = 1;

Отримана помилка:

CHECK constraint failed: price > 0 (19)

Отже, обмеження CHECK працює як під час INSERT, так і під час UPDATE.

Завдання 6. Обґрунтування обмежень

* NOT NULL — поле birth_date повинно завжди містити дату народження клієнта, тому воно не може бути порожнім.
* UNIQUE — номер телефону клієнта не повинен повторюватися.
* CHECK — ціна абонемента повинна бути більшою за нуль.
* DEFAULT — якщо опис абонемента не вказано, база автоматично встановлює значення Без опису.

Контрольні питання

1. Чому не можна просто додати CHECK через ALTER TABLE?

SQLite не підтримує додавання CHECK-обмеження до вже існуючої таблиці через ALTER TABLE ... ADD CONSTRAINT, тому таблицю потрібно перебудувати.

2. Що буде, якщо додати NOT NULL до стовпця, де вже є NULL?

Виникне помилка, тому що значення NULL не відповідають обмеженню NOT NULL. Спочатку потрібно замінити або заповнити NULL-значення.

3. Чим відрізняється CHECK після перебудови таблиці від CHECK у початковому CREATE TABLE?

Нічим. В обох випадках CHECK працює однаково: не дозволяє додавати або змінювати дані, які не відповідають умові.

4. Чому DEFAULT не можна перевірити через «порушення»?

Тому що DEFAULT не забороняє значення, а автоматично підставляє його, якщо поле не вказане. Тому потрібно додати запис без цього поля і перевірити, яке значення підставила база.

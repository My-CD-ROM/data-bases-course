Завдання 3. Пошук абонементів без продажів

Для пошуку абонементів, які не мають жодного продажу, використано LEFT JOIN та умову WHERE membership_sales.id IS NULL.

Запит повернув такі абонементи:
• Разовий
• Квартальний
• Пробний
• Тестовий
• Стандартний
Це означає, що для цих абонементів у таблиці membership_sales немає пов’язаних записів.

Завдання 4. Перевірка CROSS JOIN

Для перевірки використано запити:
SELECT COUNT() FROM clients;
SELECT COUNT() FROM memberships; 
SELECT COUNT(*) FROM clients, memberships;

Результат:
clients = 5
memberships = 9
clients, memberships = 45

Кількість рядків при CROSS JOIN дорівнює добутку кількості рядків двох таблиць:

5 × 9 = 45.

Тобто кожен клієнт комбінується з кожним абонементом. Такий запит зазвичай не потрібен для звичайного звіту, тому що він створює багато непотрібних комбінацій.

Завдання 5. Обґрунтування вибору JOIN

Завдання 1: використано INNER JOIN, тому що потрібно отримати тільки ті продажі, для яких є відповідний абонемент; якщо використати LEFT JOIN, у результат могли б потрапити також абонементи без продажів.

Завдання 2: використано INNER JOIN, тому що потрібно отримати тільки ті продажі, для яких є і відповідний абонемент, і клієнт; якщо замінити один INNER JOIN на LEFT JOIN, у результат могли б потрапити записи без відповідного абонемента або клієнта, а відповідне поле мало б значення NULL.

Завдання 3: використано LEFT JOIN, тому що потрібно знайти всі абонементи, у тому числі ті, які не мають продажів; якщо використати INNER JOIN, абонементи без продажів взагалі не потрапили б у результат.

Контрольні питання

1. Чому рядок з NULL у зовнішньому ключі ніколи не з’явиться в результаті INNER JOIN за цим ключем, а в LEFT JOIN — з’явиться?

INNER JOIN повертає тільки рядки, для яких є відповідне значення в обох таблицях. NULL не дорівнює жодному значенню, тому такий рядок не потрапить до результату INNER JOIN. LEFT JOIN зберігає всі рядки лівої таблиці, тому рядок із NULL у зовнішньому ключі з’явиться, а поля правої таблиці будуть NULL.

2. Що станеться з результатом Завдання 2, якщо один JOIN замінити на LEFT JOIN, а решту лишити INNER JOIN?

У результат можуть потрапити додаткові рядки, для яких немає відповідного запису в таблиці, приєднаній через LEFT JOIN. У таких рядках поля цієї таблиці матимуть значення NULL, але інші INNER JOIN все одно вимагатимуть відповідних записів.

3. Чим JOIN a, b WHERE a.id = b.a_id відрізняється від JOIN a JOIN b ON a.id = b.a_id за результатом, і чим — за ризиком помилки?

За правильних умов результат може бути однаковим, але запис із JOIN ... ON зрозуміліший і безпечніший, тому що умова об’єднання знаходиться безпосередньо біля JOIN. У старому кома-синтаксисі легше випадково пропустити умову зв’язку або отримати CROSS JOIN з великою кількістю зайвих рядків.

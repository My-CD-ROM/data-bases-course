Завдання 4. Перевірка ON DELETE
Прогноз
RESTRICT: я думаю, що видалити абонемент з id = 2 не вийде, тому що на нього є посилання в таблиці membership_sales. Пов’язані записи повинні залишитися.
CASCADE: я думаю, що якщо видалити клієнта з id = 1, то всі записи в membership_sales, які належать цьому клієнту, також автоматично видаляться.

У таблиці membership_sales використано два зовнішні ключі:
membership_id - memberships — ON DELETE RESTRICT;
client_id - clients — ON DELETE CASCADE.

RESTRICT
При виконанні:
DELETE FROM memberships
WHERE id = 2;
отримано помилку:
Runtime error: FOREIGN KEY constraint failed (19)
Абонемент id = 2 залишився в таблиці. Фактичний результат відповідає прогнозу.

CASCADE
До видалення клієнт id = 1 мав 3 пов’язані записи: id = 1, 4, 8.
Після виконання:
DELETE FROM clients
WHERE id = 1;
перевірка:
SELECT * FROM membership_sales
WHERE client_id = 1;
не повернула жодного рядка.
Пов’язані записи були автоматично видалені. Результат відповідає прогнозу.


Контрольні питання
1. Чим відрізняється SET колонка = колонка + 1 від конкретного числа?
колонка = колонка + 1 збільшує поточне значення на 1, а конкретне число повністю замінює старе значення.
2. Чому NOT NULL, UNIQUE і CHECK діють при UPDATE, а FOREIGN KEY залежить від PRAGMA?
NOT NULL, UNIQUE і CHECK SQLite перевіряє завжди, а FOREIGN KEY перевіряється тільки при увімкненому PRAGMA foreign_keys = ON.
3. Що змінилося б при ON DELETE CASCADE замість RESTRICT?
Пов’язані записи у фактовій таблиці також були б автоматично видалені.
4. Чому DELETE без WHERE небезпечний?
DELETE без WHERE видаляє всі рядки таблиці, а не один конкретний запис.

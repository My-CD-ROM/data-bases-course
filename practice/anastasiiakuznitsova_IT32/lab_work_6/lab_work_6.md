Для початку я перевірила запис у таблиці grades з id = 1.

Початкове значення оцінки було 90:
1|1|1|90|2026-09-01

Я виконала команду:
UPDATE grades
SET grade = 95
WHERE id = 1;

Після цього перевірила запис. Оцінка змінилася на 95:
1|1|1|95|2026-09-01

Отже, команда UPDATE змінила тільки потрібний запис.

Я змінила семестр для курсу з id = 3.

Виконала команду:
UPDATE courses
SET semester = 2
WHERE id = 3;

Після перевірки отримала:
3|Вища математика|4|2

Я використала UPDATE, тому що курс продовжує існувати, а потрібно було змінити тільки його характеристику - семестр. Видаляти курс і створювати його заново було б неправильно, оскільки це могло б порушити зв’язки з іншими таблицями.

Перед видаленням у таблиці grades було 9 записів.
Я видалила запис з id = 9:
DELETE FROM grades
WHERE id = 9;

Після виконання команди кількість записів стала дорівнювати 8.
Перевірка:
SELECT COUNT(*) FROM grades;

Результат:
8

Також я перевірила, чи залишився запис з id = 9. Запис не був знайдений, тому видалення виконано правильно.

Для перевірки зовнішнього ключа я увімкнула:
PRAGMA foreign_keys = ON;

Перевірка показала значення 1, тобто зовнішні ключі активні.
У таблиці grades для course_id встановлено:
ON DELETE CASCADE

Курс з id = 1 мав дві пов’язані оцінки.
Я виконала:
DELETE FROM courses
WHERE id = 1;

Після видалення курс з id = 1 зник із таблиці courses. Два пов’язані записи також автоматично видалилися з таблиці grades.
До цього в grades було 8 записів, після видалення стало 6.

Отже, фактичний результат відповідає роботі ON DELETE CASCADE: при видаленні батьківського запису автоматично видаляються пов’язані дочірні записи.


Контрольні питання
1. У чому різниця між SET col = col + 1 та SET col = конкретне число?
SET col = col + 1 збільшує поточне значення на 1.
SET col = 10 встановлює конкретне значення 10.

2. Чому NOT NULL, UNIQUE, CHECK перевіряються при UPDATE, а FK - тільки коли PRAGMA foreign_keys = ON?
Тому що NOT NULL, UNIQUE і CHECK є обмеженнями самої таблиці та перевіряються SQLite автоматично. Перевірка зовнішніх ключів у SQLite залежить від увімкнення PRAGMA foreign_keys.

3. Що було б при ON DELETE CASCADE замість RESTRICT?
При видаленні запису з батьківської таблиці пов’язані записи в дочірній таблиці також автоматично видалилися б.

4. Чому DELETE без WHERE небезпечніший за помилку типу або обмеження?
Тому що DELETE без WHERE може видалити всі записи таблиці. Помилка типу або обмеження зазвичай просто зупиняє операцію і не видаляє дані.

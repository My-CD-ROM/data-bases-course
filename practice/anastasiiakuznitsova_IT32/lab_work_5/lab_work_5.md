Для виконання роботи я використала таблицю courses, яка містить такі поля:
- id - первинний ключ;
- title - назва навчальної дисципліни;
- credits - кількість кредитів;
- semester - семестр.

Я додала до таблиці courses обмеження цілісності NOT NULL, UNIQUE, CHECK та DEFAULT.

Для стовпця credits я використала обмеження NOT NULL, оскільки кількість кредитів для кожної навчальної дисципліни повинна бути обов'язково вказана.

Я виконала спробу додати запис без значення credits:
INSERT INTO courses (title, semester) VALUES ('Тест NOT NULL', 1);

SQLite відхилив цей запис з помилкою:
Runtime error: NOT NULL constraint failed: courses.credits (19)
Таким чином, я перевірила, що обмеження NOT NULL не дозволяє залишити кількість кредитів порожньою.

Для стовпця title я використала обмеження UNIQUE, оскільки назви навчальних дисциплін не повинні повторюватися.
Я виконала спробу додати дисципліну з назвою, яка вже існує в таблиці:
INSERT INTO courses (title, credits, semester)
VALUES ('Бази даних', 5, 3);

SQLite відхилив запис через порушення обмеження UNIQUE. Таким чином, я перевірила, що однакова назва дисципліни не може бути додана повторно.

Для стовпця credits я також використала обмеження CHECK (credits > 0), оскільки кількість кредитів не може бути нульовою або від'ємною.

Я виконала спробу додати некоректне значення:
INSERT INTO courses (title, credits, semester)
VALUES ('Тест CHECK', -5, 1);

SQLite відхилив цей запис з помилкою:
Runtime error: CHECK constraint failed: credits > 0 (19)

Після цього я перевірила правильне значення:
INSERT INTO courses (title, credits, semester)
VALUES ('Тест CHECK 2', 3, 1);

Запис було успішно додано, оскільки значення 3 відповідає умові credits > 0.

Для стовпця semester я використала обмеження DEFAULT 1, оскільки якщо семестр не вказати, я можу автоматично встановити перший семестр.

Я виконала:
INSERT INTO courses (title, credits)
VALUES ('Тест DEFAULT', 4);

Після цього я перевірила отримане значення:
SELECT * FROM courses
WHERE title = 'Тест DEFAULT';

Отримала:
7|Тест DEFAULT|4|1

Отже, я переконалася, що SQLite автоматично встановив значення semester = 1.

Також я перевірила роботу обмеження CHECK через UPDATE, а не через INSERT:
UPDATE courses
SET credits = -10
WHERE title = 'Тест DEFAULT';

SQLite відхилив операцію з помилкою:
Runtime error: CHECK constraint failed: credits > 0 (19)

Таким чином, я підтвердила, що обмеження CHECK діє не тільки під час вставки нового запису, а й під час оновлення вже існуючого запису.


Контролюючі питання

1. Чому в SQLite неможливо просто виконати ALTER TABLE ... ADD CONSTRAINT CHECK (...), і що доводиться робити замість цього?

У SQLite не підтримується додавання такого обмеження через ALTER TABLE, тому я перестворила таблицю: перейменувала стару, створила нову з потрібним обмеженням, перенесла дані та видалила стару таблицю.

2. Що станеться, якщо перестворити таблицю, додавши NOT NULL до стовпця, у якому серед наявних рядків уже є NULL?

Перенесення даних завершиться помилкою, оскільки наявні значення NULL не відповідають обмеженню NOT NULL.

3. Чим перевірка CHECK, доданого через перестворення таблиці, відрізняється від перевірки CHECK, оголошеного одразу при CREATE TABLE?

Нічим не відрізняється - після перестворення таблиці CHECK працює так само, як і обмеження, додане під час створення таблиці.

4. Чому DEFAULT не можна перевірити тим самим способом, що й NOT NULL/UNIQUE/CHECK, і як його перевіряють замість цього?

DEFAULT не забороняє певні значення, а автоматично підставляє значення, якщо поле не вказано. Тому я перевірила його, додавши запис без значення semester, а потім виконала SELECT і переконалася, що автоматично встановилося значення 1.

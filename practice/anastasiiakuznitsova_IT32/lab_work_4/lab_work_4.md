Для виконання роботи використано три таблиці:
- students — таблиця студентів;
- courses — таблиця навчальних дисциплін;
- grades — таблиця оцінок студентів.

Створено таблицю courses з такими полями:
- id — первинний ключ;
- title — назва дисципліни;
- credits — кількість кредитів;
- semester — семестр.

До таблиці додано 5 навчальних дисциплін.

Створено таблицю grades, яка містить:
- id — первинний ключ;
- student_id — зовнішній ключ на students(id);
- course_id — зовнішній ключ на courses(id);
- grade — оцінка;
- grade_date — дата отримання оцінки.

Для student_id використано ON DELETE RESTRICT, оскільки видалення студента, для якого вже існують оцінки, може призвести до втрати історії його навчання.

Для course_id використано ON DELETE CASCADE, оскільки після видалення дисципліни пов'язані з нею оцінки втрачають актуальність.

До таблиці courses додано 5 записів.
До таблиці grades додано 9 записів з реальними значеннями зовнішніх ключів.

Було виконано JOIN таблиць students, courses та grades. У результаті отримано інформацію про студентів, дисципліни, оцінки та дати їх отримання.

Для увімкнення перевірки зовнішніх ключів використано:
PRAGMA foreign_keys = ON;

Після виконання:
PRAGMA foreign_keys;
отримано значення 1, що підтверджує увімкнення перевірки зовнішніх ключів.

Також було виконано спробу додати запис із неіснуючим student_id:
INSERT INTO grades (student_id, course_id, grade, grade_date)
VALUES (9999, 1, 100, '2026-09-23');

SQLite відхилив цей запис з помилкою:
Error: FOREIGN KEY constraint failed
Це підтверджує правильність роботи зовнішнього ключа.

Структура бази даних відповідає ER-моделі. Таблиця students пов'язана з таблицею grades, а таблиця courses також пов'язана з таблицею grades.
Таким чином, таблиця grades забезпечує зв'язок між студентами та навчальними дисциплінами.

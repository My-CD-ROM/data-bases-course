# Практична робота 12. Сортування і фільтрація даних

## Мета роботи

Навчитися сортувати дані за допомогою `ORDER BY`, обмежувати кількість результатів через `LIMIT`, отримувати унікальні значення за допомогою `DISTINCT` та використовувати оператори `IN` і `LIKE` для фільтрації даних. Дослідити особливості пошуку українського тексту з різним регістром літер.

## Завдання 1. ORDER BY за однією колонкою

Для сортування продажів абонементів за датою покупки використано запит:

```sql
SELECT
    id,
    membership_id,
    client_id,
    purchase_date,
    expiration_date
FROM membership_sales
ORDER BY purchase_date DESC;
```

Оператор `ORDER BY` сортує записи за вказаною колонкою. Ключове слово `DESC` задає порядок спадання, тому найновіші дати покупки розташовуються на початку результату.

Першим у результаті є запис з ідентифікатором **[вказати id]** і датою покупки **[вказати дату]**. Він розташований першим, оскільки має найновішу дату покупки серед записів таблиці.

## Завдання 2. ORDER BY за кількома колонками

Для сортування за двома колонками використано запит:

```sql
SELECT
    id,
    membership_id,
    client_id,
    purchase_date,
    expiration_date
FROM membership_sales
ORDER BY expiration_date ASC, purchase_date DESC;
```

Спочатку записи сортуються за колонкою `expiration_date` у порядку зростання (`ASC`), тобто від найранішої дати завершення абонемента до найпізнішої.

Якщо декілька записів мають однакову дату завершення, додаткове сортування виконується за колонкою `purchase_date` у порядку спадання (`DESC`). Таким чином, серед записів з однаковою датою завершення новіші покупки розташовуються вище.

Друга колонка сортування уточнює порядок записів, для яких значення першої колонки збігаються.

## Завдання 3. Топ-3 через ORDER BY і LIMIT

Для отримання трьох найновіших продажів використано запит:

```sql
SELECT
    id,
    membership_id,
    client_id,
    purchase_date,
    expiration_date
FROM membership_sales
ORDER BY purchase_date DESC
LIMIT 3;
```

Оператор `ORDER BY purchase_date DESC` спочатку впорядковує всі записи за датою покупки від найновішої до найстарішої.

Оператор `LIMIT 3` обмежує результат трьома першими записами після сортування.

Порядок команд має значення: спочатку необхідно відсортувати записи, а потім обмежити їх кількість. Якщо прибрати `ORDER BY`, запит із `LIMIT 3` поверне три записи без гарантії, що це будуть найновіші продажі.

Отже, поєднання `ORDER BY` і `LIMIT` дає змогу отримати три найновіші продажі абонементів.

## Завдання 4. DISTINCT і IN

### Частина А. Отримання унікальних значень за допомогою DISTINCT

Для отримання списку унікальних типів абонементів використано запит:

```sql
SELECT DISTINCT type
FROM memberships;
```

Оператор `DISTINCT` усуває повторення значень у результаті запиту. Якщо певний тип абонемента повторюється в таблиці, він відображається лише один раз.

Для підрахунку кількості унікальних типів додатково використано запит:

```sql
SELECT COUNT(DISTINCT type) AS unique_types
FROM memberships;
```

Результат запиту показує **[вказати кількість]** унікальних типів абонементів.

### Частина Б. Фільтрація за допомогою IN

Для відбору продажів клієнтів з ідентифікаторами 1, 2 або 3 використано запит:

```sql
SELECT
    id,
    client_id,
    membership_id,
    purchase_date,
    expiration_date
FROM membership_sales
WHERE client_id IN (1, 2, 3);
```

Оператор `IN` перевіряє, чи належить значення колонки `client_id` до заданого списку. У результат потрапляють лише записи, для яких ідентифікатор клієнта дорівнює 1, 2 або 3.

Цю умову можна записати через кілька операторів `OR`, але використання `IN` робить запит коротшим і зрозумілішим.

`IN` доречно використовувати для конкретного набору значень, тоді як `BETWEEN` призначений для перевірки належності до діапазону, включно з його межами.

## Завдання 5. LIKE і регістр кирилиці

### Частина А. Пошук за шаблоном

Для пошуку клієнтів, прізвища яких починаються з великої української літери «К», використано запит:

```sql
SELECT
    id,
    last_name,
    first_name
FROM clients
WHERE last_name LIKE 'К%';
```

Оператор `LIKE` дає змогу порівнювати текст зі спеціальним шаблоном. Символ `%` означає будь-яку послідовність символів, зокрема порожню.

Тому шаблон `'К%'` відповідає прізвищам, які починаються з літери «К».

### Частина Б. Перевірка регістру

Для підрахунку збігів із великою літерою виконано запит:

```sql
SELECT COUNT(*) AS matches_upper
FROM clients
WHERE last_name LIKE 'К%';
```

Для підрахунку збігів із малою літерою виконано запит:

```sql
SELECT COUNT(*) AS matches_lower
FROM clients
WHERE last_name LIKE 'к%';
```

Результати експерименту:

- Кількість збігів із великою літерою «К»: **[вказати результат matches_upper]**.
- Кількість збігів із малою літерою «к»: **[вказати результат matches_lower]**.

У SQLite оператор `LIKE` за стандартної конфігурації не розрізняє регістр для латинських символів ASCII, але зазвичай розрізняє регістр українських літер. Тому пошук із великою та малою українськими літерами може повертати різну кількість збігів.

Фактичний результат залежить від налаштувань SQLite та наявних даних. Саме тому обидва запити потрібно виконати й порівняти їхні результати.

## Контрольні питання

### 1. Чому ORDER BY потрібно використовувати перед LIMIT?

Спочатку `ORDER BY` визначає порядок записів, а потім `LIMIT` обмежує кількість рядків. Якщо прибрати `ORDER BY`, запит із `LIMIT 3` не гарантуватиме повернення трьох найновіших продажів.

### 2. Коли використовують IN, а коли BETWEEN?

`IN` використовують для перевірки відповідності одному зі значень заданого списку. `BETWEEN` застосовують для перевірки належності до певного діапазону, включно з нижньою та верхньою межами.

### 3. Чому важливо враховувати регістр українських літер?

Під час пошуку українських текстових даних велика та мала літери можуть оброблятися по-різному. Через це запити `LIKE 'К%'` і `LIKE 'к%'` можуть повертати різні результати. Це важливо враховувати, щоб правильно шукати прізвища, назви та інші текстові значення українською мовою.

## Висновок

Під час виконання практичної роботи було розглянуто сортування даних за однією та кількома колонками за допомогою `ORDER BY`, обмеження результатів через `LIMIT` і видалення повторень за допомогою `DISTINCT`. Також було застосовано оператор `IN` для відбору записів за списком значень і `LIKE` для пошуку тексту за шаблоном.

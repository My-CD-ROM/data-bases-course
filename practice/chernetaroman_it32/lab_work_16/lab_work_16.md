Завдання 2. Проміжна таблиця та імпорт CSV

Для імпорту було створено проміжну таблицю memberships_staging, яка містить колонки CSV-файлу без первинного ключа id.

CREATE TABLE memberships_staging (
    type TEXT,
    duration_days INTEGER,

CSV-файл було імпортовано за допомогою SQLite CLI:

.import --skip 1 v7_new_rows.csv memberships_staging

Прапорець --skip 1 дозволяє пропустити рядок заголовків CSV.

Після імпорту було перевірено вміст проміжної таблиці:

FROM memberships_staging;

У проміжній таблиці було отримано 8 нових рядків.

Завдання 3. Перенесення у цільову таблицю

Дані було перенесено з проміжної таблиці до memberships:

INSERT INTO memberships (type, duration_days, price)
SELECT type, duration_days, price
FROM memberships_staging;

Колонка id не зазначалася, оскільки SQLite призначає первинні ключі автоматично.

Після перенесення проміжну таблицю було видалено:

DROP TABLE memberships_staging;

Після імпорту виконано повторний підрахунок:

FROM memberships;

Для пошуку нових абонементів було використано запит:

SELECT id, type, duration_days, price

Нові записи отримали ідентифікатори, які продовжують нумерацію попередніх записів. Це підтверджує, що SQLite самостійно призначила нові значення id.

Завдання 5. Свідома помилка прямого імпорту

На окремій тестовій копії бази було виконано спробу імпорту CSV безпосередньо в таблицю memberships:

.mode csv
.import --skip 1 v7_new_rows.csv memberships

Під час імпорту виникла помилка:

[вставити фактичне повідомлення SQLite]

Причина помилки полягає в тому, що CSV-файл містить три колонки, а таблиця memberships — чотири, включаючи id.

Під час прямого імпорту значення CSV зміщуються відносно колонок таблиці. Назва абонемента намагається потрапити в колонку id, яка повинна містити ціле число.

Тому правильним способом імпорту є використання проміжної таблиці без id і подальше перенесення даних через INSERT ... SELECT.

Контрольні питання

1. Чому CSV-файл не містить колонку id?

CSV-файл навмисно не містить id, оскільки первинний ключ повинен бути унікальним.

Якщо вручну додати довільні значення id, вони можуть збігтися з уже наявними ідентифікаторами. Це призведе до помилки унікальності первинного ключа.

Тому SQLite повинна самостійно призначати нові значення id.

2. Для чого потрібна DROP TABLE?

Команда DROP TABLE видаляє проміжну таблицю після перенесення даних.

Якщо залишити її, наступний імпорт може додати нові записи до старих. При повторному INSERT ... SELECT старі записи можуть перенестися повторно.

Видалення staging-таблиці допомагає уникнути дублювання даних і підтримує чистоту структури бази.

3. Чому COUNT(*) до й після імпорту кращий за візуальну перевірку?

COUNT(*) дозволяє точно визначити кількість записів у таблиці.

Порівняння кількості рядків до та після імпорту підтверджує, що було додано саме очікувану кількість записів.

Візуальна перевірка може не показати пропущені або дубльовані рядки, особливо якщо таблиця містить багато даних.

Висновок

Під час практичної роботи було розглянуто формат CSV та імпорт даних у SQLite.

Було створено проміжну таблицю, імпортовано в неї CSV-файл і перенесено вісім нових записів у таблицю memberships.

За допомогою COUNT(*) підтверджено кількість доданих рядків. Також було перевірено автоматичне призначення первинних ключів SQLite та досліджено причину помилки прямого імпорту CSV у таблицю з колонкою id.

У результаті роботи було засвоєно принцип імпорту даних через проміжну таблицю.

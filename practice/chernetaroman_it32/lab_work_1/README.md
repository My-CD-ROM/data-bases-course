# Практична робота №1

## Варіант 7 — Спортзал (фітнес-клуб)

### Таблиця `memberships`

Таблиця `memberships` використовується для зберігання інформації про абонементи у фітнес-клубі.

| Стовпець        | Тип     | Опис                                                            |
| --------------- | ------- | --------------------------------------------------------------- |
| `id`            | INTEGER | Номер абонемента. Є первинним ключем таблиці.                   |
| `type`          | TEXT    | Назва абонемента, наприклад «Разовий», «Місячний» або «Річний». |
| `duration_days` | INTEGER | Кількість днів, протягом яких діє абонемент.                    |
| `price`         | REAL    | Вартість абонемента.                                            |

### Пояснення типів даних

**id — INTEGER**

Для цього поля використовується `INTEGER`, тому що номер абонемента є цілим числом. Поле також визначене як `PRIMARY KEY`, тому кожен абонемент має свій унікальний номер.

**type — TEXT**

Для поля `type` використовується `TEXT`, оскільки тут записується назва абонемента. Наприклад: «Разовий», «Тижневий», «Місячний», «Квартальний», «Піврічний» або «Річний».

**duration_days — INTEGER**

У цьому полі зберігається кількість днів дії абонемента. Наприклад, для місячного абонемента це 30 днів, а для річного — 365. Оскільки це цілі числа, підходить тип `INTEGER`.

**price — REAL**

Для ціни вибрано `REAL`, тому що вартість може мати копійки. Наприклад, ціна може бути `1200.50`. Тому цей тип зручніший для зберігання грошових значень, ніж `TEXT`.

### Type affinity

У SQLite кожне поле має свій тип, який визначає, з якими даними в ньому передбачається працювати. Це пов'язано з поняттям `type affinity`.

У моїй таблиці для номера та кількості днів використовується `INTEGER`, для назв абонементів — `TEXT`, а для ціни — `REAL`. Таке розподілення відповідає даним, які зберігаються в таблиці.

Наприклад, `duration_days` не варто зберігати як `TEXT`, оскільки це число, з яким можна виконувати обчислення та порівняння. Так само для `price` краще використовувати числовий тип `REAL`, щоб працювати з ціною як із числом.

Контрольні питання

1. Чому в SQLite неможливо просто виконати ALTER TABLE ... ADD CONSTRAINT CHECK (...), і що доводиться робити замість цього?

SQLite має обмежену підтримку ALTER TABLE і не дозволяє додавати нові CHECK, NOT NULL та UNIQUE через ADD CONSTRAINT. Тому потрібно перейменувати стару таблицю, створити нову з потрібним обмеженням, перенести дані та видалити стару таблицю.

2. Що станеться, якщо перестворити таблицю, додавши NOT NULL до стовпця, у якому серед наявних рядків уже є NULL?

Під час перенесення даних виникне помилка, тому що NULL не можна записати у стовпець, для якого встановлено NOT NULL.

3. Чим перевірка CHECK, доданого через перестворення таблиці, відрізняється від перевірки CHECK, оголошеного одразу при CREATE TABLE?

Нічим — після перестворення таблиці CHECK працює так само, як і обмеження, задане під час початкового створення таблиці.

4. Чому DEFAULT не можна перевірити тим самим способом, що й NOT NULL, UNIQUE, CHECK, і як його перевіряють?

DEFAULT не забороняє неправильні значення, а автоматично встановлює значення, якщо його не вказати. Тому його перевіряють, вставивши запис без цього стовпця, а потім виконуючи SELECT, щоб побачити автоматично встановлене значення.

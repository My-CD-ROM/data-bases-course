# Практика 8. Застосування агрегатних функцій

**Варіант:** 3  
**Предметна область:** Кінотеатр  
**Таблиці:** `movies`, `viewers`, `tickets`

У роботі використано базу даних із Практики 7. Фактовою (журнальною) таблицею є `tickets`, у якій міститься 5 записів. Структуру таблиць не змінювали.

## Завдання 1. COUNT(*) проти COUNT(колонка)

Для підрахунку всіх квитків і квитків із заповненою датою покупки виконано запит:

```sql
SELECT
    COUNT(*) AS total_tickets,
    COUNT(purchase_date) AS tickets_with_purchase_date
FROM tickets;
```

**Результат:** `COUNT(*) = 5`, `COUNT(purchase_date) = 5`.

Результати збігаються, оскільки всі п'ять квитків мають заповнене значення `purchase_date`. Перевірка структури показала, що цей стовпець, як і всі інші стовпці таблиці `tickets`, має обмеження `NOT NULL`. Тому встановити `NULL` командою `UPDATE` неможливо без зміни структури таблиці, а умова практичної роботи забороняє змінювати структуру.

Для демонстрації того, що `COUNT(вираз)` не враховує `NULL`, виконано додатковий запит:

```sql
SELECT
    COUNT(*) AS total_tickets,
    COUNT(CASE WHEN id <> 5 THEN purchase_date END) AS count_non_null_expression
FROM tickets;
```

**Результат:** `COUNT(*) = 5`, `COUNT(вираз) = 4`. Для рядка з `id = 5` вираз `CASE` повертає `NULL`, тому `COUNT` його не враховує. Реальні дані таблиці при цьому не змінюються.

## Завдання 2. SUM і AVG на числовій колонці

Для числового стовпця `price` таблиці `tickets` обчислено суму та середнє значення:

```sql
SELECT
    SUM(price) AS total_revenue,
    AVG(price) AS average_ticket_price
FROM tickets;
```

**Результат:**
- `SUM(price) = 890.0`;
- `AVG(price) = 178.0`.

Загальна вартість п'яти квитків у наявній базі становить 890 грн. Середня ціна одного квитка дорівнює 178 грн.

## Завдання 3. MIN/MAX на текстовій колонці

Для текстового стовпця `title` таблиці `movies` визначено назви, які першими та останніми розташовані за алфавітом:

```sql
SELECT
    MIN(title) AS first_movie_alphabetically,
    MAX(title) AS last_movie_alphabetically
FROM movies;
```

**Результат:**
- `MIN(title) = Harry Potter and the Philosopher's Stone`;
- `MAX(title) = Titanic`.

SQLite порівнює текстові значення відповідно до правил сортування. За замовчуванням використовується правило `BINARY`, яке порівнює символи за їхніми кодами. Тому найменшим і найбільшим є текстові значення, що стоять на початку та в кінці такого порядку порівняння.

## Завдання 4. Кілька агрегатних функцій в одному запиті

Створено загальний звіт за всіма квитками:

```sql
SELECT
    COUNT(*) AS tickets_count,
    SUM(price) AS total_revenue,
    AVG(price) AS average_price,
    MIN(price) AS minimum_price,
    MAX(price) AS maximum_price
FROM tickets;
```

**Результат:**

| Показник | Значення |
|---|---:|
| Кількість квитків | 5 |
| Загальна вартість | 890 грн |
| Середня ціна | 178 грн |
| Мінімальна ціна | 150 грн |
| Максимальна ціна | 200 грн |

Запит формує узагальнений звіт: показує кількість квитків, загальну та середню вартість, а також найнижчу й найвищу ціну.

## Завдання 5. Агрегат + WHERE

Таблицю квитків пов'язано з таблицею фільмів через `INNER JOIN`. Умова `WHERE` залишає лише квитки на фільми жанру `Sci-Fi`:

```sql
SELECT
    COUNT(t.id) AS scifi_tickets,
    SUM(t.price) AS scifi_revenue,
    AVG(t.price) AS scifi_average_price
FROM tickets AS t
INNER JOIN movies AS m ON t.movie_id = m.id
WHERE m.genre = 'Sci-Fi';
```

**Результат:**
- `scifi_tickets = 3`;
- `scifi_revenue = 570.0` грн;
- `scifi_average_price = 190.0` грн.

Умова `WHERE m.genre = 'Sci-Fi'` прибирає з розрахунку квитки на фільми інших жанрів. У результаті залишаються три квитки: два на Interstellar і один на Inception. Фільм Matrix також має жанр Sci-Fi, але квитків на нього в таблиці `tickets` немає.

## Контрольні питання

**1. Чому `COUNT(*)` і `COUNT(колонка)` можуть повернути різні числа на тій самій таблиці, а `COUNT(*)` і `COUNT(id)` — практично завжди однакові, якщо `id` є первинним ключем?**

`COUNT(*)` рахує всі рядки таблиці незалежно від значень у стовпцях. `COUNT(колонка)` рахує лише ті рядки, у яких значення зазначеної колонки не дорівнює `NULL`. Первинний ключ `id` не може бути `NULL`, тому `COUNT(id)` дорівнює `COUNT(*)`.

**2. Якщо в таблиці є 5 рядків, а в одному значення числової колонки дорівнює `NULL`, чому дорівнює знаменник при обчисленні `AVG`?**

Знаменник дорівнює 4, оскільки `AVG` ігнорує рядки, у яких значення обчислюваної колонки дорівнює `NULL`. Середнє значення обчислюється за чотирма наявними числовими значеннями.

**3. Що поверне `SUM(колонка)`, якщо всі рядки мають `NULL` у цій колонці?**

`SUM(колонка)` поверне `NULL`, а не 0 і не помилку, оскільки немає жодного числового значення для підсумовування. Це перевірено запитом:

```sql
SELECT SUM(NULLIF(price, price)) AS sum_all_null
FROM tickets;
```

`NULLIF(price, price)` повертає `NULL`, оскільки обидва аргументи однакові. Отже, для всіх рядків функція `SUM` отримує `NULL`, і результатом є `NULL`.

## Висновок

Під час практичної роботи застосовано агрегатні функції `COUNT`, `SUM`, `AVG`, `MIN` та `MAX` до таблиць кінотеатру. Визначено кількість квитків, загальну й середню вартість, мінімальну та максимальну ціну, а також першу й останню назви фільмів за текстовим порядком. За допомогою `JOIN` і `WHERE` сформовано окремий звіт для квитків на фільми жанру Sci-Fi. Перевірено, що `COUNT` ігнорує `NULL`, `AVG` обчислює середнє лише за наявними числовими значеннями, а `SUM` повертає `NULL`, якщо всі значення є `NULL`. Структуру вихідної бази даних не змінювали.

    Практика 2. Формування запитів вибірки у SQLite¶

    Схема бази не змінюється в цій практиці. Працюємо з тією самою базою й тією самою таблицею-вимір 1, яку створили та наповнили в Практиці 1 — тепер до неї застосовуються запити вибірки замість повторного CREATE TABLE.

    Нагадування: ваш варіант¶

    Відкрийте файл .db, створений у Практиці 1 (наприклад, у DB Browser for SQLite), і переконайтесь, що таблиця й дані на місці. Якщо точну назву таблиці чи стовпців не пам'ятаєте — подивіться в Практику 1 або на вкладку структури таблиці в DB Browser for SQLite.

    Для орієнтиру у Завданні 2 — стовпець, за яким природно фільтрувати рядки, залежно від варіанта:

    № Таблиця-вимір 1 Стовпець для умови у Завданні 2 (приклад)
    1 books publication_year або copies_count
    2 products price або size
    3 movies duration_min або year
    4 medicines price
    5 cars year або price
    6 rooms price_per_night або capacity
    7 memberships duration_days або price
    8 dishes price
    9 students admission_year
    10 drivers experience_years

    Приклад: наскрізна демонстрація¶

    Розберіть приклад на іншому, непов'язаному домені — невеликій колекції вінілових платівок — перш ніж переходити до завдань на власному варіанті. Техніка та сама, дані інші.

    CREATE TABLE albums (
    id INTEGER PRIMARY KEY,
    title TEXT,
    artist TEXT,
    year INTEGER,
    genre TEXT,
    price REAL,
    rating INTEGER
);

INSERT INTO albums (id, title, artist, year, genre, price, rating) VALUES
(1, 'Kind of Blue', 'Miles Davis', 1959, 'джаз', 450, 5),
(2, 'Rumours', 'Fleetwood Mac', 1977, 'рок', 380, 4),
(3, 'Thriller', 'Michael Jackson', 1982, 'поп', 420, 5),
(4, 'Random Access Memories', 'Daft Punk', 2013, 'електроніка', 500, NULL),
(5, 'Blue Train', 'John Coltrane', 1957, 'джаз', 460, NULL);

    Явний перелік стовпців замість SELECT *:

    SELECT title, artist, year FROM albums;

    LIMIT — перегляд лише кількох перших рядків (порядок без ORDER BY не гарантований, тут це і є перші рядки в порядку вставки):

    SELECT title, artist FROM albums LIMIT 3;
SELECT title FROM albums LIMIT 2 OFFSET 2;   -- "сторінка 2" по 2 рядки

    WHERE з умовою за ціною і складена умова через AND:

    SELECT title, price FROM albums WHERE price < 450;

SELECT title, artist, year
FROM albums
WHERE genre = 'джаз' AND year < 1960;

    IS NULL / IS NOT NULL — і чому = NULL тут не працює:

    -- невірно: жодного рядка, хоча дві платівки без рейтингу є в таблиці
SELECT title FROM albums WHERE rating = NULL;

-- правильно
SELECT title FROM albums WHERE rating IS NULL;
SELECT title, rating FROM albums WHERE rating IS NOT NULL;

    rating = NULL завжди дає NULL (не TRUE, не FALSE) для будь-якого рядка — тому що порівняння з невідомим значенням саме таке, невідоме, і WHERE жодного разу не пропускає рядок далі. IS NULL — окремий оператор, який прямо запитує «чи це комірка без значення?», а не порівнює значення між собою.

    Завдання¶

    Завдання 1. SELECT з явним переліком стовпців¶

    Виведіть кілька записів своєї таблиці-вимір 1, вказавши явно 3-4 стовпці (не *) у порядку, який вам самим здається зручним для перегляду.

    Завдання 2. WHERE за умовою свого варіанта¶

    Складіть запит WHERE з умовою, характерною для типу даних вашого варіанта (див. таблицю-нагадування вище) — наприклад, рік більший за певне число, ціна в певних межах, стаж більший за N років тощо. Виведіть лише ті стовпці, які потрібні для перевірки умови.

    Завдання 3. LIMIT¶

    Виведіть перші N записів своєї таблиці (N — на ваш вибір, наприклад 3 або 5) одним запитом із LIMIT.

    Завдання 4. IS NULL / IS NOT NULL¶

    Оберіть у своїй таблиці один стовпець, значення якого реалістично може бути невідомим (наприклад, genre, якщо ще не визначений, чи age_rating, якщо фільм ще без рейтингу — залежно від вашого варіанта). Вставте один додатковий рядок, де саме цей стовпець — NULL (через INSERT ... VALUES (..., NULL, ...), а не порожній рядок і не нуль). Потім напишіть два запити: один із IS NULL, інший — з IS NOT NULL. Письмово, у 2-3 реченнях, поясніть, чому такий запит не можна коректно написати через = NULL.

    Завдання 5. Складена умова¶

    Складіть один запит із двома умовами, об'єднаними через AND або OR (на ваш вибір, залежно від того, яка умова природніша для вашого варіанта). Якщо у виразі є одночасно AND і OR — розставте дужки явно.

    Що здати й оцінюється¶

    Здайте lab_work_2.sql — усі п'ять запитів Завдань 1-5, виконаних на власній таблиці (варіант із Практики 1); lab_work_2.db — поточний файл бази даних (структура й дані цього разу не змінюються, це той самий файл, що й після Практики 1); і lab_work_2.md — письмові відповіді на контрольні питання:

    • Чому запит WHERE price = NULL завжди повертає порожній результат, навіть якщо в таблиці є рядки з NULL у стовпці price? Що саме потрібно написати замість цього?
    • Чим WHERE принципово відрізняється від HAVING? (Детально HAVING розглядається в Лекції 9 — тут достатньо загального уявлення: WHERE фільтрує окремі рядки таблиці ще до будь-якого групування, тоді як HAVING фільтрує вже готові групи.)
    • У якому випадку варто уникати SELECT *, і чому саме?

    Оцінюється правильність запитів саме для вашого варіанта (а не збіг із прикладом-колекцією платівок вище) та повнота письмових пояснень.

    Підсумок заняття¶

    • Побудовано запити SELECT з явним переліком стовпців для власної таблиці-вимір 1.
    • Складено умови WHERE за типом даних свого варіанта, зокрема складену умову через AND/OR.
    • Застосовано LIMIT для обмеження кількості рядків результату.
    • Продемонстровано різницю між = NULL (завжди NULL, ніколи не спрацьовує як фільтр) та IS NULL / IS NOT NULL (коректний спосіб перевірити відсутність значення).

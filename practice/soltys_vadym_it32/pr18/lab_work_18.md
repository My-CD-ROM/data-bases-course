# Практика 18. Згенеровані стовпці (варіант 2, інтернет-магазин одягу)

## Завдання 1
До таблиці `products` додано VIRTUAL-стовпець `price_with_vat REAL GENERATED ALWAYS AS (round(price * 1.2, 2)) VIRTUAL`. Він показує ціну товару з ПДВ 20 % (наприклад, футболка 299,0 → 358,8, сукня 650,0 → 780,0). Бізнес-сенс: покупцеві й менеджеру потрібна кінцева ціна з податком, і її не треба вводити вручну чи окремо зберігати, її завжди обчислює база за актуальною базовою ціною. Формула бере лише колонку `price` того самого рядка.

## Завдання 2
Додано стовпець `low_stock INTEGER GENERATED ALWAYS AS (stock_quantity < 10) VIRTUAL`: прапорець «мало на складі» (1) чи «достатньо» (0). У `products` немає колонки статусу, тому прапорець побудовано на `stock_quantity`. Перевірка запитом показала відповідність реальному стану: значення 1 отримали товари із залишком менше 10 (id 3 з 6, id 13 з 6, id 19 з 9, id 22 з 8, id 24 з 5), а, наприклад, товар id 11 із залишком рівно 10 має 0, бо умова `< 10` для нього хибна. NULL у прапорці тут не виникає, бо `stock_quantity` має обмеження `NOT NULL`.

## Завдання 3
Спроба `UPDATE products SET price_with_vat = 1 WHERE id = 1;` завершилась помилкою SQLite:

`cannot UPDATE generated column "price_with_vat"`

Для другого стовпця аналогічно: `cannot UPDATE generated column "low_stock"`.

## Завдання 4
Для товару 6 («Шапка вовняна») до `UPDATE`: `price = 250.0`, `price_with_vat = 300.0`. Після `UPDATE products SET price = 275 WHERE id = 6;` (змінено лише базову колонку): `price = 275.0`, `price_with_vat = 330.0`. Згенерований стовпець змінився автоматично й синхронно з базовою колонкою, без жодної додаткової команди, бо SQLite обчислює його за формулою щоразу, коли значення потрібне.

## Завдання 5
```sql
SELECT id, name, price, price_with_vat FROM products WHERE price_with_vat > 1500 ORDER BY price_with_vat DESC;
```
Запит повернув 8 товарів (від «Чоботи шкіряні» 4080 до «Кардиган в'язаний» 1536). Такий запис зручніший, ніж `WHERE price * 1.2 > 1500`: формула із ставкою ПДВ прописана в одному місці (у визначенні стовпця), а не повторюється в кожному запиті. Якщо ставка зміниться, її достатньо виправити один раз, і всі запити лишаться узгодженими. Умова також читається як бізнес-поняття («ціна з ПДВ понад 1500»), а не як арифметика.

## Контрольні питання (коротко)
1. STORED-стовпець не можна додати командою `ALTER TABLE ... ADD COLUMN` до наявної таблиці: SQLite відповідає `cannot add a STORED column`. Тому в цій практиці, де таблиці вже створені, можливий лише VIRTUAL.
2. `DROP COLUMN` базової колонки не вийде: SQLite повертає помилку `error in table products after drop column: no such column: price`, бо згенерований стовпець від неї залежить.
3. Пряме записування було б способом зіпсувати узгодженість: значення могло б розійтися з формулою. Заборона гарантує, що похідне значення завжди відповідає базовим колонкам, тому це перевага.

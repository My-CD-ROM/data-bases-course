# Практика 4. Додавання записів, встановлення ключів і зв'язків

**Варіант 2 — Інтернет-магазин одягу**

## Завдання 1. Увімкнення перевірки і таблиця-вимір 2

`PRAGMA foreign_keys = ON;` виконано як перший рядок сеансу (база — файл з Практики 1, де вже існує таблиця-вимір 1 `products`).
Створено таблицю-вимір 2 `clients` (клієнти): `id`, `full_name`, `email`, `phone`, `registration_date`.

## Завдання 2. Фактова таблиця з двома FOREIGN KEY

Створено фактову таблицю `orders` (замовлення) з `id INTEGER PRIMARY KEY` і двома зовнішніми ключами:

- `product_id → products(id)` — **ON DELETE RESTRICT**.
  Обґрунтування: `products` — таблиця-вимір 1, яка веде облік залишків (`stock_quantity`). Видалити товар, на який уже є оформлені замовлення, не можна напряму — це зламало б звітність про продажі й залишки; товар спершу треба зняти з продажу іншим способом (наприклад, окремим статусом), а не видаляти рядок.

- `client_id → clients(id)` — **ON DELETE SET NULL**.
  Обґрунтування: обліковий запис клієнта може бути видалений (наприклад, за запитом на видалення персональних даних), але сам факт продажу товару та фінансовий запис про нього мають зберегтися для бухгалтерії. Тому при видаленні клієнта посилання в `orders.client_id` просто обнуляється, а не блокує видалення і не видаляє замовлення каскадно. Колонка `client_id` навмисно nullable (без `NOT NULL`).

Дії обрано різні свідомо: втрата товару з каталогу і втрата облікового запису клієнта мають різну вагу для бізнес-логіки магазину — перше критично для точності складу й продажів (RESTRICT), друге — питання приватності, що не повинно ламати історію продажів (SET NULL).

Рішення збережено для перевірки в Практиці 5.

## Завдання 3. Заповнення пов'язаними даними

- У `clients` вставлено 5 рядків.
- У `orders` вставлено 10 рядків, кожен коректно пов'язаний із реальними `product_id` (1–6, наявна таблиця `products` з Практики 1) і `client_id` (1–5, щойно заповнена `clients`). Вигаданих значень зовнішніх ключів немає.

## Завдання 4. Навмисна помилка зовнішнього ключа

Спроба вставки:

```sql
INSERT INTO orders (product_id, client_id, order_date, quantity)
VALUES (9999, 1, '2026-09-11', 1);
```

Точний текст помилки, отриманий від SQLite:

```
FOREIGN KEY constraint failed
```

Рядок не потрапив у таблицю — підтвердження, що `PRAGMA foreign_keys = ON;` реально діє на з'єднанні.

## Завдання 5. Звірка з ER-діаграмою Практики 3

Структуру (`products` — `clients` — `orders`, напрямки зв'язків через `product_id` і `client_id`) реалізовано відповідно до запланованої в Практиці 3 ER-схеми. Змін у назвах таблиць, колонок чи напрямках зв'язків під час реалізації не знадобилося.

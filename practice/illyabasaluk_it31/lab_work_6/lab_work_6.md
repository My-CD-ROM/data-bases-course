# Практична робота 6. UPDATE та DELETE у SQLite

**Варіант:** 1 — Бібліотека

## Мета роботи

Навчитися виконувати операції `UPDATE` та `DELETE` у SQLite, перевіряти роботу обмежень таблиць та зовнішніх ключів, а також дослідити поведінку `ON DELETE`.

## Завдання 1

У таблиці `loans` було оновлено запис з `id = 5`.

Для нього значення `return_date` було змінено з `NULL` на `2026-09-23`.

```sql
UPDATE loans
SET return_date = '2026-09-23'
WHERE id = 5;
```

## Завдання 2

У таблиці `books` для книги **«Чорна рада»** з `id = 6` кількість примірників було змінено з **5 до 6**.

```sql
UPDATE books
SET copies_count = copies_count + 1
WHERE id = 6;
```

`UPDATE` використовується тому, що кількість примірників книги може змінюватися в процесі роботи бібліотеки, але сама книга залишається тим самим об'єктом. Тому немає потреби видаляти старий запис і створювати новий.

## Завдання 3

Перед видаленням у таблиці `loans` було **10 записів**.

Було виконано:

```sql
DELETE FROM loans
WHERE id = 10;
```

Після видалення залишилося **9 записів**.

Отже, було видалено рівно один запис.

## Завдання 4

Для зовнішнього ключа таблиці `loans` використовується `ON DELETE RESTRICT`.

Було виконано спробу видалити книгу `Кобзар` з `id = 1`, яка має пов'язані записи в таблиці `loans`.

```sql
DELETE FROM books
WHERE id = 1;
```

SQLite повернув помилку:

```text
FOREIGN KEY constraint failed
```

Після цього перевірка показала, що книга `Кобзар` з `id = 1` залишилася в таблиці `books`.

Отже, поведінка `ON DELETE RESTRICT` відповідає очікуваній: видалення батьківського запису забороняється, якщо на нього існують посилання з таблиці `loans`.

## Контрольні питання

### 1. Чим відрізняється `UPDATE ... SET col = col + 1` від встановлення конкретного числа?

`SET col = col + 1` збільшує поточне значення на одиницю. Наприклад, якщо кількість примірників дорівнює 5, після операції вона стане 6.

Якщо записати `SET col = 10`, значення буде безпосередньо встановлено в 10 незалежно від попереднього значення.

### 2. Чому `NOT NULL`, `UNIQUE` та `CHECK` перевіряються під час `UPDATE`, а зовнішній ключ залежить від `PRAGMA foreign_keys`?

Обмеження `NOT NULL`, `UNIQUE` та `CHECK` є частиною структури таблиці, тому SQLite перевіряє їх під час зміни даних.

Зовнішні ключі в SQLite контролюються режимом `PRAGMA foreign_keys`. Якщо контроль зовнішніх ключів вимкнений, відповідні зв'язки не перевіряються під час виконання операцій.

### 3. Що сталося б при `ON DELETE CASCADE` замість `RESTRICT`?

При `ON DELETE CASCADE` видалення книги з таблиці `books` автоматично призвело б до видалення пов'язаних записів із таблиці `loans`.

При `RESTRICT` видалення книги забороняється, якщо існують пов'язані записи.

### 4. Чому `DELETE` без `WHERE` небезпечніший?

`DELETE` без `WHERE` видаляє всі записи таблиці. Помилка або випадковий запуск такої команди може призвести до втрати всіх даних.

Якщо використовується `WHERE` з конкретним `id`, можна обмежити операцію одним потрібним записом.

## Висновок

Під час практичної роботи було виконано оновлення даних за допомогою `UPDATE` та видалення конкретного запису за допомогою `DELETE`. Було перевірено зміну кількості примірників книги та заповнення дати повернення. Також перевірено роботу зовнішнього ключа з `ON DELETE RESTRICT`: видалення книги, на яку посилаються записи таблиці `loans`, було заборонено. Отримані результати підтверджують правильність роботи обмежень цілісності даних у SQLite.

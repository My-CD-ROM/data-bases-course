# Практична робота №5
## Обмеження цілісності даних у SQLite

**Варіант:** 1 — Бібліотека

### Завдання 1. NOT NULL

Для поля `title` таблиці `books` встановлено обмеження `NOT NULL`.

При спробі додати книгу без назви отримано помилку:

`NOT NULL constraint failed: books.title`

Отже, поле `title` не може бути порожнім.

### Завдання 2. UNIQUE

Для полів `title` та `author` таблиці `books` встановлено складене обмеження `UNIQUE`.

При спробі додати книгу з такими самими назвою та автором отримано помилку:

`UNIQUE constraint failed: books.title, books.author`

Отже, дублювати комбінацію назви книги та автора не можна.

### Завдання 3. CHECK

Для поля `copies_count` встановлено обмеження:

`CHECK (copies_count >= 0)`

При спробі встановити кількість примірників `-5` отримано помилку:

`CHECK constraint failed: copies_count >= 0`

Коректне значення `5` було встановлено успішно.

### Завдання 4. DEFAULT

Для поля `copies_count` встановлено значення за замовчуванням:

`DEFAULT 0`

Було додано книгу без зазначення кількості примірників.

Результат перевірки:

| title | copies_count |
|---|---:|
| Тестова книга | 0 |

Отже, якщо значення `copies_count` не вказати, SQLite автоматично встановлює `0`.

### Завдання 5. Перевірка обмеження через UPDATE

Було виконано:

`UPDATE books SET copies_count = -1 WHERE title = 'Чорна рада';`

Отримано помилку:

`CHECK constraint failed: copies_count >= 0`

Отже, обмеження `CHECK` працює не тільки під час `INSERT`, а й під час `UPDATE`.

### Завдання 6. Обґрунтування використаних обмежень

- **NOT NULL** — гарантує, що кожна книга має назву.
- **UNIQUE** — не дозволяє створювати дублікати книги з однаковими назвою та автором.
- **CHECK** — не дозволяє вказувати від'ємну кількість примірників.
- **DEFAULT** — автоматично встановлює кількість примірників `0`, якщо її не вказано.

## Висновок

Під час практичної роботи було додано та перевірено обмеження `NOT NULL`, `UNIQUE`, `CHECK` і `DEFAULT` у базі даних бібліотеки. Обмеження забезпечують коректність та цілісність даних під час додавання і зміни записів.

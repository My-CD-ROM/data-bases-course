При додаванні запису в таблицю orders без вказування колонки status командою:
INSERT INTO orders (product_id, customer_id, order_date, quantity) VALUES (1, 1, '2026-09-28', 1);
Отримано наступний результат з бази даних: id: 11, product_id: 1, customer_id: 1, order_date: 2026-09-28, quantity: 1, status: new.
Значення "new" підставилося в колонку status автоматично.   Завдання 5. Результат перевірки через UPDATE:
Спроба оновити ціну наявного товару на від'ємне значення командою:
UPDATE products SET price = -100 WHERE id = 1;
Зафіксований текст помилки: Error near line 84: CHECK constraint failed: price > 0.
Висновок: обмеження CHECK діє однаково безумовно як при виконанні INSERT, так і при UPDATE. 
Завдання 6.
NOT NULL для products.category: Товар обов'язково повинен мати категорію для фільтрації та пошуку в каталозі.

UNIQUE (name, size) для products: Назва разом із розміром створюють унікальну складську позицію (SKU), що запобігає дублюванню.

CHECK (price > 0) для products.price: Ціна товару є позитивною грошовою величиною і не може бути нульовою чи від'ємною.

DEFAULT 'new' для orders.status: Будь-яке нове замовлення автоматично отримує початковий стан "new".

Відповіді на контрольні питання
Чому в SQLite неможливо виконати ALTER TABLE ... ADD CONSTRAINT CHECK (...), і що роблять замість цього?

1. SQLite реалізовано у спрощеному вигляді для мінімізації розміру СУБД, тому команда ALTER TABLE не підтримує пряме додавання обмежень. Замість цього застосовують алгоритм перестворення таблиці: вимикають зовнішні ключі (PRAGMA foreign_keys = OFF;), перейменовують стару таблицю, створюють нову з потрібними обмеженнями, копіюють дані командою INSERT INTO ... SELECT, видаляють стару таблицю та вмикають ключі назад.

2. Що станеться, якщо перестворити таблицю з NOT NULL, якщо у старих даних вже є NULL?

Під час копіювання даних (INSERT INTO ... SELECT ...) SQLite зупинить процес з помилкою "NOT NULL constraint failed", і дані не перенесуться.

3. Чим перевірка CHECK, доданого через перестворення, відрізняється від CHECK при первинному CREATE TABLE?

Для подальших операцій (INSERT та UPDATE) різниці немає взагалі. Відмінність полягає лише в тому, що при перестворенні SQLite додатково перевіряє вже існуючі в базі записи в момент їх копіювання.

4.
Чому DEFAULT не можна перевірити спробою порушення і як його перевіряють?

DEFAULT є підставителем значення за замовчуванням, а не заборонним обмеженням, тому його неможливо порушити. Його перевіряють шляхом виконання INSERT без вказування цієї колонки, після чого через SELECT переконуються, що поле заповнилося потрібним значенням.

Завдання 1. ORDER BY за однією колонкою
При виконанні запиту до таблиці orders із сортуванням ORDER BY order_date DESC першим у результатах опинився рядок із id = 6 (дата 2026-03-03).
Чому саме він: Модифікатор DESC (Descending) впорядковує текстові дати за стандартом ISO 8601 у зворотному хронологічному порядку. Дата 2026-03-03 є найновішою у базі даних, тому вона розмістилася на самому початку вибірки.

Завдання 2. ORDER BY за кількома колонками
Запит ORDER BY customer_id ASC, order_date ASC вибудовує сортування у два етапи:
Роль першої колонки (customer_id): Групує всі замовлення за конкретними покупцями (спочатку покупці з id = 1, потім id = 2 і т.д.).
Роль другої колонки (order_date): Виконує локальне сортування всередині кожної групи однакових customer_id. Це дозволяє побачити історію покупок кожного конкретного клієнта, впорядковану від його найдавнішого замовлення до найновішого.

Завдання 3. Топ-N через ORDER BY + LIMIT
Запит ORDER BY quantity DESC LIMIT 3 знаходить 3 замовлення з найбільшою кількістю придбаних одиниць товару.
Порядок виконання: Команда ORDER BY виконується раніше за LIMIT. Спочатку СУБД сортує абсолютно всі рядки таблиці від найбільшого значення quantity до найменшого, і лише після цього LIMIT 3 зрізає перші три рядки з уже відсортованого списку.

Завдання 4. DISTINCT і BETWEEN / IN
(а) DISTINCT: Запит SELECT DISTINCT quantity FROM orders відсіяв усі дублікати та повернув 3 унікальні значення кількостей: 1, 2 та 5.

(б) BETWEEN vs IN: Для фільтрації цін у таблиці products було обрано команду BETWEEN (WHERE price BETWEEN 200 AND 1500).
Обґрунтування: Ціна є неперервною числовою величиною. BETWEEN дозволяє компактно задати межі «від і до». Використання IN тут було б недоречним, адже воно вимагало б перелічення кожного можливого числового значення ціни через кому.

Завдання 5. LIKE і пастка з кирилицею
При виконанні двох експериментальних запитів було зафіксовано такі результати:
WHERE full_name LIKE 'М%' — знайдено 1 рядок (Мельник Ганна).
WHERE full_name LIKE 'м%' — знайдено 0 рядків.
Причина відмінності: У SQLite оператор LIKE працює регістронезалежно лише для символів латинського алфавіту (ASCII). Для кириличних літер (UTF-8) порівняння є суворо регістрозалежним, оскільки велика літера «М» та мала «м» мають різні байтові коди.

Відповіді на контрольні питання
1. Чому в Завданні 3 обов'язково писати ORDER BY ПЕРЕД LIMIT, а не навпаки — і що станеться, якщо ORDER BY прибрати зовсім, залишивши лише LIMIT 3?
Чому ORDER BY пишеться перед LIMIT: Згідно з синтаксисом та логікою виконання SQL-запитів, СУБД повинна спочатку впорядкувати увесь набір даних (ORDER BY), і лише потім відсікти потрібну кількість рядків (LIMIT). Написати LIMIT перед ORDER BY синтаксично заборонено (виникне синтаксична помилка).

Що станеться без ORDER BY: Якщо прибрати ORDER BY і залишити тільки LIMIT 3, SQLite поверне перші 3 рядки у тому довільному порядку, як вони фізично збережені на диску (за замовчуванням у порядку додавання/PRIMARY KEY). Це будуть випадкові 3 записи, а не 3 найбільші чи найновіші.

2. У Завданні 4 — коли варто обирати IN, а коли BETWEEN, якщо обидві команди технічно можна замінити ланцюжком OR/AND?
BETWEEN варто обирати для неперервних діапазонів (числових, дат або часу), де є чітка нижня та верхня межа (наприклад, ціна від 100 до 500 грн, вік від 18 до 25 років, дати протягом місяця). Замінює умову x >= min AND x <= max.

IN варто обирати для дискретних (окремих) переліків значень, які не утворюють суцільний діапазон (наприклад, статус замовлення 'new' або 'shipped', товари з категорій 1, 3, 7, міста 'Київ', 'Львів'). Замінює ланцюжок x = val1 OR x = val2 OR x = val3.

3. Чому висновок Завдання 5 (про регістр і кирилицю) важливий саме для цього курсу, де майже всі текстові дані — українською?
Висновок Завдання 5 є критично важливим, оскільки незнання регістрозалежності кирилиці в SQLite призводить до прихованих помилок у програмах. Якщо розробник створить пошуковий запит на кшталт WHERE last_name LIKE 'шевченко%', база даних поверне порожній результат (0 рядків), бо прізвища збережені з великої літери (Шевченко).
Для коректного пошуку українською мовою в SQLite розробникам необхідно або суворо контролювати регістр вхідних даних у коді (наприклад, приводити першу літеру до верхнього регістру), або використовувати додаткові функції форматування (наприклад, LOWER(full_name) LIKE LOWER('шевченко%')).

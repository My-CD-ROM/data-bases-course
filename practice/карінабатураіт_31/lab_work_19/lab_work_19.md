запитання1. Чим PostgreSQL як клієнт-серверна СУБД відрізняється від SQLite і яка в ньому ієрархія об’єктів?Відмінність: SQLite — файлова СУБД (уся база в одному файлі .db без окремого сервера). PostgreSQL — клієнт-серверна СУБД: працює як окремий серверний процес, керує багатокористувацьким доступом, правами й транзакціями, а клієнти (pgAdmin, psql) підключаються до нього по мережі (порт 5432).
Ієрархія об’єктів: Сервер (екземпляр PostgreSQL) - Бази даних (lab_work19) -  Схеми (public) - Об’єкти схеми (таблиці, послідовності, подання, індекси) - Стовпці, обмеження й рядки.
2. Чому саме GENERATED ALWAYS AS IDENTITY, а не старіший SERIAL, обрано як основний спосіб автоінкременту в цьому курсі і чим вони відрізняються по суті?SERIAL — застарілий псевдотип-макрос, який неявно створює окрему послідовність і дозволяє випадково вставляти id вручну, через що легко збивається лічильник.GENERATED ALWAYS AS IDENTITY — сучасний стандарт SQL, який жорстко захищає стовпець від випадкової ручної підсsтановки id під час звичайного INSERT і простіше керується за правами доступу.
3. Чому таблиці-виміри потрібно перенести (і створити, і заповнити даними) перед фактовою таблицею, а не в довільному порядку?Фактова таблиця (orders) посилається на таблиці-виміри (customers, products) через FOREIGN KEY. Якщо створювати або заповнювати orders раніше за довідники, PostgreSQL відхилить запит, оскільки батьківських таблиць або відповідних id у них ще не існує (SQL state: 23503).
4. Що сталося б, якби завдання 4 (виправлення лічильника) пропустити, і на якому саме кроці це призвело б до помилки?Після імпорту CSV рядки вже мають значення id (1..N), але лічильник послідовності залишається на 1. Якщо не оновити його через setval, то під час першого ж INSERT без явного id PostgreSQL спробує підставити id = 1 і викличе помилку порушення унікальності первинного ключа (SQL state: 23505).
5. Для чого потрібні pgAdmin і Query Tool і аналогами яких інструментів DB Browser for SQLite вони є?pgAdmin — графічний клієнт для адміністрування сервера PostgreSQL та перегляду структури й даних; аналог оболонки DB Browser for SQLite (Database Structure / Browse Data).Query Tool — вбудований у pgAdmin редактор і виконавець SQL-запитів; аналог вкладки Execute SQL у DB Browser for SQLite.
6. Чому після перенесення бази в PostgreSQL для перевірки зовнішніх ключів більше не потрібна команда PRAGMA foreign_keys?У SQLite перевірка зовнішніх ключів вимкнена за замовчуванням і потребує PRAGMA foreign_keys = ON у кожному сеансі. У PostgreSQL контроль FOREIGN KEY увімкнений завжди за замовчуванням на рівні ядра СУБД, а директиви PRAGMA в PostgreSQL узагалі не існують.

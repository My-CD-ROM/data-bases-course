    Практика 16. Імпорт даних із CSV у SQLite¶

    Мета заняття: розібратися з форматом CSV і командами імпорту CLI sqlite3 (.mode csv, .import), а потім імпортувати готовий CSV-файл із додатковими рядками у свою таблицю через проміжну (staging) таблицю, оскільки пряме .import у таблицю з id не працює. Окремої лекції з цієї теми немає: усю потрібну теорію наведено нижче на цій сторінці.

    Теорія¶

    Досі кожен рядок таблиці потрапляв у базу через власноруч написаний INSERT. На практиці ж дані частіше приходять готовим файлом: вивантаженням з Excel, Google Таблиць, вебсервісу чи іншої СУБД. Переписувати сотні рядків такого файлу в INSERT вручну не варіант, тому SQLite вміє завантажити файл напряму. Усі приклади цього розділу побудовано на ветклініці: таблиця animals з трьома тваринами і файл new_animals.csv з трьома новими.

    CREATE TABLE animals (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    species TEXT,
    age INTEGER,
    status TEXT
);
INSERT INTO animals (name, species, age, status) VALUES
('Мурчик', 'кіт', 3, 'на обліку'),
('Рекс', 'собака', 5, 'на обліку'),
('Белла', 'собака', 7, 'вибув');

    1. Формат CSV¶

    CSV (comma-separated values, «значення через кому») є простим текстовим форматом таблиці. Його можна відкрити будь-яким текстовим редактором:

    name,species,age,status
Джек,собака,2,на обліку
Соня,кіт,4,на обліку
"Пухнастик, молодший",кролик,1,на обліку

    Правила формату:

    • перший рядок містить заголовки колонок, а не дані;
    • кожен наступний рядок файлу є одним записом (рядком таблиці);
    • значення в межах рядка розділені комами, і їх стільки ж, скільки заголовків;
    • якщо значення саме містить кому, його беруть у подвійні лапки ("Пухнастик, молодший"), інакше кома розірвала б його на дві колонки; лапка всередині такого значення записується двічі ("Салат ""Цезар""").

    Саме тому CSV і став найпоширенішим форматом обміну таблицями між зовсім різними програмами: Excel, Google Таблиці й будь-яка СУБД уміють і зберігати його, і читати.

    2. Імпорт у CLI: .mode csv і .import¶

    .mode csv
.import --skip 1 new_animals.csv animals_staging

    Це не SQL-команди, а дот-команди CLI sqlite3: вони починаються з крапки й пишуться без крапки з комою в кінці. .mode csv вмикає режим CSV (роздільник: кома, з підтримкою лапок), а .import файл.csv таблиця завантажує кожен запис файлу як рядок указаної таблиці. Прапорець --skip 1 пропускає перший рядок файлу, тобто заголовки.

    Якщо таблиця вже існує, а --skip 1 забули, рядок заголовків потрапить у неї як звичайні дані (помилки при цьому не буде):

           name          species  age   status
-------------------  -------  ---  ---------
name                 species  age  status
Джек                 собака     2  на обліку
Соня                 кіт        4  на обліку
Пухнастик, молодший  кролик     1  на обліку

    Третій запис показує роботу лапок: Пухнастик, молодший завдяки лапкам лишився одним значенням у колонці name.

    .import розкладає значення по колонках таблиці за порядком, а не за назвами заголовків: перше значення запису йде в першу колонку, друге в другу і так далі.

    3. Пастка: у CSV немає id, а в таблиці є¶

    Файл new_animals.csv має 4 колонки, а таблиця animals має 5: першою стоїть id INTEGER PRIMARY KEY. Пряма спроба імпорту в саму таблицю закінчується так:

    .mode csv
.import --skip 1 new_animals.csv animals

    new_animals.csv:2: expected 5 columns but found 4 - filling the rest with NULL
new_animals.csv:2: INSERT failed: datatype mismatch
new_animals.csv:3: expected 5 columns but found 4 - filling the rest with NULL
new_animals.csv:3: INSERT failed: datatype mismatch
new_animals.csv:4: expected 5 columns but found 4 - filling the rest with NULL
new_animals.csv:4: INSERT failed: datatype mismatch

    Кожне значення зсунулося на одну колонку ліворуч: кличка Джек намагається потрапити в id, куди можна записати лише ціле число, і рядок відхиляється. SELECT COUNT(*) FROM animals; після цього повертає ті самі 3: жодна тварина не додалася. Число в префіксі (:2, :3, :4) означає номер рядка у файлі, рахуючи й рядок заголовків.

    Дописувати колонку id у файл власноруч теж погана ідея: номери з файлу можуть збігтися з уже зайнятими id у таблиці, і такі рядки впадуть з помилкою унікальності первинного ключа. Нумерацію нових рядків варто довірити самій СУБД.

    4. Рішення: проміжна (staging) таблиця¶

    Проміжна таблиця є тимчасовим «контейнером», у якого рівно ті самі колонки, що й у CSV-файлі, без id. Імпорт іде в чотири кроки:

    -- 1. Проміжна таблиця з тими самими колонками, що в CSV (без id)
CREATE TABLE animals_staging (
    name TEXT,
    species TEXT,
    age INTEGER,
    status TEXT
);

    -- 2. Імпорт CSV саме в неї: кількість колонок збігається
.mode csv
.import --skip 1 new_animals.csv animals_staging

    -- 3. Перенесення в реальну таблицю: id SQLite призначає сам
INSERT INTO animals (name, species, age, status)
SELECT name, species, age, status FROM animals_staging;

-- 4. Проміжна таблиця більше не потрібна
DROP TABLE animals_staging;

    На кроці 3 колонку id не вказано ні в INSERT, ні в SELECT, тому SQLite призначає кожному новому рядку наступний номер після найбільшого наявного: у таблиці були id 1–3, нові тварини отримали 4, 5 і 6. Нумерація продовжується, а не починається знову з 1. DROP TABLE на кроці 4 видаляє лише проміжну таблицю; перенесені рядки в animals лишаються. Якщо ж проміжну таблицю не видалити, наступний імпорт допише в неї нові рядки до старих, і повторне INSERT ... SELECT перенесе старі рядки вдруге.

    5. Той самий принцип у DB Browser for SQLite¶

    DB Browser for SQLite має майстер імпорту (File, Import, Table from CSV file), який створює нову таблицю з колонками, узятими з рядка заголовків CSV. У наявну таблицю майстер імпортує лише тоді, коли кількість колонок збігається, тож у animals з id файл без id теж не потрапить. Тож і тут принцип той самий: імпортуйте файл майстром як нову проміжну таблицю (наприклад, animals_staging), а потім виконайте той самий INSERT ... SELECT і DROP TABLE у вкладці Execute SQL. Налаштування майстра (роздільник, кодування, заголовки) детально розглянуто на практиці 17.

    6. Перевірка результату¶

    Відсутність помилок ще не доводить, що всі рядки дійшли до таблиці. Найпростіша перевірка: порівняти COUNT(*) до й після імпорту. Різниця має дорівнювати кількості записів у CSV без рядка заголовків:

    SELECT COUNT(*) FROM animals;   -- до імпорту: 3
-- ... кроки 1–4 ...
SELECT COUNT(*) FROM animals;   -- після: 6, приріст 3 = 3 записи у файлі

    Друга перевірка: знайти саме нові рядки за значеннями, яких раніше в таблиці не було, і подивитися, чи стоять значення у своїх колонках і які id вони отримали:

    SELECT id, name, species
FROM animals
WHERE name IN ('Джек', 'Соня', 'Пухнастик, молодший');

    id         name          species
--  -------------------  -------
 4  Джек                 собака
 5  Соня                 кіт
 6  Пухнастик, молодший  кролик

    Приклад: наскрізна демонстрація¶

    Уся послідовність з теорії одним блоком (ветклініка, файл new_animals.csv з трьома тваринами):

    SELECT COUNT(*) FROM animals;  -- 3

CREATE TABLE animals_staging (
    name TEXT, species TEXT, age INTEGER, status TEXT
);

    .mode csv
.import --skip 1 new_animals.csv animals_staging

    SELECT * FROM animals_staging;  -- 3 рядки, заголовків серед них немає

INSERT INTO animals (name, species, age, status)
SELECT name, species, age, status FROM animals_staging;

DROP TABLE animals_staging;

SELECT COUNT(*) FROM animals;  -- 6: стало більше рівно на 3

    Завдання¶

    Завдання 1. Підрахунок до імпорту. Виконайте SELECT COUNT(*) FROM цільова_таблиця; і зафіксуйте письмово точне число рядків, яке було у вашій цільовій таблиці до імпорту.

    Завдання 2. Проміжна таблиця й імпорт CSV. Створіть проміжну таблицю з колонками, що точно відповідають заголовкам CSV-файлу вашого варіанта (без id; типи колонок візьміть такі самі, як у цільовій таблиці), і імпортуйте файл у неї через CLI (.mode csv + .import --skip 1 ...) або майстер імпорту DB Browser for SQLite. Перевірте вміст проміжної таблиці окремим SELECT.

    Завдання 3. Перенесення в реальну таблицю. Виконайте INSERT ... SELECT із проміжної таблиці у вашу цільову таблицю, а потім видаліть проміжну таблицю (DROP TABLE). Виконайте SELECT COUNT(*) ще раз і письмово підтвердьте: різниця з числом із Завдання 1 дорівнює точно 8 (кількості рядків у CSV-файлі).

    Завдання 4. Перевірка конкретних нових рядків. Складіть запит (WHERE ... IN (...) чи LIKE, лекція 10), що знаходить у таблиці саме ті рядки, які прийшли з імпортованого CSV (за назвою чи значенням, якого не було раніше). Письмово підтвердьте, що їхні id природно продовжують нумерацію попередніх рядків, а не почались знову з 1.

    Завдання 5. Свідома помилка прямого імпорту. Спробуйте (на окремій тестовій копії файлу бази, щоб не зіпсувати робочу!) виконати .import CSV-файлу напряму в цільову таблицю (не в проміжну). Зафіксуйте письмово, що саме сталося: повідомлення про помилку, неправильний розподіл значень по колонках чи щось інше, і поясніть, чому саме через різну кількість колонок (CSV без id, таблиця з id) це не працює безпосередньо.

    Що здати й оцінюється¶

    Здайте lab_work_16.sql (усі виконані команди Завдань 1–5 разом з результатами підрахунків), lab_work_16.db (файл бази даних після імпорту CSV) і lab_work_16.md (письмові пояснення до Завдань 1, 3, 4 і 5). Контрольні питання:

    • Чому CSV-файл цієї практики навмисно не містить колонку id: що б сталося, якби спробувати додати її туди самостійно з довільними значеннями?
    • Яка роль DROP TABLE проміжної таблиці в кінці процесу: чи можна просто залишити її в базі «про всяк випадок»?
    • Чим підрахунок COUNT(*) до й після імпорту (Завдання 1 і 3) кращий за враження «здається, що імпорт спрацював»?

    Оцінюється правильна структура проміжної таблиці (Завдання 2), точний збіг приросту кількості рядків з кількістю рядків CSV (Завдання 3), і зафіксований результат свідомої помилки прямого імпорту (Завдання 5).

    Підсумок заняття¶

    • Розібрано формат CSV і дот-команди .mode csv та .import --skip 1 CLI sqlite3.
    • Імпортовано 8 нових рядків CSV-файлу свого варіанта в цільову таблицю через проміжну таблицю, без жодного вигаданого чи вручну набраного значення id.
    • Підтверджено підрахунком COUNT(*), що кількість перенесених рядків точно відповідає кількості рядків вихідного CSV-файлу.
    • На практиці підтверджено, чому прямий імпорт CSV без id у таблицю з колонкою id не працює безпосередньо.

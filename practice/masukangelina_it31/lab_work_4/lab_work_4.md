# Практична робота №4

## Варіант 1 — Бібліотека

### Мета роботи

Навчитися створювати пов'язані таблиці в SQLite, використовувати зовнішні ключі, налаштовувати поведінку при видаленні пов'язаних записів та перевіряти роботу обмежень цілісності даних.

### Завдання 1. Створення таблиці-виміру

Для виконання роботи було створено базу даних `lab_work_4.db`.

На початку виконання SQL-скрипту було увімкнено контроль зовнішніх ключів:

```sql
PRAGMA foreign_keys = ON;
```

Було створено таблицю `readers`, яка містить інформацію про читачів бібліотеки:

* `id` — первинний ключ;
* `last_name` — прізвище;
* `first_name` — ім'я;
* `email` — електронна пошта;
* `registration_date` — дата реєстрації.

До таблиці було додано 6 читачів.

### Завдання 2. Створення факт-таблиці

Було створено таблицю `loans`, яка містить інформацію про видачу книг читачам.

Таблиця містить такі поля:

* `id` — первинний ключ;
* `book_id` — зовнішній ключ на таблицю `books`;
* `reader_id` — зовнішній ключ на таблицю `readers`;
* `loan_date` — дата видачі книги;
* `return_date` — дата повернення книги.

Для `book_id` встановлено:

```sql
ON DELETE RESTRICT
```

Це означає, що книгу не можна видалити, якщо на неї існує запис у таблиці `loans`. Такий варіант дозволяє зберегти історію видачі книг.

Для `reader_id` встановлено:

```sql
ON DELETE SET NULL
```

У цьому випадку після видалення читача запис про видачу книги зберігається, але значення `reader_id` стає `NULL`. Це дозволяє не втрачати інформацію про сам факт видачі книги.

### Завдання 3. Заповнення таблиць даними

До таблиці `readers` було додано 6 записів.

До таблиці `loans` було додано 10 записів. Усі значення зовнішніх ключів відповідають існуючим записам у таблицях `books` та `readers`.

Таким чином, були створені пов'язані дані про книги, читачів та їх видачу.

### Завдання 4. Перевірка зовнішнього ключа

Для перевірки роботи обмеження зовнішнього ключа було виконано спробу додати запис із неіснуючим значенням:

```sql
INSERT INTO loans (id, book_id, reader_id, loan_date, return_date)
VALUES (11, 9999, 1, '2026-09-18', NULL);
```

Оскільки книги з `id = 9999` у таблиці `books` немає, SQLite не дозволила виконати операцію.

Точний текст помилки:

```text
FOREIGN KEY constraint failed
```

Помилковий запис до таблиці `loans` не додався.

### Завдання 5. Порівняння з ER-діаграмою

Структура бази даних відповідає ER-діаграмі, створеній у Практичній роботі №3.

У базі присутні три таблиці:

* `books`;
* `readers`;
* `loans`.

Таблиця `loans` має два зовнішні ключі:

```text
loans.book_id → books.id
loans.reader_id → readers.id
```

Отже, реалізована структура відповідає попередньо спроєктованій моделі бібліотеки. Додатково у Практичній роботі №4 для зовнішніх ключів було визначено поведінку при видаленні пов'язаних записів: `RESTRICT` для книги та `SET NULL` для читача.

### Контрольні питання

**1. Для чого потрібен `PRAGMA foreign_keys = ON` і чому його потрібно повторювати для кожного з'єднання?**

`PRAGMA foreign_keys = ON` вмикає контроль зовнішніх ключів у SQLite. Він потрібен для того, щоб база даних перевіряла відповідність значень зовнішніх ключів записам у пов'язаних таблицях. Налаштування діє для конкретного з'єднання з базою даних, тому його потрібно вмикати для кожного нового з'єднання.

**2. Чим відрізняються PRIMARY KEY та FOREIGN KEY?**

`PRIMARY KEY` однозначно ідентифікує запис у таблиці. Значення первинного ключа має бути унікальним.

`FOREIGN KEY` використовується для зв'язку між таблицями та посилається на ключ іншої таблиці. Він забезпечує зв'язок між пов'язаними даними.

**3. Чим відрізняються CASCADE та RESTRICT? Чому для різних зв'язків можуть бути обрані різні дії?**

`RESTRICT` забороняє видалення запису, якщо на нього посилаються записи з іншої таблиці.

`CASCADE` автоматично видаляє пов'язані записи.

Для різних зв'язків можуть використовуватися різні дії залежно від логіки предметної області. У цій роботі для книги використано `RESTRICT`, щоб не дозволити видалення книги з історії видачі. Для читача використано `SET NULL`, щоб зберегти запис про видачу навіть після видалення даних про читача.

### Висновок

Під час практичної роботи було створено пов'язані таблиці `readers` та `loans`, налаштовано зовнішні ключі та їх поведінку при видаленні записів. Базу даних було заповнено пов'язаними даними про книги, читачів та видачу книг. Також було перевірено роботу обмеження зовнішнього ключа шляхом спроби додати запис із неіснуючим `book_id`. У результаті SQLite повернула помилку `FOREIGN KEY constraint failed`, що підтвердило правильну роботу контролю цілісності даних.

# Практична робота №5

## Тема

Обмеження цілісності даних: NOT NULL, UNIQUE, CHECK, DEFAULT.

## Мета роботи

Навчитися використовувати обмеження цілісності даних у базі даних SQLite: NOT NULL, UNIQUE, CHECK та DEFAULT. Навчитися додавати ці обмеження до існуючих таблиць шляхом їх повторного створення та перевіряти їх роботу під час додавання і зміни даних.

## Варіант

Варіант 1 — Бібліотека.

## Хід виконання роботи

У роботі використовувалася база даних бібліотеки з таблицями `books`, `readers` та `loans`.

### Завдання 1. Обмеження NOT NULL

Для поля `genre` таблиці `books` було додано обмеження `NOT NULL`.

Після цього була виконана спроба додати книгу без зазначення жанру:

```sql
INSERT INTO books (title, author, publication_year, copies_count)
VALUES ('Тестова книга', 'Тестовий автор', 2026, 1);
```

Система не дозволила виконати операцію та вивела помилку:

```text
NOT NULL constraint failed: books.genre
```

Отже, поле `genre` обов'язково повинно містити значення.

### Завдання 2. Обмеження UNIQUE

Для поля `email` таблиці `readers` було додано обмеження `UNIQUE`.

Було виконано спробу додати читача з електронною поштою, яка вже існує:

```sql
INSERT INTO readers (last_name, first_name, email, registration_date)
VALUES ('Тестовий', 'Читач', 'olena@example.com', '2026-09-23');
```

Було отримано помилку:

```text
UNIQUE constraint failed: readers.email
```

Отже, електронна пошта кожного читача повинна бути унікальною.

### Завдання 3. Обмеження CHECK

Для поля `copies_count` таблиці `books` було встановлено умову:

```sql
CHECK (copies_count >= 0)
```

Спочатку була виконана спроба встановити від'ємну кількість примірників:

```sql
UPDATE books
SET copies_count = -1
WHERE id = 1;
```

Було отримано помилку:

```text
CHECK constraint failed: copies_count >= 0
```

Після цього було встановлено допустиме значення:

```sql
UPDATE books
SET copies_count = 5
WHERE id = 1;
```

Операція виконалася успішно.

Отже, обмеження `CHECK` не дозволяє зберігати від'ємну кількість примірників.

### Завдання 4. Обмеження DEFAULT

Для поля `copies_count` було встановлено значення за замовчуванням:

```sql
DEFAULT 1
```

Було додано нову книгу без зазначення кількості примірників:

```sql
INSERT INTO books (title, author, publication_year, genre)
VALUES ('Тестова книга DEFAULT', 'Тестовий автор', 2026, 'тест');
```

Після перевірки запису значення поля `copies_count` було встановлено автоматично — `1`.

Отже, якщо кількість примірників не вказана під час додавання книги, база даних автоматично встановлює значення `1`.

### Завдання 5. Перевірка обмеження під час UPDATE

Для перевірки роботи обмеження `NOT NULL` під час зміни даних була виконана команда:

```sql
UPDATE books
SET genre = NULL
WHERE id = 1;
```

Система відхилила операцію та вивела помилку:

```text
NOT NULL constraint failed: books.genre
```

Це показує, що обмеження цілісності працюють не тільки під час `INSERT`, а й під час `UPDATE`.

### Завдання 6. Обґрунтування обмежень

Обмеження `NOT NULL` для поля `genre` потрібне, оскільки для кожної книги повинен бути зазначений жанр.

Обмеження `UNIQUE` для поля `email` потрібне, щоб два різні читачі не мали однакової електронної пошти.

Обмеження `CHECK` для поля `copies_count` потрібне, щоб кількість примірників не могла бути від'ємною.

Обмеження `DEFAULT` для поля `copies_count` потрібне для автоматичного встановлення кількості примірників, якщо користувач не вказав її під час додавання книги.

## Висновок

Під час практичної роботи було опрацьовано основні обмеження цілісності даних у SQLite: `NOT NULL`, `UNIQUE`, `CHECK` та `DEFAULT`. Було виконано їх додавання до таблиць та перевірено роботу на прикладах `INSERT` і `UPDATE`. У результаті було підтверджено, що обмеження допомагають запобігати некоректному введенню даних та підтримувати цілісність бази даних.

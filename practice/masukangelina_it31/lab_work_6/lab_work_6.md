# Практична робота №6

## Тема

Оновлення та видалення записів у базі даних. Оператори `UPDATE` і `DELETE`.

## Мета роботи

Навчитися змінювати та видаляти записи в базі даних за допомогою операторів `UPDATE` і `DELETE`, а також перевірити роботу зовнішніх ключів з дією `ON DELETE SET NULL`.

## Варіант

Варіант 1 — Бібліотека.

## Хід виконання роботи

У роботі використовувалася база даних бібліотеки з таблицями `books`, `readers` та `loans`.

### Завдання 1. UPDATE у фактовій таблиці

Фактовою таблицею є `loans`. Для позики з `id = 4` було заповнено поле `return_date`, яке раніше мало значення `NULL`.

```sql
UPDATE loans
SET return_date = '2026-09-23'
WHERE id = 4;
```

У результаті було змінено рівно один рядок.

### Завдання 2. UPDATE у таблиці-вимірі

У таблиці `books` було змінено кількість примірників книги з `id = 1`.

```sql
UPDATE books
SET copies_count = 6
WHERE id = 1;
```

Було змінено рівно один рядок.

`UPDATE` доречний у цьому випадку, тому що змінюється поточне значення кількості примірників уже існуючої книги, а не створюється новий запис.

### Завдання 3. DELETE одного рядка

Перед видаленням було перевірено кількість записів у таблиці `loans`. У таблиці було 10 записів.

Після цього було видалено позику з `id = 2`:

```sql
DELETE FROM loans
WHERE id = 2;
```

Було видалено рівно один рядок.

Після видалення кількість записів у таблиці `loans` стала 9. Отже, було видалено саме один запис.

### Завдання 4. Перевірка ON DELETE

У таблиці `loans` для зовнішнього ключа `reader_id` встановлено:

```sql
ON DELETE SET NULL
```

Перед видаленням читача з `id = 4` було визначено, що на нього посилаються два записи таблиці `loans`.

Прогноз:

після видалення читача `id = 4` пов'язані записи в таблиці `loans` повинні залишитися, але значення `reader_id` у них повинно автоматично змінитися на `NULL`.

Для перевірки було виконано:

```sql
DELETE FROM readers
WHERE id = 4;
```

Читача було успішно видалено.

Після цього було перевірено пов'язані записи:

```sql
SELECT id, book_id, reader_id, loan_date, return_date
FROM loans
WHERE id IN (4, 8);
```

Було отримано 2 записи. Обидва записи залишилися в таблиці `loans`, а їхнє поле `reader_id` стало `NULL`.

Фактичний результат повністю відповідає прогнозу. Це підтверджує правильну роботу `ON DELETE SET NULL`.

## Контрольні питання

### 1. Чим `UPDATE ... SET колонка = колонка + 1` відрізняється від `UPDATE ... SET колонка = <конкретне число>`?

`UPDATE ... SET колонка = колонка + 1` збільшує поточне значення колонки на одиницю, а `UPDATE ... SET колонка = <конкретне число>` замінює поточне значення на вказане число.

### 2. Чому NOT NULL, UNIQUE і CHECK перевіряються при UPDATE, а FOREIGN KEY потребує PRAGMA foreign_keys = ON?

`NOT NULL`, `UNIQUE` і `CHECK` є обмеженнями таблиці та перевіряються під час зміни даних. У SQLite перевірка зовнішніх ключів виконується лише тоді, коли для поточного з'єднання увімкнено `PRAGMA foreign_keys = ON`.

### 3. Що змінилося б при ON DELETE CASCADE замість RESTRICT?

При `ON DELETE CASCADE` видалення запису з таблиці-виміру автоматично призвело б до видалення всіх пов'язаних записів у фактовій таблиці. При `RESTRICT` видалення батьківського запису, на який є посилання, було б заборонено.

### 4. Чому DELETE без WHERE небезпечніший за помилку типу чи порушення обмеження цілісності?

`DELETE` без `WHERE` може видалити всі записи таблиці одразу. На відміну від порушення типу або обмеження цілісності, така команда може успішно виконатися і призвести до втрати великої кількості даних.

## Висновок

Під час практичної роботи було виконано оновлення записів за допомогою `UPDATE` та видалення записів за допомогою `DELETE`. Було змінено один запис у фактовій таблиці та один запис у таблиці-вимірі, а також видалено один запис із таблиці `loans`. Додатково було перевірено роботу `ON DELETE SET NULL`. У результаті підтверджено, що після видалення читача пов'язані записи позик залишаються в базі даних, а значення зовнішнього ключа автоматично змінюється на `NULL`.

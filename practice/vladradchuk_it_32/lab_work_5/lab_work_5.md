Практична робота №5



Варіант 3 — Кінотеатр



Мета роботи



Навчитися використовувати обмеження цілісності даних у SQLite: NOT NULL, UNIQUE, CHECK та DEFAULT.



Хід роботи



NOT NULL — додано обмеження для поля email таблиці viewers. Перевірка показала, що запис без email не допускається.



UNIQUE — додано обмеження унікальності для email глядачів. Повторне використання адреси викликає помилку.



CHECK — для поля duration\_min таблиці movies встановлено умову duration\_min > 0. Від'ємна тривалість не допускається.



DEFAULT — для поля status встановлено значення за замовчуванням 'у прокаті'. Під час додавання фільму без зазначення статусу це значення встановлюється автоматично.



Перевірено роботу обмеження NOT NULL за допомогою UPDATE. Спроба встановити email у NULL завершилася помилкою.



Контрольні запитання



1\. Чи можна додати обмеження до вже створеної таблиці через ALTER TABLE?



У SQLite більшість обмежень не можна безпосередньо додати до наявної таблиці. Для цього створюють нову таблицю з потрібними обмеженнями, копіюють дані, видаляють стару таблицю та перейменовують нову.



2\. Що станеться, якщо додати NOT NULL до поля, у якому вже є NULL?



Під час перенесення даних у нову таблицю виникне помилка, оскільки NULL не відповідає обмеженню NOT NULL. Спочатку потрібно виправити такі записи.



3\. Для чого використовується CHECK?



CHECK перевіряє, чи відповідає значення заданій умові. У цій роботі він забороняє вказувати тривалість фільму, яка дорівнює нулю або є від'ємною.



4\. Як перевірити роботу DEFAULT?



Потрібно додати запис, не вказуючи значення відповідного поля, а потім виконати SELECT. SQLite автоматично підставить значення за замовчуванням.



Висновок



Під час практичної роботи було додано та перевірено обмеження NOT NULL, UNIQUE, CHECK і DEFAULT у базі даних кінотеатру. Перевірки підтвердили, що вони допомагають контролювати правильність введення даних і забезпечують цілісність бази даних.

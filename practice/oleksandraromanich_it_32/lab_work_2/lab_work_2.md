Пояснення до Завдання 4:

Запит WHERE genre = NULL не повертає жодного рядка, бо NULL — це не «порожнє значення», а маркер «невідомо». Будь-яке порівняння з NULL (навіть NULL = NULL) дає не TRUE і не FALSE, а NULL. WHERE пропускає далі тільки рядки, де умова істинна, тому з = NULL не проходить жоден рядок. Правильний оператор — IS NULL (перевіряє «чи комірка без значення»), який повертає TRUE/FALSE, а не NULL.

Контрольні питання — відповіді:

1. Чому WHERE price = NULL завжди порожній?
Тому що NULL означає «значення невідоме». Порівняння = NULL запитує «чи дорівнює price чомусь невідомому» і завжди повертає NULL — не TRUE. WHERE приймає лише TRUE. Замість цього треба писати IS NULL (або IS NOT NULL).

2. Чим WHERE відрізняється від HAVING?
WHERE фільтрує окремі рядки до групування, тому не може містити агрегатні функції. HAVING фільтрує готові групи після GROUP BY, тому може використовувати COUNT, SUM, AVG тощо. Порядок виконання: WHERE → GROUP BY → HAVING → ORDER BY.

3. Коли варто уникати SELECT *?
Коли таблиця має багато стовпців, важкі поля (BLOB, довгі TEXT), або коли структура може змінитися. SELECT * витягує все зайве (повільніше, більше пам'яті), ламає клієнтський код при додаванні нового стовпця, і не дає контролю над порядком стовпців. У робочому коді краще перелічувати потрібні стовпці явно.

**Контрольні питання**

Чим PostgreSQL як клієнт-серверна СУБД відрізняється від SQLite і яка в ньому ієрархія об’єктів?  
PostgreSQL як клієнт-серверна відрізняється від SQLite тим, що база даних створюється не в окремому файлі, а на сервері(localhost). Ієрархія PostgreSQL: Servers -> Databases -> Сама база даних -> Schemas -> public -> Tables

Чому саме GENERATED ALWAYS AS IDENTITY, а не старіший SERIAL, обрано як основний спосіб автоінкременту в цьому курсі і чим вони відрізняються по суті?  
Тому що GENERATED ALWAYS AS IDENTITY є стандартом SQL і в такому способі важче зламати нумерецію. SERIAL просто може додати вже наявне значення id, в той час як GENERATED ALWAYS AS IDENTITY не дозволяє просто вставити будь-який id

Чому таблиці-виміри потрібно перенести (і створити, і заповнити даними) перед фактовою таблицею, а не в довільному порядку?  
Тому що у PostgreSQL постійно перевіряються зовнішні ключі. Якщо спершу перенести фактову таблицю, то не вийде, бо виведе помилку про неіснуючий зовнішній ключ

Що сталося б, якби завдання 4 (виправлення лічильника) пропустити, і на якому саме кроці це призвело б до помилки?  
Тоді при вставленні нових даних виникали б помилки через те, що лічильник не бачить вже додані дані через експорт та їхні PK. Лічильник намагався б використати вже зайнятий PK

Для чого потрібні pgAdmin і Query Tool і аналогами яких інструментів DB Browser for SQLite вони є?  
pgAdmin потрібен для графічного інтерфейсу та роботи з таблицею. Він подібний до самого DB4S. Query Tool необхідний для роботи із SQL-командами. Аналогічний до Execute SQL у DB4S

Чому після перенесення бази в PostgreSQL для перевірки зовнішніх ключів більше не потрібна команда PRAGMA foreign_keys?  
Тому що в PostgreSQL вже наперед активна перевірка зовнішніх ключів, на відміну від SQLite

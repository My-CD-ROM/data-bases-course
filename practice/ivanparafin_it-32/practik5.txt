Чому не можна ALTER TABLE ... ADD CONSTRAINT CHECK (...)?
SQLite не підтримує просте додавання такого обмеження до вже існуючої таблиці. Тому потрібно перестворити таблицю: створити нову таблицю з потрібним CHECK, перенести в неї дані, а стару замінити.
Що буде, якщо додати NOT NULL, а в старих даних є NULL?
Під час перенесення даних виникне помилка, тому що старі NULL не відповідають новому обмеженню NOT NULL.
Чим відрізняється CHECK після перестворення від CHECK при CREATE TABLE?
Нічим за принципом роботи. В обох випадках SQLite перевіряє умову CHECK під час INSERT та UPDATE. Різниця лише в тому, що в першому випадку обмеження було додано через перестворення таблиці.
Чому DEFAULT перевіряють не через помилку?
Тому що DEFAULT не забороняє значення, а автоматично підставляє його, коли стовпець не вказаний під час INSERT. Тому потрібно зробити INSERT без цього стовпця, а потім виконати SELECT і перевірити, чи підставилося значення за замовчуванням.

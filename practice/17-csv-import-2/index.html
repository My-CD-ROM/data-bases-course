    Практика 17. Імпорт даних із CSV у SQLite: типові проблеми, перевірка й експорт¶

    Мета заняття: навчитися розпізнавати й виправляти типові проблеми "брудного" CSV-файлу (інший роздільник, порожні поля, дублікати, заголовок, кодування), перевіряти якість даних у проміжній таблиці перед перенесенням, імпортувати файл через майстер DB Browser for SQLite і вивантажувати результат запиту назад у CSV. Практика продовжує Практику 16: проміжна таблиця й INSERT ... SELECT звідти вважаються відомими. Окремої лекції з цієї теми немає, теорію наведено нижче на цій сторінці.

    Теорія¶

    У Практиці 16 файл був "чистим": коми, заголовок, усі значення на місці. Реальні файли такими бувають рідко. Приклади цього розділу продовжують ветклініку з теорії Практики 16: таблиця animals (id, name, species, age, status) із трьома тваринами і файл shelter_animals.csv, який притулок вивантажив з Excel:

    name;species;age;status
Бублик;собака;3;на обліку
Ліза;кіт;;на обліку
Граф;собака;5;на обліку
Сірко, старший;собака;;на обліку
Бублик;собака;3;на обліку

    У файлі три проблеми одразу: роздільник ; замість коми, порожній вік у двох тварин і Бублик, записаний двічі. Нижче видно, як кожна з них проявляється і як її виправити.

    1. Попередження .import не зупиняють імпорт¶

    Якщо кількість полів у записі не збігається з кількістю колонок таблиці, .import не відмовляється працювати, а лише друкує попередження й вставляє рядок як вийде:

    • expected 4 columns but found 1 - filling the rest with NULL: полів менше, ніж колонок, решта колонок отримує NULL;
    • expected 4 columns but found 5 - extras ignored: полів більше, зайві відкидаються.

    Тому після кожного імпорту читайте всі повідомлення CLI і дивіться вміст проміжної таблиці, а не лише на те, що "помилки не було".

    2. Роздільник: кома чи крапка з комою¶

    Excel з українськими регіональними налаштуваннями зберігає CSV із крапкою з комою, бо кома в цих налаштуваннях є десятковим знаком. Імпорт такого файлу в режимі .mode csv дає попередження на кожен запис:

    shelter_animals.csv:2: expected 4 columns but found 1 - filling the rest with NULL
shelter_animals.csv:3: expected 4 columns but found 1 - filling the rest with NULL
shelter_animals.csv:4: expected 4 columns but found 1 - filling the rest with NULL
shelter_animals.csv:5: expected 4 columns but found 2 - filling the rest with NULL
shelter_animals.csv:6: expected 4 columns but found 1 - filling the rest with NULL

    COUNT(*) проміжної таблиці при цьому дорівнює 5, ніби все гаразд, але кожен запис цілком опинився в колонці name (Бублик;собака;3;на обліку), а решта колонок порожні. Запис Сірко, старший розпався по комі на два поля. Виправлення: після .mode csv задати роздільник командою .separator:

    .mode csv
.separator ;
.import --skip 1 shelter_animals.csv animals_staging

    Тепер попереджень немає, і кожне значення стоїть у своїй колонці. У файлі з ; кома всередині значення (Сірко, старший) лапок не потребує, а от значення, що містить ;, треба було б узяти в лапки.

    .separator діє і на виведення результатів, доки ви не виконаєте .mode csv знову: ця команда повертає роздільник-кому. Про це варто пам'ятати перед експортом (розділ 9).

    3. Порожні поля: порожній рядок замість NULL¶

    Порожнє поле (;;) імпортується не як NULL, а як порожній рядок ''. Це видно функцією typeof():

    SELECT name, age, typeof(age) FROM animals_staging;

    name            age  typeof(age)
--------------  ---  -----------
Бублик          3    integer
Ліза                 text
Граф            5    integer
Сірко, старший       text
Бублик          3    integer

    Для бази '' і NULL є різними речами: COUNT(age) рахує порожній рядок як значення, а AVG(age) вважає його нулем. Запит SELECT COUNT(*), COUNT(age), AVG(age) FROM animals_staging; дає 5, 5 і 2.2 замість правильних 5, 3 і приблизно 3.67. Тому під час перенесення порожні рядки перетворюють на NULL функцією NULLIF: NULLIF(a, b) повертає NULL, якщо a = b, і a в іншому разі.

    INSERT INTO animals (name, species, age, status)
SELECT name, species, NULLIF(age, ''), status FROM animals_staging;

    Якщо ж колонка в цільовій таблиці оголошена як NOT NULL, така вставка завершиться помилкою NOT NULL constraint failed, і вся команда INSERT ... SELECT не додасть жодного рядка. Вигадувати значення в такому разі не можна: переносять лише повні рядки (WHERE колонка <> ''), а неповні відкладають і повідомляють власникові даних.

    Щоб не перевіряти колонки по одній, порожні значення в усіх колонках можна порахувати одним запитом (порівняння name = '' дає 1 або 0):

    SELECT SUM(name = '') AS name_empty, SUM(species = '') AS species_empty,
       SUM(age = '') AS age_empty, SUM(status = '') AS status_empty
FROM animals_staging;

    name_empty  species_empty  age_empty  status_empty
----------  -------------  ---------  ------------
0           0              2          0

    4. Дублікати¶

    SQLite не перевіряє, чи такий рядок уже був: однакові записи файлу перетворяться на однакові рядки таблиці, кожен зі своїм id. Шукати їх зручно в проміжній таблиці, групуючи за всіма колонками (Практика 10):

    SELECT name, species, age, status, COUNT(*) AS cnt
FROM animals_staging
GROUP BY name, species, age, status
HAVING COUNT(*) > 1;

    name    species  age  status     cnt
------  -------  ---  ---------  ---
Бублик  собака   3    на обліку  2

    Повністю однакові рядки прибирає SELECT DISTINCT під час перенесення. Друге джерело дублікатів: той самий файл імпортують повторно. Рядки проміжної таблиці, які вже є в цільовій, знаходить EXISTS: умова EXISTS (підзапит) істинна, якщо вкладений SELECT повернув хоча б один рядок. Тут для кожного рядка проміжної таблиці s підзапит шукає в animals тварину з тим самим іменем і видом:

    SELECT s.name
FROM animals_staging s
WHERE EXISTS (SELECT 1 FROM animals a
              WHERE a.name = s.name AND a.species = s.species);

    5. Заголовок і типи колонок¶

    Забутий --skip 1 під час імпорту в наявну таблицю перетворює заголовок на звичайний рядок даних (теорія Практики 16). Інша ситуація: таблиці ще немає. Тоді .import створює її сам, бере назви колонок з першого рядка файлу й усім колонкам дає тип TEXT:

    .mode csv
.separator ;
.import shelter_animals.csv fresh
.schema fresh

    CREATE TABLE IF NOT EXISTS "fresh"(
"name" TEXT, "species" TEXT, "age" TEXT, "status" TEXT);

    Числа в такій таблиці зберігаються як текст, і ORDER BY age сортує їх посимвольно ('10' опиниться перед '5'). Якщо ж до неіснуючої таблиці додати --skip 1, пропущеним виявиться заголовок, і назвами колонок стане перший запис ("Бублик" TEXT, "собака" TEXT, ...), а сам Бублик у дані не потрапить. Тому проміжну таблицю створюйте самі, з потрібними типами, і тоді використовуйте --skip 1.

    6. Кодування¶

    SQLite очікує файл у кодуванні UTF-8. Файл, збережений у старому кодуванні Windows-1251, після імпорту перетворює кирилицю на нечитабельні знаки. У Excel обирайте тип файлу CSV UTF-8, а в текстовому редакторі перевіряйте кодування перед імпортом. Невидиму позначку на початку UTF-8 файлу (BOM), яку додає Excel, CLI sqlite3 розпізнає й пропускає сам.

    7. Контрольний список перевірки¶

    Перед перенесенням у цільову таблицю перевірте проміжну:

    1. COUNT(*) проміжної таблиці дорівнює кількості записів у файлі (а не кількості рядків тексту: значення в лапках може містити переведення рядка).
    2. Значення стоять у своїх колонках (SELECT * ... LIMIT 5).
    3. Порожні рядки: запит із SUM(колонка = '') з розділу 3.
    4. Типи: typeof(колонка) з групуванням для числових колонок.
    5. Дублікати: GROUP BY за всіма колонками з HAVING COUNT(*) > 1.

    Після перенесення приріст COUNT(*) цільової таблиці має дорівнювати кількості рядків, які ви вирішили перенести (без дублікатів і відкладених рядків), а WHERE колонка IS NULL має знайти саме ті рядки, де в файлі було порожнє поле.

    8. Імпорт через DB Browser for SQLite¶

    Майстер File → Import → Table from CSV file... робить те саме, що .import, але з налаштуваннями у вікні:

    • Table name: назва нової таблиці, наприклад animals_staging;
    • Column names in first line: позначка означає, що перший рядок є заголовком (аналог --skip 1 з назвами колонок із файлу);
    • Field separator: роздільник; для файлу з Excel оберіть ;;
    • Quote character: символ лапок, зазвичай ";
    • Encoding: кодування, для українських даних UTF-8.

    Залежно від версії DB Browser майстер може записувати порожні поля як NULL, а не як порожній рядок ''. Тоді в перевірках розділу 3 замість колонка = '' шукайте колонка IS NULL, а NULLIF у перенесенні лишається безпечним.

    Унизу вікна є попередній перегляд: якщо всі значення злилися в одну колонку, роздільник обрано неправильно. Майстер створює нову таблицю, тому далі, як і в Практиці 16, перевірки й INSERT ... SELECT виконуються у вкладці Execute SQL.

    9. Експорт: із таблиці назад у CSV¶

    Ті самі дот-команди працюють і у зворотний бік:

    .headers on
.mode csv
.output animals_export.csv
SELECT id, name, species, age FROM animals WHERE id > 3;
.output stdout

    .headers on додає рядок заголовків, .mode csv задає формат і роздільник-кому, .output файл перенаправляє результат запитів у файл замість екрана, а .output stdout повертає виведення на екран (без неї результати всіх наступних запитів теж підуть у файл). У файл потрапляє результат будь-якого SELECT: таблиця цілком, відфільтрована вибірка чи підсумковий звіт. Вміст файлу:

    id,name,species,age
4,"Бублик","собака",3
5,"Ліза","кіт",
6,"Граф","собака",5
7,"Сірко, старший","собака",

    Значення з комою ("Сірко, старший") SQLite бере в лапки автоматично, а NULL записується як порожнє поле. Тобто якщо цей файл імпортувати знову, NULL повернеться порожнім рядком, і NULLIF знадобиться ще раз. У DB Browser експорт виконує File → Export → Table(s) as CSV file....

    Варіант¶

    Той самий варіант і той самий файл .db, що в Практиці 16, і та сама цільова таблиця (для варіанта 9 це courses). Для кожного варіанта підготовлено файл v{N}_raw_rows.csv: вивантаження з Excel партнера, 10 записів для цільової таблиці, без колонки id. У файлі навмисно закладено три типові проблеми з теорії вище; знайти, описати й виправити їх є частиною завдання. Кожен запис файлу описує окремий новий об'єкт, тож однакових записів у правильному файлі бути не повинно. Виняток лише варіант 6: там вважайте, що партнер вивантажив один і той самий номер двічі.

    • v1_raw_rows.csv: Бібліотека (books)
    • v2_raw_rows.csv: Інтернет-магазин одягу (products)
    • v3_raw_rows.csv: Кінотеатр (movies)
    • v4_raw_rows.csv: Аптека (medicines)
    • v5_raw_rows.csv: Автосалон (cars)
    • v6_raw_rows.csv: Готель (rooms)
    • v7_raw_rows.csv: Спортзал (memberships)
    • v8_raw_rows.csv: Служба доставки їжі (dishes)
    • v9_raw_rows.csv: Університет (courses)
    • v10_raw_rows.csv: Транспортна компанія (drivers)

    Якщо базу втрачено, відновіть її з v{N}_prerequisites.sql Практики 4 (повторно виконавши завдання тієї практики); імпорт Практики 16 для цієї практики не обов'язковий.

    Приклад: наскрізна демонстрація¶

    Повний правильний імпорт файлу shelter_animals.csv з теорії (до імпорту в animals 3 тварини, найбільший id дорівнює 3):

    CREATE TABLE animals_staging (
    name TEXT, species TEXT, age INTEGER, status TEXT
);

    .mode csv
.separator ;
.import --skip 1 shelter_animals.csv animals_staging

    SELECT COUNT(*) FROM animals_staging;                      -- 5 записів
SELECT COUNT(*) FROM (SELECT DISTINCT * FROM animals_staging);  -- 4 унікальні

INSERT INTO animals (name, species, age, status)
SELECT DISTINCT name, species, NULLIF(age, ''), status
FROM animals_staging;

SELECT COUNT(*) FROM animals;                     -- 7: приріст 4
SELECT COUNT(*) FROM animals WHERE age IS NULL;   -- 2: Ліза і Сірко
DROP TABLE animals_staging;

    .headers on
.mode csv
.output animals_export.csv
SELECT id, name, species, age FROM animals WHERE id > 3;
.output stdout

    Завдання¶

    Завдання 1. Огляд файлу й "наївний" імпорт. Відкрийте v{N}_raw_rows.csv свого варіанта в текстовому редакторі (не в Excel: він приховує роздільники) і порахуйте записи. Створіть проміжну таблицю з колонками, що відповідають заголовкам файлу (лише назви й типи колонок, як у цільовій таблиці, без NOT NULL, DEFAULT і PRIMARY KEY), й імпортуйте файл у неї звичайними .mode csv і .import --skip 1, без жодних додаткових налаштувань. Зафіксуйте письмово перші три попередження CLI дослівно, значення COUNT(*) проміжної таблиці і значення першої колонки в першому рядку проміжної таблиці (SELECT * FROM ... LIMIT 1). Поясніть причину й очистіть проміжну таблицю (DELETE FROM ...).

    Завдання 2. Правильний імпорт. Повторіть імпорт з потрібним роздільником: у CLI через .separator, або майстром DB Browser for SQLite в нову проміжну таблицю (тоді зафіксуйте, які налаштування майстра ви змінили). Переконайтеся, що попереджень немає, а COUNT(*) проміжної таблиці дорівнює кількості записів у файлі.

    Завдання 3. Контроль якості в проміжній таблиці. Виконайте перевірки з контрольного списку (розділ 7 теорії): порожні рядки в кожній колонці, typeof() для числових колонок, пошук дублікатів через GROUP BY за всіма колонками з HAVING COUNT(*) > 1. Письмово опишіть кожну знайдену проблему (які рядки, які колонки) і обчисліть, скільки рядків має додатися до цільової таблиці після виправлення. Колонки з NOT NULL визначте командою .schema цільова_таблиця: рядки з порожнім значенням у таких колонках відкладаються й до розрахунку не входять.

    Завдання 4. Перенесення з виправленням. Зафіксуйте COUNT(*) і MAX(id) цільової таблиці. Перенесіть рядки одним INSERT ... SELECT, який прибирає дублікати й перетворює порожні рядки на NULL. Якщо вставка падає з NOT NULL constraint failed (колонка у вашій таблиці не допускає NULL), не вигадуйте значень: перенесіть лише повні рядки й письмово зазначте, які рядки відкладено і чому. Підтвердьте, що приріст COUNT(*) збігається з розрахунком із Завдання 3, а запит з IS NULL знаходить саме ті рядки, що мали порожні поля. Видаліть проміжну таблицю.

    Завдання 5. Експорт у CSV. Вивантажте в CSV-файл із рядком заголовків усі рядки, додані в Завданні 4 (WHERE id > ... зі значенням MAX(id) до перенесення), через .headers on, .mode csv, .output і .output stdout (або File → Export у DB Browser). Відкрийте файл у текстовому редакторі й письмово зазначте: який у ньому роздільник, як записано значення, що містить кому, і як записано NULL. Поясніть, що сталося б із цими NULL, якби файл імпортували назад.

    Що здати й оцінюється¶

    Здайте lab_work_17.sql (усі виконані команди Завдань 1-5, включно з дот-командами, з результатами перевірок), lab_work_17.db (файл бази даних після перенесення) і lab_work_17.md (письмові відповіді до Завдань 1, 3, 4 і 5, разом із вмістом експортованого CSV-файлу). Контрольні питання:

    • Чому імпорт файлу з крапкою з комою в режимі .mode csv формально "проходить", але дає неправильний результат, і як це помітити?
    • Чому порожнє поле CSV треба перетворювати на NULL і чим загрожує порожній рядок у числовій колонці для агрегатних функцій?
    • Чому дублікати й порожні значення краще знаходити в проміжній таблиці, а не вже в цільовій?

    Оцінюється повнота опису трьох проблем файлу (Завдання 1 і 3), правильність перенесення: без дублікатів, з NULL замість порожніх рядків і з приростом, що збігається з розрахунком (Завдання 4), і правильний експорт із поясненням (Завдання 5).

    Підсумок заняття¶

    • Розпізнано на власному файлі типові проблеми CSV: роздільник ;, порожні поля, що імпортуються як '', і повторені записи.
    • Перевірено якість даних у проміжній таблиці (typeof, порожні рядки, GROUP BY ... HAVING) до перенесення в цільову таблицю.
    • Рядки перенесено з SELECT DISTINCT і NULLIF, а результат підтверджено приростом COUNT(*) і запитом з IS NULL.
    • Результат запиту вивантажено назад у CSV через .headers on, .mode csv і .output.

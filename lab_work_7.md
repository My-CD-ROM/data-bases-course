# Практична робота №7
## Запити з різними видами об'єднання таблиць у SQLite

**Предметна область:** Кінотеатр

### Завдання 1

Використано `INNER JOIN`, щоб об'єднати таблицю `sessions` з таблицею `movies` за зовнішнім ключем `movie_id`.

Запит показує назву фільму, дату та час сеансу замість числового `movie_id`.

```sql
SELECT movies.title AS фільм, sessions.session_date AS дата, sessions.session_time AS час
FROM sessions
INNER JOIN movies ON sessions.movie_id = movies.id
ORDER BY sessions.session_date, sessions.session_time;
```

Результат містить 4 сеанси.

### Завдання 2

До попереднього запиту додано ще один `INNER JOIN` для таблиці `halls`.

```sql
SELECT movies.title AS фільм, halls.hall_number AS зал,
       sessions.session_date AS дата, sessions.session_time AS час
FROM sessions
INNER JOIN movies ON sessions.movie_id = movies.id
INNER JOIN halls ON sessions.hall_id = halls.id
ORDER BY sessions.session_date, sessions.session_time;
```

У результаті один рядок показує назву фільму, номер залу, дату та час.

### Завдання 3

Потрібно було знайти фільми, для яких немає жодного сеансу.

Для цього використано `LEFT JOIN` та перевірку `IS NULL`.

```sql
SELECT movies.title AS фільм
FROM movies
LEFT JOIN sessions ON sessions.movie_id = movies.id
WHERE sessions.id IS NULL
ORDER BY movies.title;
```

Результат:

```text
Матриця
Шрек
```

Ці фільми є в таблиці `movies`, але не мають пов'язаного запису в `sessions`.

### Завдання 4

Кількість фільмів:

```text
5
```

Кількість залів:

```text
3
```

Запит:

```sql
SELECT COUNT(*)
FROM movies, halls;
```

Результат:

```text
15
```

Результат дорівнює `5 * 3 = 15`, тому що кома між таблицями без умови з'єднання створює декартів добуток.

Кожен фільм поєднується з кожним залом.

У реальному звіті такий запит майже завжди є помилкою, тому що він створює багато штучних комбінацій, які не обов'язково відповідають реальним зв'язкам у базі даних.

### Завдання 5

У Завданні 1 використано `INNER JOIN`, тому що потрібно отримати тільки сеанси, для яких існує відповідний фільм.

У Завданні 2 використано `INNER JOIN`, тому що потрібно отримати тільки записи, у яких існують відповідні фільм і зал.

У Завданні 3 використано `LEFT JOIN`, тому що потрібно зберегти всі фільми та знайти серед них ті, для яких немає відповідного сеансу.

## Контрольні питання

### 1. Чому рядок з NULL у зовнішньому ключі не з'явиться в INNER JOIN?

`INNER JOIN` потребує відповідності між ключами. `NULL` не є конкретним значенням, тому для нього не знаходиться відповідний запис. У `LEFT JOIN` рядок лівої таблиці все одно зберігається.

### 2. Що станеться, якщо один JOIN у Завданні 2 замінити на LEFT JOIN?

Тоді можуть залишитися записи з лівої таблиці навіть без відповідного запису у приєднаній таблиці. Але наступний `INNER JOIN` може знову виключити рядки без відповідності.

### 3. Чим відрізняється кома-синтаксис від JOIN ... ON?

Наприклад:

```sql
FROM movies, sessions
WHERE movies.id = sessions.movie_id
```

та

```sql
FROM movies
JOIN sessions ON movies.id = sessions.movie_id
```

можуть дати однаковий результат, якщо умова правильна. Варіант із `JOIN ... ON` є зрозумілішим і безпечнішим, тому що умова зв'язку знаходиться безпосередньо біля JOIN. У кома-синтаксисі легко забути `WHERE` і випадково отримати декартів добуток.

## Висновок

У практичній роботі було виконано об'єднання таблиць кінотеатру за допомогою `INNER JOIN` та `LEFT JOIN`. Було отримано звіти з реальними назвами фільмів та номерами залів замість ідентифікаторів. За допомогою `LEFT JOIN` знайдено фільми без сеансів. Також було перевірено роботу декартового добутку та встановлено, чому відсутність умови з'єднання може призвести до неправильного результату.

    Лекція 11. Запити форматування таблиць¶

    Дані в таблиці зберігаються в "сирому" вигляді: вартість візиту 420.5, дата '2026-03-03'. Звіт же потребує людяного вигляду: 420.50 грн, 03.03.2026, заголовок колонки «Дата візиту». SQLite надає функції прямо всередині SELECT, що форматують значення "на виході" — без зміни того, що фізично зберігається в таблиці.

    Дані для прикладів¶

    Усі приклади лекції — на базі ветеринарної клініки з попередніх лекцій. До таблиці visits додано колонку cost — вартість візиту в гривнях (REAL). Ось шість візитів, на яких рахуються всі результати лекції:

    visit_date | тварина | діагноз        | cost
2025-11-28 | Мурчик  | плановий огляд | 350
2025-12-15 | Рекс    | вакцинація     | 420.5
2026-01-31 | Мурчик  | стерилізація   | 1850
2026-02-10 | Рекс    | плановий огляд | 350
2026-02-24 | Кіко    | огляд дзьоба   | 280.5
2026-03-03 | Рекс    | вакцинація     | 420.5

    Папуга Кіко (Лекція 10) має вік NULL, а власниця Олена Ковальчук — телефон NULL; обидва NULL знадобляться далі. Щоб відтворити кожен результат нижче, виконайте цей скрипт на порожній базі:

    PRAGMA foreign_keys = ON;

CREATE TABLE owners (
    id INTEGER PRIMARY KEY,
    last_name TEXT NOT NULL,
    first_name TEXT NOT NULL,
    phone TEXT
);

CREATE TABLE animals (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    species TEXT,
    age INTEGER,
    owner_id INTEGER NOT NULL REFERENCES owners (id)
);

CREATE TABLE vets (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    specialization TEXT
);

CREATE TABLE visits (
    id INTEGER PRIMARY KEY,
    animal_id INTEGER NOT NULL REFERENCES animals (id),
    vet_id INTEGER NOT NULL REFERENCES vets (id),
    visit_date TEXT NOT NULL,
    diagnosis TEXT,
    cost REAL
);

INSERT INTO owners (last_name, first_name, phone) VALUES
    ('Мельник', 'Ганна', '0671234567'),
    ('Бондар', 'Ігор', '0501234567'),
    ('Ковальчук', 'Олена', NULL);

INSERT INTO animals (name, species, age, owner_id) VALUES
    ('Мурчик', 'кіт', 3, 1),
    ('Рекс', 'пес', 5, 2),
    ('Кіко', 'папуга', NULL, 1);

INSERT INTO vets (name, specialization) VALUES
    ('Савчук Олег', 'терапія'),
    ('Литвин Марія', 'хірургія');

INSERT INTO visits (animal_id, vet_id, visit_date, diagnosis, cost) VALUES
    (1, 1, '2025-11-28', 'плановий огляд', 350),
    (2, 1, '2025-12-15', 'вакцинація', 420.5),
    (1, 2, '2026-01-31', 'стерилізація', 1850),
    (2, 1, '2026-02-10', 'плановий огляд', 350),
    (3, 1, '2026-02-24', 'огляд дзьоба', 280.5),
    (2, 1, '2026-03-03', 'вакцинація', 420.5);

    1. printf() — форматування чисел і рядків¶

    SELECT visit_date, cost, printf('%.2f грн', cost) AS formatted
FROM visits;

    visit_date | cost   | formatted
2025-11-28 | 350.0  | 350.00 грн
2025-12-15 | 420.5  | 420.50 грн
2026-01-31 | 1850.0 | 1850.00 грн
...

    printf(шаблон, значення, ...) (читається «прінт-еф», від print formatted) підставляє значення в специфікатори шаблону: %d — ціле число, %.2f — дробове рівно з двома знаками після крапки (f — від float, число з рухомою комою, той самий REAL), %s — рядок. Решта шаблону (грн) виводиться без змін. %.2f не обрізає, а округлює:

    SELECT printf('%.2f грн', AVG(cost)) AS avg_cost FROM visits;
-- AVG(cost) = 611.9166666666666  ->  '611.92 грн'

SELECT printf('%s, %d р.', name, age) FROM animals;
-- 'Мурчик, 3 р.'

    Кілька специфікаторів заповнюються по черзі, зліва направо. У SQLite 3.38 і новіших та сама функція доступна ще й як format() — повний синонім; у старіших версіях є лише printf(). Версію SQLite показує запит SELECT sqlite_version();.

    2. printf() — ширина поля, нулі й вирівнювання¶

    SELECT printf('%03d', 7);           -- '007'
SELECT printf('[%8.2f]', 1850);     -- '[ 1850.00]'
SELECT printf('[%8.2f]', 350);      -- '[  350.00]'
SELECT printf('[%-8s]', 'Rex');     -- '[Rex     ]'

    Ціле число одразу після %, до крапки, — мінімальна ширина результату: у %8.2f ширина 8, а .2 — два знаки після крапки. '1850.00' має сім символів, тож зліва додається один пробіл, а '350.00' — шість, тож пробілів два (квадратні дужки в прикладах — звичайний текст, щоб було видно пробіли). Без знака значення притискається до правого краю, 0 перед шириною заповнює нулями, - — притискає до лівого краю. Довше значення не обрізається: printf('%05d', 100000) → '100000'. Вирівнювання пробілами має сенс для текстового виводу (консоль sqlite3, текстовий файл), де немає таблиці з лініями.

    3. Пастки printf(): NULL і кирилиця¶

    SELECT printf('%s, %d р.', name, age) FROM animals;
-- 'Кіко, 0 р.'   <- age = NULL!

SELECT printf('[%-8s]', 'Рекс');    -- '[Рекс]'
SELECT printf('[%!-8s]', 'Рекс');   -- '[Рекс    ]'
    • NULL стає нулем. %d і %.2f показують NULL як 0, а %s — як порожній рядок, без жодної помилки: звіт "каже", що папузі Кіко 0 років, хоча його вік невідомий (як це виправити — у розділі 11).
    • Кирилиця і ширина поля. Ширину для %s printf() рахує в байтах, а українська літера в кодуванні UTF-8 займає 2 байти: 'Рекс' — 4 символи, але 8 байтів, тож %-8s не додає жодного пробілу. Прапорець ! (%!-8s) змушує рахувати ширину в символах.

    4. Число чи текст: printf() і round(); ділення цілих¶

    SELECT printf('%.2f', AVG(cost)), round(AVG(cost), 2) FROM visits;
-- '611.92' (текст)     611.92 (число)

SELECT COUNT(*) / 5, COUNT(*) / 5.0 FROM visits;
-- 1     1.2

    round(x, n) округлює, але результат лишається числом — з ним можна рахувати й правильно сортувати. printf() повертає текст лише для показу, тож форматуємо в самому кінці. Ділення двох цілих чисел у SQLite — цілочисельне (6 / 5 = 1, дробова частина відкидається без помилки); щоб отримати 1.2, зробіть дробовим хоча б одне число (5.0).

    5. Функції дати: date(), datetime(), поточний момент¶

    SELECT date('now');       -- наприклад, '2026-10-05'
SELECT datetime('now');   -- наприклад, '2026-10-05 17:28:35'

    SQLite зберігає дати як звичайний текст у форматі ISO 8601 ('РРРР-ММ-ДД', Лекція 2), але має вбудовані функції, що розуміють цей формат. date('now') і datetime('now') повертають поточний момент — за UTC, тому результат щоразу інший і відстає від київського часу на 2-3 години; місцевий час дає datetime('now', 'localtime'). Зручно для DEFAULT-значень (Лекція 6) — DEFAULT (datetime('now')), саме в дужках: виклик функції як значення за замовчуванням без дужок дає near "(": syntax error — і порівнянь на кшталт visit_date > date('now') — візити, заплановані на майбутнє.

    6. Арифметика з датами через модифікатори¶

    SELECT visit_date, date(visit_date, '+30 days') AS checkup_date
FROM visits;

    visit_date | checkup_date
2025-11-28 | 2025-12-28
2026-02-10 | 2026-03-12
...

    Другий аргумент date()/datetime() — рядок-модифікатор ('+30 days', '-1 month', '+1 year' тощо), що зсуває дату. Запис без знака ('30 days') SQLite вважає зсувом уперед.

    Обережно з '+1 month' наприкінці місяця. SQLite змінює номер місяця, а неіснуючі дні переносить у наступний місяць:

    SELECT date('2026-01-31', '+1 month');                            -- '2026-03-03'
SELECT date('2026-01-31', 'start of month', '+2 months', '-1 day'); -- '2026-02-28'

    Перший запит дає не кінець лютого, а 3 березня: у лютому 2026-го 28 днів, тож три "зайві" дні (29-те, 30-те, 31-ше) переносяться в березень. Якщо потрібен останній день наступного місяця — модифікатори поспіль, зліва направо: на перше число, +2 місяці, −1 день.

    7. Скільки днів між датами: julianday()¶

    SELECT julianday('2026-03-03') - julianday('2025-12-15');                 -- 78.0
SELECT CAST(julianday('2026-03-03') - julianday('2025-12-15') AS INTEGER); -- 78

    julianday() («джуліан-дей») перетворює дату на число днів від умовної точки відліку; різниця двох таких чисел — кількість днів між датами (тут — між двома вакцинаціями Рекса). Результат дробовий, бо враховує й час доби (між '2026-03-01 09:00' і '2026-03-03 18:00' — 2.375 дня); навіть для дат без часу результат має тип дробового числа (78.0), а CAST(... AS INTEGER) лишає цілі дні. Віднімати дати як текст не можна: '2026-03-03' - '2025-12-15' дає 1 — SQLite бере лише число на початку кожного рядка (рік).

    8. strftime() — витягти частину дати¶

    SELECT visit_date,
       strftime('%Y', visit_date) AS year,
       strftime('%m', visit_date) AS month,
       strftime('%d.%m.%Y', visit_date) AS ua_date
FROM visits;

    visit_date | year | month | ua_date
2025-11-28 | 2025 | 11    | 28.11.2025
2026-03-03 | 2026 | 03    | 03.03.2026
...

    strftime(шаблон, дата) («стрф-тайм», від string format time): %Y — рік, %m — місяць, %d — день, %w — день тижня (0 = неділя, не понеділок: strftime('%w', '2026-03-03') → '2', вівторок). Решта символів шаблону переноситься як є. Результат — завжди текст: умова strftime('%m', visit_date) = 3 не знайде жодного рядка; порівнюйте з '03' або з CAST(strftime('%m', visit_date) AS INTEGER) = 3.

    9. strftime() і GROUP BY: звіт за місяцями¶

    SELECT strftime('%Y-%m', visit_date) AS year_month,
       COUNT(*) AS visits_count
FROM visits
GROUP BY year_month;

    year_month | visits_count
2025-11    | 1
2025-12    | 1
2026-01    | 1
2026-02    | 2
2026-03    | 1

    Це звичайний GROUP BY (Лекція 9), але за результатом strftime(). GROUP BY visit_date дав би окрему групу на кожен день (на наших даних — шість груп по одному візиту), а шаблон '%m' без року злив би березень 2026-го й березень 2027-го в одну групу. Для річного звіту — шаблон '%Y' (2 візити за 2025 рік, 4 — за 2026 рік).

    10. Некоректна дата — мовчазний NULL, а не помилка¶

    SELECT strftime('%Y', '15.03.2026');   -- NULL
SELECT date('2026-3-5');               -- NULL (бракує нулів)
SELECT date('2026-02-30');             -- '2026-03-02'

    Текст не у форматі РРРР-ММ-ДД функції дати мовчки перетворюють на NULL — без помилки; у звіті за місяцями такий рядок потрапить у групу NULL. А неіснуючий день місяця (01-31) непомітно переноситься в наступний місяць. Отже, функції дати не перевіряють дані — це робить CHECK на вході (Лекція 6):

    visit_date TEXT NOT NULL
    CHECK (date(visit_date) IS NOT NULL AND date(visit_date) = visit_date)

    Обидві половини потрібні: date('15.03.2026') дає NULL, порівняння з NULL теж дає NULL (Лекція 3), а умова, що дала NULL, не порушує CHECK (Лекція 10) — тож без IS NOT NULL рядок '15.03.2026' пройшов би (перевірено: таке обмеження відхиляє '15.03.2026', '2026-3-5' і '2026-02-30').

    11. Склеювання рядків, NULL і coalesce()¶

    SELECT last_name || ' ' || first_name || ', тел. ' || phone AS contact
FROM owners;
-- 'Мельник Ганна, тел. 0671234567'
-- NULL      <- у Ковальчук телефон не вказано

SELECT last_name || ' ' || first_name || ', тел. '
       || coalesce(phone, 'не вказано') AS contact
FROM owners;
-- 'Ковальчук Олена, тел. не вказано'

    Оператор || склеює рядки (конкатенація). Як і порівняння з NULL (Лекція 3), будь-яка операція з NULL — NULL + 100, склеювання — дає NULL, тож один порожній телефон "з'їдає" весь рядок, навіть прізвище. coalesce(x, y, ...) («коа-лесс») повертає перше значення, яке не NULL (у SQLite є й ifnull(x, y) для двох значень). Так само виправляється Кіко: підпис ' р.' приклеюємо до віку через || (для NULL увесь шматок стане NULL), а coalesce() підставляє текст:

    SELECT printf('%s, %s', name, coalesce(age || ' р.', 'вік невідомий'))
FROM animals;
-- 'Мурчик, 3 р.'   'Кіко, вік невідомий'

    Специфікатор тут %s, бо підставляється вже текст.

    12. Заголовки колонок: псевдоніми AS¶

    SELECT strftime('%d.%m.%Y', visit_date) AS "Дата візиту",
       printf('%.2f грн', cost) AS "Вартість"
FROM visits
ORDER BY visit_date;

    Дата візиту | Вартість
28.11.2025  | 350.00 грн
15.12.2025  | 420.50 грн
31.01.2026  | 1850.00 грн
10.02.2026  | 350.00 грн
24.02.2026  | 280.50 грн
03.03.2026  | 420.50 грн

    Псевдонім після AS (Лекція 3) стає заголовком колонки; з пробілом чи комою — у подвійних лапках (у "Вартість" пробілу немає, лапки там лише для однаковості). Одинарні лапки в SQL — для текстових значень, подвійні — для назв колонок і таблиць. Сортуйте за сирою колонкою: ORDER BY "Дата візиту" сортував би текст ДД.ММ.РРРР посимвольно ('03.03.2026' раніше за '10.02.2026'), а сортування за printf('%.2f грн', cost) поставило б '1850.00 грн' перед '280.50 грн'.

    Підсумок¶

    • printf(шаблон, ...): %d ціле, %.2f два знаки з округленням, %s рядок; число одразу після % — мінімальна ширина, 0 — нулі, - — вирівнювання ліворуч, ! — ширина в символах для кирилиці.
    • printf() повертає текст; NULL у %d і %.2f показує як 0, у %s — як порожній рядок; round() лишає число; ціле / ціле — ціле.
    • date('now')/datetime('now') — поточна дата/час за UTC; модифікатори ('+30 days', '+1 month', 'start of month') зсувають дату; різниця julianday() — кількість днів між датами.
    • strftime(шаблон, дата) витягує частину дати як текст і записує дату в будь-якому вигляді; '%Y-%m' — основа GROUP BY за місяцями.
    • Некоректна дата дає мовчазний NULL або непомітний зсув — форматування не замінює перевірку даних на вході (CHECK).
    • || склеює рядки, NULL "з'їдає" весь рядок — coalesce(); AS "..." дає заголовки; сортуємо за сирими колонками.

    Лекція 16. Імпорт даних: CSV → SQLite¶

    Досі кожен рядок таблиці потрапляв у базу через власноруч написаний INSERT. Але на практиці дані частіше приходять готовим файлом — вивантаженням з Excel, вебсервісу чи іншої системи — у форматі CSV ("comma-separated values", значення через кому). Переписувати сотні рядків такого файлу в INSERT вручну — не варіант. SQLite вміє завантажити CSV напряму, але тут є пастка, пов'язана з першинним ключем id, яку ця лекція розбирає детально.

    1. CSV — простий текстовий формат таблиці¶

    title,author,publication_year,genre,copies_count
Проза,Автор Х,2000,роман,2
Друга книга,Автор Y,2001,повість,1

    Перший рядок CSV-файлу — заголовки колонок, кожен наступний рядок — одне значення таблиці, розділене комами. Це найпоширеніший формат обміну табличними даними між зовсім різними програмами (Excel, Google Таблиці, експорт з будь-якої СУБД).

    2. Базовий імпорт: .mode csv і .import (CLI)¶

    .mode csv
.import --skip 1 new_books.csv books_staging

    У CLI sqlite3 дот-команда .mode csv перемикає режим введення на CSV, а .import файл.csv таблиця завантажує кожен рядок файлу як рядок вказаної таблиці. Прапорець --skip 1 пропускає перший рядок (заголовки), щоб він не потрапив у таблицю як звичайні дані.

    3. Пастка: CSV без id, а в таблиці id є¶

    Пряма спроба .import new_books.csv books (де books — вже наявна таблиця-вимір з колонкою id INTEGER PRIMARY KEY) майже завжди йде не так: CSV має 5 колонок (title, author, publication_year, genre, copies_count), а таблиця books — 6 (додається id). Кількість колонок CSV повинна точно відповідати кількості колонок цільової таблиці — інакше .import або відмовляється працювати, або (що гірше) розставляє значення по колонках неправильно.

    4. Рішення: проміжна (staging) таблиця¶

    -- 1. Проміжна таблиця з РІВНО тими колонками, що в CSV (без id)
CREATE TABLE books_staging (
    title TEXT,
    author TEXT,
    publication_year INTEGER,
    genre TEXT,
    copies_count INTEGER
);

    -- 2. Імпорт CSV саме в неї — кількість колонок збігається
.mode csv
.import --skip 1 new_books.csv books_staging

    -- 3. Перенесення в реальну таблицю: id SQLite призначає сам
INSERT INTO books (title, author, publication_year, genre, copies_count)
SELECT title, author, publication_year, genre, copies_count
FROM books_staging;

-- 4. Проміжна таблиця більше не потрібна
DROP TABLE books_staging;

    Перевірено виконанням: після INSERT ... SELECT нові рядки отримують свої id, що природно продовжують нумерацію вже наявних рядків таблиці (наприклад, якщо в books уже було 2 рядки з id = 1, 2, нові рядки з books_staging отримують id = 3, 4, — SQLite сам призначає значення для INTEGER PRIMARY KEY, коли колонку не вказано в INSERT). Сама проміжна таблиця (books_staging) — тимчасовий "контейнер" лише для перенесення даних; DROP TABLE після переносу прибирає її, не торкаючись основної таблиці й уже перенесених даних.

    5. Той самий принцип у DB Browser for SQLite¶

    DB Browser for SQLite має власний майстер імпорту (File → Import → Table from CSV), який теж створює нову таблицю безпосередньо з колонок CSV-файлу. Якщо потрібно додати рядки в УЖЕ наявну таблицю з колонкою id, принцип той самий: спершу імпортувати CSV як нову (проміжну) таблицю через майстер, а потім виконати той самий INSERT ... SELECT у вкладці Execute SQL, як і в CLI.

    6. Перевірка результату¶

    SELECT COUNT(*) FROM books;

    Найпростіший спосіб підтвердити, що імпорт спрацював, — порівняти кількість рядків (COUNT(*), Лекція 8) ДО і ПІСЛЯ імпорту: різниця має дорівнювати кількості рядків у CSV-файлі (без рядка заголовків).

    Підсумок¶

    • CSV — текстовий формат таблиці: перший рядок — заголовки колонок, далі — значення через кому, один рядок файлу = один рядок таблиці.
    • .mode csv + .import --skip 1 файл.csv таблиця — базовий імпорт у CLI sqlite3; кількість колонок CSV має точно відповідати кількості колонок цільової таблиці.
    • Якщо цільова таблиця має колонку id INTEGER PRIMARY KEY, якої в CSV немає, — пряме .import в неї не спрацює: розв'язок — імпорт у проміжну таблицю з колонками CSV, а потім INSERT ... SELECT у реальну таблицю (SQLite сам призначить нові id), і DROP TABLE проміжної.
    • COUNT(*) до й після імпорту — простий спосіб підтвердити, що всі рядки файлу дійсно потрапили в таблицю.

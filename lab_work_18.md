# Практична робота №18

**Тема:** Згенеровані стовпці у SQLite  
**Варіант:** 3 — Кінотеатр

## Мета роботи

Навчитися створювати згенеровані стовпці у SQLite, використовувати тип `VIRTUAL`, перевірити автоматичне обчислення значень, заборону їх ручного редагування та застосування згенерованих стовпців у фільтрації.

## Підготовка бази даних

Для виконання роботи створено файл `lab_work_18.db` копіюванням бази `lab_work_17.db`. Таблиці `movies`, `viewers` і `tickets` збережено. Перед внесенням змін перевірено структуру таблиць.

У таблиці `tickets` є числовий стовпець `price`, а в таблиці `movies` — текстовий стовпець `genre`. Вони підходять для створення двох згенерованих стовпців.

## Хід роботи

### 1. Створення згенерованого числового стовпця

У таблиці `tickets` створено стовпець `price_with_vat`, який обчислює вартість квитка з урахуванням ПДВ 20%.

```sql
ALTER TABLE tickets
ADD COLUMN price_with_vat REAL
GENERATED ALWAYS AS (price * 1.2) VIRTUAL;
```

Перевірка:

```sql
SELECT id, price, price_with_vat
FROM tickets;
```

Отримані результати:

| ID квитка | Ціна без ПДВ | Ціна з ПДВ |
|---:|---:|---:|
| 1 | 180.0 | 216.0 |
| 2 | 200.0 | 240.0 |
| 3 | 170.0 | 204.0 |
| 4 | 150.0 | 180.0 |
| 5 | 190.0 | 228.0 |
| 6 | 210.0 | 252.0 |
| 8 | 155.0 | 186.0 |

Значення `price_with_vat` обчислюється автоматично за формулою `price * 1.2`.

### 2. Створення згенерованого логічного стовпця

У таблиці `movies` створено стовпець `is_drama`. Він перевіряє, чи дорівнює значення `genre` слову `драма`.

```sql
ALTER TABLE movies
ADD COLUMN is_drama INTEGER
GENERATED ALWAYS AS (genre = 'драма') VIRTUAL;
```

Перевірка:

```sql
SELECT id, title, genre, is_drama
FROM movies;
```

Результат показав, що для фільмів із жанром `драма` значення `is_drama` дорівнює `1`, а для інших жанрів — `0`. Наприклад, для фільмів «Заборонений», «Додому» та «Стоп-Земля» отримано `1`, а для «Interstellar», «Titanic» і «Довбуш» — `0`.

У цій таблиці стовпець `genre` має обмеження `NOT NULL`, тому в наявних даних логічний стовпець повертає `0` або `1`. Загалом у SQLite порівняння з `NULL` повертає `NULL`, а не `0`.

### 3. Спроба змінити згенерований стовпець

Було виконано команду:

```sql
UPDATE tickets
SET price_with_vat = 300
WHERE id = 1;
```

SQLite повернув помилку:

```text
Parse error near line 16: cannot UPDATE generated column "price_with_vat"
```

Це очікувана поведінка. Згенерований стовпець не можна змінювати безпосередньо, оскільки його значення визначається виразом.

### 4. Перевірка автоматичного перерахунку

Спочатку було перевірено квиток №1:

| Стан | price | price_with_vat |
|---|---:|---:|
| До зміни | 180.0 | 216.0 |

Після цього виконано:

```sql
UPDATE tickets
SET price = price + 20
WHERE id = 1;
```

Повторна перевірка:

```sql
SELECT id, price, price_with_vat
FROM tickets
WHERE id = 1;
```

Отримано:

| ID | price | price_with_vat |
|---:|---:|---:|
| 1 | 200.0 | 240.0 |

Після зміни базового стовпця `price` значення `price_with_vat` автоматично перерахувалося з 216 до 240. Це підтверджує правильність роботи згенерованого стовпця.

### 5. Фільтрація за згенерованим стовпцем

Виконано запит:

```sql
SELECT id, price, price_with_vat
FROM tickets
WHERE price_with_vat > 200;
```

Результат:

| ID квитка | Ціна без ПДВ | Ціна з ПДВ |
|---:|---:|---:|
| 1 | 200.0 | 240.0 |
| 2 | 200.0 | 240.0 |
| 3 | 170.0 | 204.0 |
| 5 | 190.0 | 228.0 |
| 6 | 210.0 | 252.0 |

Фільтрація за `price_with_vat` зрозуміліша, ніж повторення формули `price * 1.2` у кожному запиті. Назва стовпця безпосередньо пояснює, за яким значенням виконується відбір.

## Відповіді на контрольні питання

**1. Чому використано `VIRTUAL`, а не `STORED`? Що в наявній таблиці цьому заважає?**

У цій роботі таблиці вже існували, тому згенеровані стовпці додавалися командою `ALTER TABLE ... ADD COLUMN`. SQLite дозволяє таким способом додавати згенеровані стовпці типу `VIRTUAL`, але не `STORED`. Для додавання `STORED` потрібно створити нову таблицю з потрібною структурою, перенести дані та замінити стару таблицю. Отже, обмеження пов'язане зі способом зміни вже створеної таблиці, а не зі значеннями її записів.

`VIRTUAL` обчислюється під час читання і не зберігає результат окремо в таблиці. `STORED` обчислюється під час запису та зберігає результат у базі даних.

**2. Що станеться, якщо видалити базовий стовпець, на який посилається згенерований?**

SQLite не дозволить видалити базовий стовпець, доки згенерований стовпець використовує його у своєму виразі. Спочатку потрібно видалити залежний згенерований стовпець, а потім базовий.

**3. Чому заборона прямого `INSERT` або `UPDATE` у згенерований стовпець є перевагою?**

Це запобігає суперечностям між базовими та обчисленими даними. Користувач змінює лише вихідні значення, а SQLite самостійно обчислює похідне значення за заданою формулою. Завдяки цьому зменшується ризик помилок і неузгодженості даних.

## Висновок

Під час практичної роботи створено два згенеровані стовпці типу `VIRTUAL`: `price_with_vat` у таблиці `tickets` та `is_drama` у таблиці `movies`. Перевірено, що SQLite забороняє безпосередньо змінювати згенеровані значення, автоматично перераховує їх після зміни базових стовпців і дозволяє використовувати їх у запитах із `WHERE`. Також розглянуто відмінності між `VIRTUAL` і `STORED` та залежність згенерованих стовпців від базових.

# Звіт з Практичної роботи №6 (DML: UPDATE, DELETE)

**Варіант:** Аптека  
**Фактова таблиця:** `deliveries`  
**Таблиці-виміри:** `medicines`, `suppliers`  

---

## Завдання 2. Пояснення до оновлення таблиці-виміру

**Обґрунтування:**  
Використання `UPDATE` є доречним, оскільки воно змінює лише поточний стан атрибута препарату (ціну чи залишок), зберігаючи його первинний ключ (`id`) та цілісність усіх існуючих поставок у фактовій таблиці без порушення зовнішніх ключів.

---

## Завдання 4. Перевірка обмеження ON DELETE

* **Таблиця-вимір:** `medicines` (`id = 1`)
* **Фактова таблиця:** `deliveries`
* **Обраний режим ON DELETE (з Практики 4):** `RESTRICT` (за замовчуванням)

### 1. Прогноз
Оскільки для зовнішнього ключа в таблиці `deliveries` встановлено обмеження `RESTRICT` (або за замовчуванням), очікується, що при спробі видалити медикамент із `medicines`, на який є посилання у фактовій таблиці `deliveries`, СУБД SQLite заборонить видалення та поверне помилку цілісності зовнішнього ключа (`FOREIGN KEY constraint failed`).

### 2. Фактичний результат
Запит `DELETE FROM medicines WHERE id = 1;` повернув помилку: `FOREIGN KEY constraint failed`.

### 3. Порівняння
Фактичний результат **повністю відповідає прогнозу**. Видалення було відхилено СУБД, а пов'язані дані в таблиці `deliveries` залишилися неушкодженими.

# Практична робота №23
## Транзакції та обробка помилок у процедурах PostgreSQL

**Виконала:** Вовк Марія  
**Група:** І-23  
**Варіант:** 1 — Бібліотека

### Мета роботи

Навчитися створювати процедури PostgreSQL з обробкою помилок, використовувати транзакції, команди `COMMIT` і `ROLLBACK`, а також дослідити особливості їх використання всередині процедур.

### Завдання 1. Створення процедури видачі книги

Створено процедуру `issue_book_23`, яка виконує видачу книги читачу.

Перед виконанням операції процедура перевіряє, чи не є ідентифікатори книги та читача порожніми, чи існує книга та чи є доступні примірники. Для блокування рядка книги використовується `SELECT ... FOR UPDATE`.

Після перевірок процедура додає запис до таблиці `loans` та зменшує кількість примірників книги на одиницю.

Проведено перевірки:
- Успішна видача книги ID 8 читачу ID 2. Кількість примірників зменшилася з 1 до 0.
- Повторна видача книги ID 8 викликала помилку про відсутність примірників.
- Видача книги ID 999 викликала помилку, оскільки такої книги не існує.

### Завдання 2. Обробка помилок зовнішнього ключа

Під час спроби видати книгу неіснуючому читачу з ID 999 виникла системна помилка порушення зовнішнього ключа.

Код помилки: `23503` (`foreign_key_violation`).

Після цього процедуру було змінено. Додав блок `EXCEPTION`, який перехоплює помилку `foreign_key_violation` та виводить зрозуміле повідомлення: «Читача з ID 999 не знайдено».

Після повторної перевірки отримано повідомлення про відсутність читача. Перевірка таблиць підтвердила, що новий запис позики не створився, а кількість примірників книги ID 1 залишилася незмінною — 7.

### Завдання 3. Пакетне оновлення кількості примірників

Створено процедуру `update_books_batch_23` з двома параметрами: величина збільшення кількості примірників та максимальна допустима межа.

Процедура перебирає книги за зростанням ID, обчислює нову кількість примірників та перевіряє її на перевищення встановленої межі. Після кожного успішного оновлення виконується `COMMIT`.

Для перевірки використано параметри `1` та `8`. Процедура послідовно оновила 24 книги, пропустила книгу ID 24 зі значенням `NULL` та зупинилася на книзі ID 26, оскільки нова кількість примірників становила 9 і перевищувала межу 8.

Помилка не скасувала попередні зміни, оскільки вони вже були зафіксовані командами `COMMIT`.

### Завдання 4. Особливості використання COMMIT

**4а. Виклик процедури всередині явної транзакції**

Було виконано `BEGIN`, після чого викликано процедуру `update_books_batch_23` з параметрами `1` та `100`.

Виникла помилка `2D000` — неприпустиме завершення транзакції. Причина полягає в тому, що процедура містить `COMMIT`, але викликається всередині вже відкритої транзакції.

Після цього виконано `ROLLBACK`.

**4б. Використання COMMIT усередині блоку EXCEPTION**

До процедури `issue_book_23` тимчасово додано команду `COMMIT` після `INSERT` усередині блоку `BEGIN ... EXCEPTION`.

Під час виклику процедури з правильними даними виникла помилка `2D000` — неможливо затвердити транзакцію, коли активні підтранзакції.

Це пояснюється тим, що блок `EXCEPTION` створює підтранзакцію, всередині якої не дозволено виконувати `COMMIT`.

Після перевірки процедуру відновлено до робочого стану без команди `COMMIT` усередині блоку обробки помилок.

### Контрольні питання

**Завдання 1. Створення процедури видачі книги**

Проведено перевірки:
- Успішна видача книги ID 8 читачу ID 2. Кількість примірників зменшилася з 1 до 0, а запис про видачу додався до таблиці `loans`.
- Повторна видача книги ID 8 викликала помилку про відсутність примірників.
- Видача книги ID 999 викликала помилку, оскільки такої книги не існує.

**Завдання 3. Пакетне оновлення кількості примірників**

Для перевірки використано параметри `1` та `8`. Процедура послідовно оновила 24 книги, пропустила книгу ID 24, оскільки її поле `copies_count` має значення `NULL`, та зупинилася на книзі ID 26, оскільки нова кількість примірників становила 9 і перевищувала межу 8.

Помилка не скасувала попередні зміни, оскільки вони вже були зафіксовані командами `COMMIT`.

**Завдання 4. Особливості використання COMMIT**

**4а. Виклик процедури всередині явної транзакції**

Було виконано `BEGIN`, після чого викликано процедуру `update_books_batch_23` з параметрами `1` та `100`.

Виникла помилка `2D000` — неприпустиме завершення транзакції. Причина полягає в тому, що процедура містить `COMMIT`, але викликається всередині вже відкритої транзакції.

Після цього виконано `ROLLBACK`, який скасував незбережені зміни, виконані під час цього виклику процедури.

**Контрольне питання 1. Що відбувається з роботою до COMMIT, якщо після нього виникає помилка? А якщо COMMIT не було?**

Якщо команда `COMMIT` уже виконана, зафіксовані нею зміни зберігаються навіть у разі подальшої помилки. Зміни, які ще не були зафіксовані, можуть бути скасовані за допомогою `ROLLBACK`. Якщо `COMMIT` не було, незавершені зміни можна скасувати.

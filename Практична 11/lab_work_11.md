# Практична робота №11
## Комбіновані завдання з групуванням та відбором даних

**Варіант 9 — Університет (деканат)**

### Дослідницьке питання

Які студенти отримали найбільшу суму стипендій у поточному навчальному році?

## Завдання 1. Проєктування нової таблиці

Створено залежну таблицю `scholarships`, яка пов’язана з таблицею студентів `university` через зовнішній ключ `student_id`. У ній зберігаються навчальний рік, тип стипендії, її сума та дата призначення.

Первинний ключ `id` однозначно визначає кожний запис. `student_id` має обмеження `NOT NULL` і зовнішній ключ із `ON DELETE CASCADE`, тому стипендія не може існувати без студента. Поле `amount` має перевірку `CHECK (amount > 0)`, адже сума стипендії повинна бути додатною. Для `academic_year` використано перевірку формату навчального року. Обмеження `UNIQUE (student_id, academic_year, scholarship_type)` не дозволяє двічі призначити одному студентові той самий тип стипендії за один навчальний рік.

Таблиця містить 8 початкових записів. Кількість записів у групах студентів різна. Студент Коваленко (id=7) навмисно не має жодної стипендії — він потрібен для експерименту з `LEFT JOIN`.

## Завдання 2. JOIN + GROUP BY

Таблиці `university` та `scholarships` об’єднано за `university.id = scholarships.student_id`. Функція `SUM()` обчислює загальну суму призначених стипендій для кожного студента. Групування виконується за `university.id`, а не за ПІБ, оскільки id є унікальним.

Початковий результат:

| Студент | Загальна сума, грн |
|---|---:|
| Петренко Олександр | 4500 |
| Іванов Максим | 1800 |
| Сидоренко Марія | 3000 |
| Ковальчук Ірина | 3200 |
| Мельник Андрій | 2200 |
| Бойко Софія | 1000 |

## Завдання 3. Додавання HAVING

Використано умову `HAVING SUM(scholarships.amount) > 3000`. Вона залишає студентів, у яких загальна сума стипендій за всі роки перевищує 3000 грн.

**Результат:** Петренко Олександр — 4500 грн; Ковальчук Ірина — 3200 грн. Інші групи не проходять встановлений поріг.

## Завдання 4. WHERE + JOIN + GROUP BY + HAVING

Додано `WHERE scholarships.academic_year = '2025-2026'`, щоб враховувати лише поточний навчальний рік. Після групування за студентами `HAVING SUM(scholarships.amount) > 2000` залишає тих, кому за цей рік призначено понад 2000 грн.

**Результат:**
- Петренко Олександр — 2500 грн;
- Сидоренко Марія — 3000 грн;
- Мельник Андрій — 2200 грн.

Отже, загальний результат за всі роки відрізняється від результату за поточний навчальний рік: Ковальчук Ірина мала понад 3000 грн загалом, але за 2025–2026 рік її сума становить лише 1700 грн.

## Завдання 5. Експерименти та висновок

### а) Пастка групування

До таблиці `university` додано нового студента id=8 з таким самим ПІБ, як у студента id=1 — Петренко Олександр. Для нового запису додано дві стипендії по 1600 грн, тобто разом 3200 грн.

Якщо групувати за `university.id`, тезки залишаються окремими групами:
- id=1, Петренко Олександр — 4500 грн;
- id=4, Ковальчук Ірина — 3200 грн;
- id=8, Петренко Олександр — 3200 грн.

Якщо групувати за прізвищем та ім’ям, записи двох Петренків об’єднаються в одну групу — 7700 грн. Через це неможливо зрозуміти, яка саме людина отримала кожну суму. Тому для коректної аналітики потрібно групувати за унікальним id, а ім’я використовувати лише для відображення.

### б) LEFT JOIN

У запиті Завдання 4 `JOIN` замінено на `LEFT JOIN`. Результат не змінився: залишилися Петренко Олександр, Сидоренко Марія та Мельник Андрій.

Студент id=7, який не має стипендій, після `LEFT JOIN` зберігається як рядок із `NULL` у полях `scholarships`. Але умова `WHERE scholarships.academic_year = '2025-2026'` відкидає цей рядок, оскільки `NULL` не дорівнює зазначеному року. Тому в цьому запиті `LEFT JOIN` фактично не зберігає студента без стипендії. Щоб включити його до результату, довелося б змінити умову `WHERE` та окремо врахувати `NULL`.

### в) Відповідь на дослідницьке питання

У 2025–2026 навчальному році понад 2000 грн стипендій отримали Петренко Олександр — 2500 грн, Сидоренко Марія — 3000 грн та Мельник Андрій — 2200 грн. Найбільшу суму серед них отримала Сидоренко Марія. Саме ці студенти відповідають заданій умові, а не всі, хто мав найбільші виплати за весь період навчання.

## Контрольне питання

Якщо автор має дві книги, і кожна продавалася тричі, після `JOIN` до групування буде **6 рядків**: по три рядки продажу для кожної книги. Тому `COUNT(*)` покаже 6, бо рахує рядки результату об’єднання, тобто продажі, а не унікальні книги. Щоб отримати кількість книг, потрібно використати `COUNT(DISTINCT books.id)`, і результат буде 2.

# Практична робота №17
## Імпорт даних із CSV у SQLite: типові проблеми, перевірка й експорт

**Варіант:** 3 — кінотеатр  
**База даних:** `lab_work_17.db`  
**Вхідний файл:** `v3_raw_rows.csv`

## Мета роботи

Навчитися імпортувати CSV-файли до SQLite, виявляти помилки роздільника та кодування, перевіряти якість імпортованих даних, усувати дублікати й неповні записи, безпечно додавати коректні дані до основної таблиці та експортувати результат у CSV.

## 1. Підготовка бази даних

Для збереження результатів попередньої роботи було створено окрему копію бази даних `lab_work_16.db` під назвою `lab_work_17.db`.

У базі створено тимчасову таблицю `movies_staging` без обмежень `NOT NULL`:

```sql
CREATE TABLE movies_staging (
    title TEXT,
    genre TEXT,
    duration_min INTEGER,
    year INTEGER,
    age_rating INTEGER
);
```

Така таблиця дає змогу спочатку завантажити початкові дані, включно з неповними значеннями, а потім перевірити їх перед перенесенням до основної таблиці.

## 2. Неправильний імпорт CSV

Спочатку було ввімкнено режим CSV, але не було змінено стандартний роздільник-кома. У файлі `v3_raw_rows.csv` поля розділені крапкою з комою `;`.

Під час імпорту SQLite видала попередження. Перші три повідомлення:

```text
expected 5 columns but found 2 - filling the rest with NULL
expected 5 columns but found 1 - filling the rest with NULL
expected 5 columns but found 1 - filling the rest with NULL
```

Після неправильного імпорту в таблиці було 10 рядків. Перший стовпець першого запису містив лише `Люксембург`, оскільки кома в назві `Люксембург, Люксембург` була сприйнята як роздільник полів.

**Висновок:** перед імпортом CSV необхідно перевірити фактичний роздільник у файлі та налаштувати SQLite відповідно до нього.

Після перевірки таблицю `movies_staging` було очищено командою:

```sql
DELETE FROM movies_staging;
```

## 3. Правильний імпорт CSV

Для правильного імпорту було встановлено роздільник `;`:

```sql
.mode csv
.separator ";"
.import --skip 1 "C:/Users/user/OneDrive/Desktop/data-bases-course/docs/practice/csv/17-csv-import-2/v3_raw_rows.csv" movies_staging
```

Після імпорту попереджень не було. Запит `SELECT COUNT(*) FROM movies_staging;` повернув **10**. Отже, усі 10 записів із CSV були завантажені до staging-таблиці.

## 4. Перевірка якості даних

### 4.1. Порожні значення

Перевірка показала:

| Стовпець | Кількість порожніх значень |
|---|---:|
| `title` | 0 |
| `genre` | 0 |
| `duration_min` | 2 |
| `year` | 0 |
| `age_rating` | 0 |

Порожня тривалість була в записах фільмів **«Будинок «Слово»»** та **«20 днів у Маріуполі»**.

### 4.2. Перевірка типів даних

Результат `typeof()`:

| Тип `duration_min` | Тип `year` | Тип `age_rating` | Кількість |
|---|---|---|---:|
| `integer` | `integer` | `integer` | 8 |
| `text` | `integer` | `integer` | 2 |

Два порожні значення тривалості були імпортовані як текстові значення, а не як числові `NULL`. Це потрібно враховувати під час перенесення даних.

### 4.3. Пошук дублікатів

Запит із `GROUP BY` та `HAVING COUNT(*) > 1` виявив один дублікат:

| Назва | Жанр | Тривалість | Рік | Віковий рейтинг | Кількість |
|---|---|---:|---:|---:|---:|
| Довбуш | пригоди | 125 | 2023 | 16 | 2 |

Один із двох однакових записів потрібно було відкинути.

### 4.4. Перевірка обмежень основної таблиці

Структура таблиці `movies`:

```sql
CREATE TABLE movies (
    id INTEGER PRIMARY KEY,
    title TEXT NOT NULL,
    genre TEXT NOT NULL,
    duration_min INTEGER NOT NULL,
    year INTEGER NOT NULL,
    age_rating INTEGER NOT NULL
);
```

Усі п'ять полів, крім первинного ключа, мають обмеження `NOT NULL`. Тому два записи без `duration_min` не можна було вставити до основної таблиці без вигадування даних.

До вставлення в `movies` було **14 записів**, максимальний ID — **14**.

Із 10 рядків CSV можна було перенести 7 повних унікальних записів: два рядки відкладено через відсутню тривалість, а один повторний запис «Довбуш» усунуто.

## 5. Перенесення коректних даних до основної таблиці

Для перенесення використано один запит `INSERT ... SELECT`. У ньому застосовано:

- `DISTINCT` — для усунення повторів у staging-таблиці;
- `NULLIF()` — для перетворення порожнього рядка на `NULL`;
- `CAST(... AS INTEGER)` — для приведення числових значень до цілого типу;
- умову `duration_min != ''` — щоб не порушити обмеження `NOT NULL`;
- `NOT EXISTS` — щоб не додати запис, який уже є в основній таблиці.

Після виконання запиту отримано такі результати:

| Показник | До імпорту | Після імпорту |
|---|---:|---:|
| Кількість фільмів | 14 | 21 |
| Максимальний ID | 14 | 21 |

Було додано 7 записів:

| ID | Назва | Жанр | Тривалість | Рік | Віковий рейтинг |
|---:|---|---|---:|---:|---:|
| 15 | Люксембург, Люксембург | комедія | 108 | 2022 | 16 |
| 16 | Стоп-Земля | драма | 122 | 2021 | 12 |
| 17 | Довбуш | пригоди | 125 | 2023 | 16 |
| 18 | Віддана | драма | 125 | 2020 | 16 |
| 19 | Носоріг | драма | 101 | 2021 | 18 |
| 20 | Мої думки тихі | комедія | 104 | 2019 | 16 |
| 21 | Скажене весілля | комедія | 95 | 2018 | 12 |

Перевірка наявності `NULL` у полях таблиці `movies` повернула **0** неповних записів. Це підтвердило, що обмеження `NOT NULL` не порушені.

Після перенесення даних тимчасову таблицю було видалено:

```sql

DROP TABLE movies_staging;
```

## 6. Експорт даних у CSV

Сім доданих записів було експортовано до файлу `practice17_export.csv` за допомогою команд:

```sql
.headers on
.mode csv
.output "C:/Users/user/OneDrive/Desktop/practices_BD/practice10/practice17_export.csv"

SELECT title, genre, duration_min, year, age_rating
FROM movies
WHERE id BETWEEN 15 AND 21
ORDER BY id;

.output stdout
```

Файл містить один рядок заголовків і сім рядків із даними.

Під час перегляду CSV було помічено, що українські символи спочатку відображалися неправильно через проблему кодування під час перегляду файлу. Після перевірки виведення безпосередньо з SQLite український текст відображався коректно.

### Пояснення формату CSV

- **Роздільник:** кома `,`, оскільки експорт виконувався в режимі `.mode csv`.
- **Лапки:** текстові значення беруться в подвійні лапки. Наприклад, назва `Люксембург, Люксембург` обрамлена лапками, щоб кома всередині назви не сприймалася як межа двох стовпців.
- **Порожні значення:** серед експортованих семи записів порожніх значень немає. Якби значення було `NULL`, SQLite відобразила б його як порожнє поле CSV.
- **Повторний імпорт:** під час повторного імпорту потрібно правильно налаштувати роздільник, врахувати заголовок і перевірити обмеження таблиці. Якщо імпортувати ці рядки безпосередньо в `movies`, можна отримати дублікати, якщо не виконати попередню перевірку.

## 7. Фінальна перевірка

Фінальний запит `SELECT COUNT(*) FROM movies;` повернув **21**.

Команда `.tables` показала три основні таблиці:

```text
movies

```

Тимчасова таблиця `movies_staging` відсутня.

## Висновок

Під час практичної роботи було досліджено імпорт CSV-файлів у SQLite та типові проблеми, що виникають через неправильний роздільник, порожні значення, дублікати й особливості типізації даних. Після правильного налаштування роздільника до staging-таблиці було імпортовано 10 записів. Перевірка якості даних виявила два порожні значення тривалості та один дублікат. До основної таблиці було безпечно додано 7 повних унікальних записів. Після цього виконано експорт доданих даних у CSV та перевірено результат. У підсумку таблиця `movies` містить 21 запис, а тимчасову таблицю видалено.

## Контрольні запитання — короткі відповіді

**1. Для чого потрібна staging-таблиця?**  
Це проміжна таблиця, у яку спочатку імпортують необроблені дані. Вона дає змогу перевірити й очистити їх перед додаванням до основної таблиці.

**2. Чому під час неправильного імпорту виникли попередження?**  
Тому що SQLite використовувала кому як роздільник, хоча в початковому CSV поля були розділені крапкою з комою.

**3. Як налаштувати роздільник CSV у SQLite CLI?**  
За допомогою команди `.separator ";"`.

**4. Чим порожній рядок відрізняється від NULL?**  
Порожній рядок `''` є текстовим значенням нульової довжини, а `NULL` означає відсутність значення.

**5. Для чого використовується NULLIF()?**  
`NULLIF(a, b)` повертає `NULL`, якщо `a` дорівнює `b`. Наприклад, `NULLIF(duration_min, '')` перетворює порожній рядок на `NULL`.

**6. Для чого використовується DISTINCT?**  
Для вилучення повторюваних рядків із результату вибірки.

**7. Як знайти дублікати?**  
Згрупувати записи за всіма важливими полями за допомогою `GROUP BY` і залишити групи, де `COUNT(*) > 1`.

**8. Чому неповні записи не було додано до movies?**  
Тому що поле `duration_min` має обмеження `NOT NULL`. Вставлення рядка без тривалості порушило б це обмеження.

**9. Для чого потрібні .headers on та .mode csv?**  
`.headers on` додає назви стовпців до результату, а `.mode csv` форматує виведення як CSV.

**10. Навіщо текстові значення в CSV беруться в лапки?**  
Щоб коми або інші символи всередині тексту не сприймалися як роздільники полів.

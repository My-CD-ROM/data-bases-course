# Практика 15. Створення індексів та аналіз ефективності запитів

*Мета заняття: застосувати `CREATE INDEX` і `EXPLAIN QUERY PLAN` з
лекції 13 до своєї бази – побудувати індекс на фактовій таблиці й на
власні очі побачити зміну плану виконання запиту з `SCAN` на
`SEARCH ... USING INDEX`.*

## Варіант

Той самий варіант і той самий файл `.db`, що на практиках 4–14:
структура таблиць не змінюється, лише додається індекс (сам індекс –
не таблиця й не зв’язок, тож жодного нового `.sql`-стану тут не
потрібно). Якщо файл `.db` втрачено, поверніться до
`v{N}_prerequisites.sql` з [практики 4](04-insert-keys.md#sql) і
повторно виконайте завдання 1–4 тієї практики, щоб відновити повну
схему з трьома таблицями й зв’язками, перш ніж продовжувати тут.

## Приклад: наскрізна демонстрація

```sql
-- план до індексу
EXPLAIN QUERY PLAN
SELECT * FROM visits WHERE vet_id = 2;
-- SCAN visits

CREATE INDEX idx_visits_vet ON visits(vet_id);

-- план після індексу
EXPLAIN QUERY PLAN
SELECT * FROM visits WHERE vet_id = 2;
-- SEARCH visits USING INDEX idx_visits_vet (vet_id=?)
```

## Завдання

**Завдання 1. EXPLAIN QUERY PLAN до індексу.** Виконайте
`EXPLAIN QUERY PLAN` для запиту, що фільтрує вашу фактову таблицю за
одним із зовнішніх ключів (`WHERE product_id = ...`,
`WHERE customer_id = ...` тощо). Зафіксуйте письмово точний текст
плану, який показала SQLite до створення будь-якого індексу.

**Завдання 2. CREATE INDEX на зовнішньому ключі.** Створіть індекс на
тому самому зовнішньому ключі фактової таблиці, який використали в
Завданні 1. Повторіть той самий `EXPLAIN QUERY PLAN`-запит і зафіксуйте
письмово, як саме змінився текст плану.

**Завдання 3. Композитний індекс.** Побудуйте запит, що фільтрує
фактову таблицю за **двома** умовами одночасно (наприклад,
`WHERE customer_id = ... AND status = ...`). Виконайте
`EXPLAIN QUERY PLAN` для нього до й після створення композитного
індексу на обох колонках (`CREATE INDEX ... ON таблиця(колонка1,
колонка2)`). Письмово поясніть різницю в плані.

**Завдання 4. Індекс і ORDER BY.** Побудуйте індекс на колонці-даті
вашої фактової таблиці (`order_date`, `sale_date`, `trip_date` тощо) і
порівняйте `EXPLAIN QUERY PLAN` для запиту з `ORDER BY` за цією
колонкою до й після створення індексу. Письмово поясніть, що саме
змінилося в плані щодо кроку сортування.

**Завдання 5. DROP INDEX і повторна перевірка.** Видаліть один зі
створених індексів (`DROP INDEX`) і повторіть відповідний
`EXPLAIN QUERY PLAN`-запит. Письмово підтвердьте: план повернувся до
`SCAN` (або використовує інший наявний індекс, що починається з тієї
самої колонки, наприклад композитний із Завдання 3), і перевірте
окремим `SELECT` із `sqlite_master`, що індекс справді видалено зі
списку.

## Що здати й оцінюється

Здайте `lab_work_15.sql` – усі виконані команди (`CREATE INDEX`,
`DROP INDEX`, `EXPLAIN QUERY PLAN`) разом з точними текстами планів до
й після для завдань 1–5; `lab_work_15.db` – файл бази даних з
побудованими індексами (крім видаленого); і `lab_work_15.md` – письмові
пояснення до завдань 2–5. Контрольні питання:

- Чому `EXPLAIN QUERY PLAN` показує саме план, а не результат запиту,
  і навіщо перевіряти план окремо від того, що запит просто «працює»?
- У Завданні 3: чому індекс лише на першій із двох колонок умови дає
  менший ефект, ніж композитний індекс на обох?
- Яка ціна створення індексу (лекція 13, розділ 15) і чому не варто
  індексувати кожну колонку таблиці «про всяк випадок»?

Оцінюється точність зафіксованих текстів плану до й після в кожному
завданні, правильний вибір колонок для індексу (завдання 2–4) і
розуміння того, коли композитний індекс дає перевагу над одноколонковим
(Завдання 3).

## Підсумок заняття

- Побудовано індекс (одноколонковий і композитний) на фактовій таблиці
  свого варіанта та підтверджено зміну плану виконання запиту з `SCAN`
  на `SEARCH ... USING INDEX`.
- На практиці підтверджено вплив індексу на `ORDER BY` та перевірено
  видалення індексу через `DROP INDEX` і `sqlite_master`.
- Зрозуміло, що індекс має свою ціну і створюється цілеспрямовано, а не
  на кожній колонці підряд.

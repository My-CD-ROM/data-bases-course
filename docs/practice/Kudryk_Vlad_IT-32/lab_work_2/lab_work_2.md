# Звіт з Практичної роботи №2
**Тема:** Формування запитів вибірки у SQLite (glovo)

## Пояснення до Завдання 4
Оператор `= NULL` не працює в SQL, тому що `NULL` означає «відсутність даних» або «невідоме значення». Будь-яке порівняння з невідомим дає результат `NULL` (невідомо), а не `TRUE` чи `FALSE`. Блок `WHERE` виводить лише ті рядки, де результат `TRUE`. Тому порівняння через `=` ніколи не спрацює. Для перевірки на порожню комірку правильно використовувати спеціальний оператор `IS NULL`.

## Відповіді на контрольні питання

1. **Чому запит WHERE price = NULL завжди повертає порожній результат?**
   У SQL використовується тризначна логіка (`TRUE`, `FALSE`, `UNKNOWN/NULL`). Вираз `price = NULL` обчислюється як `UNKNOWN` (невідомо), що сприймається блоком `WHERE` як хибна умова, і жоден рядок не потрапляє у вибірку. Замість цього слід використовувати `WHERE price IS NULL`.

2. **Чим WHERE принципово відрізняється від HAVING?**
   Оператор `WHERE` фільтрує окремі рядки таблиці **до** того, як дані будуть згруповані. Оператор `HAVING` фільтрує вже згруповані дані **після** використання `GROUP BY` та обчислення агрегатних функцій (`SUM`, `COUNT`, `AVG` тощо).

3. **У якому випадку варто уникати SELECT *, і чому саме?**
   Використання `SELECT *` варто уникати у продакшен-коді з двох причин:
   - **Продуктивність:** завантаження всіх стовпців створює зайве навантаження на мережу та оперативну пам'ять, якщо потрібна лише частина даних.
   - **Стабільність:** якщо структура таблиці зміниться (додадуться чи видаляться стовпці), це може зламати логіку програми, яка розраховує на конкретний порядок або кількість стовпців.

# Практика 5. Робота з командами оновлення та видалення у SQLite

*Мета заняття: застосувати `UPDATE` і `DELETE` з Лекції 6 до фактової
(журнальної) таблиці свого варіанта — без жодної зміни структури — і на
практиці переконатися, що обмеження цілісності з Лекції 5 (`NOT NULL`,
`UNIQUE`, `CHECK`) продовжують діяти й після того, як рядок уже
записано.*

## Варіант

Той самий варіант і той самий файл `.db`, що в
[Практиці 1](01-sqlite-create.md) і [Практиці 4](04-insert-keys.md) —
сьогодні структура таблиць **не змінюється**, лише дані в них.
Знадобиться повна тристаблична схема з Практики 4: обидві
таблиці-вимір і фактова (журнальна) таблиця з двома зовнішніми ключами.

Якщо свій файл `.db` після Практики 4 не збережено чи загублено —
готового файлу з уже побудованими зв'язками тут немає навмисно
(побудова зв'язків — це власне завдання Практики 4). Поверніться до
`v{N}_prerequisites.sql` свого варіанта з
[Практики 4](04-insert-keys.md#sql) і виконайте Завдання 1-4 тієї
практики ще раз, щоб отримати повну робочу схему для сьогоднішнього
заняття.

## Приклад: наскрізна демонстрація

На ветклініці з лекцій — `UPDATE` одного рядка, потім `DELETE`, потім
спроба порушити `CHECK` при оновленні:

```sql
-- позначити, що тварині виповнилось на рік більше
UPDATE animals SET age = age + 1 WHERE name = 'Мурчик';

-- видалити один конкретний візит (за id, найнадійніший спосіб — унікальний PK)
DELETE FROM visits WHERE id = 2;

-- спроба оновлення, яка порушує CHECK з Лекції 5
UPDATE animals SET age = -1 WHERE name = 'Рекс';
-- Runtime error: CHECK constraint failed: age >= 0
```

Останній рядок навмисно провальний: обмеження `CHECK (age >= 0)`,
задане ще при `CREATE TABLE`, продовжує діяти й на `UPDATE`, не тільки
на `INSERT` — саме це й перевіряє Завдання 4 нижче на вашому варіанті.

## Завдання

**Завдання 1. UPDATE у фактовій таблиці.** Оновіть **один конкретний**
рядок фактової (журнальної) таблиці свого варіанта, заповнивши
значення стовпця, який досі було `NULL` або мало "тимчасове" значення
— подивіться свій рядок таблиці варіантів із Практики 1: для
"Бібліотеки" це `return_date` у `loans`, для "Готелю" —
фактичний виїзд у `bookings`, для решти варіантів — аналогічний за
змістом стовпець (статус, дата завершення тощо). Використайте `WHERE`
з умовою за первинним ключем (`id = ...`), щоб оновити рівно один
рядок.

**Завдання 2. UPDATE у таблиці-вимірі.** Оновіть один "змінний"
показник в одній з двох таблиць-вимірів (наприклад
`stock_quantity`, `status`, `price`) для одного конкретного рядка.
Письмово (одне речення) поясніть, чому тут доречний саме `UPDATE`, а не
видалення старого рядка й вставка нового.

**Завдання 3. DELETE одного рядка.** Видаліть **рівно один** рядок з
фактової (журнальної) таблиці за умовою на первинний ключ (наприклад,
скасоване замовлення чи бронювання). Виконайте `SELECT COUNT(*)` до і
після видалення, щоб задокументувати, що зникнув саме один рядок, а не
більше.

**Завдання 4. Перевірка обмежень цілісності при UPDATE.** Навмисно
спробуйте виконати `UPDATE`, який порушує одне з обмежень Лекції 5 на
вашій таблиці (`NOT NULL`, `UNIQUE` або `CHECK` — залежно від того, які
обмеження ви заклали в Практиці 1 чи 4). Запишіть точний текст
повідомлення про помилку, яке видала SQLite, і поясніть, яке саме
обмеження спрацювало.

**Завдання 5. DELETE/UPDATE без WHERE — аналіз без виконання.**
**Не виконуйте** цю команду на своїй базі. Письмово поясніть: що б
сталося, якби з команди Завдання 3 прибрати `WHERE`? А якби з команди
Завдання 1? Скільки рядків це зачепило б у вашій поточній базі —
дайте точне число, спираючись на `SELECT COUNT(*)` вашої фактової
таблиці.

## Що здати й оцінюється

Здайте оновлений файл бази (`.db`) після Завдань 1-3 та письмові
відповіді Завдань 2, 4 і 5.

Контрольні питання:

- Чим `UPDATE ... SET колонка = колонка + 1` відрізняється від
  `UPDATE ... SET колонка = <конкретне число>`?
- Чому обмеження `NOT NULL`/`UNIQUE`/`CHECK` завжди перевіряються при
  `UPDATE`, тоді як `FOREIGN KEY` — лише за умови
  `PRAGMA foreign_keys = ON;`?
- Якби на вашій фактовій таблиці FK було оголошено з `ON DELETE
  CASCADE` замість `RESTRICT` (Лекція 4), як це змінило б наслідки
  видалення рядка з таблиці-вимір, на яку та фактова таблиця
  посилається?
- Чому `DELETE` без `WHERE` небезпечніший за помилку типу чи
  порушення обмеження цілісності?

Оцінюється правильність виконаних `UPDATE`/`DELETE` (рівно ті рядки, що
вимагались, жодного зайвого), точність зафіксованого повідомлення про
помилку в Завданні 4 і обґрунтованість письмових відповідей.

## Підсумок заняття

- Фактова (журнальна) таблиця варіанта оновлена (`UPDATE`) і зменшена
  на один рядок (`DELETE`) — без жодної зміни структури таблиць.
- Підтверджено практично: обмеження цілісності з Лекції 5 діють і при
  `UPDATE`, не лише при `INSERT`.
- Проаналізовано (без виконання) ризик `DELETE`/`UPDATE` без `WHERE` —
  найдорожчу з типових помилок цієї теми.

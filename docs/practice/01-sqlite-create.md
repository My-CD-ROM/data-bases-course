# Практика 1. Створення бази даних у SQLite

*Мета заняття: створити файл власної бази даних у SQLite і першу таблицю
свого варіанта — таблицю-вимір 1 — з правильно обраними типами даних,
закріпивши CLI (або DB Browser for SQLite) і типи даних із Лекції 1.*

## Крок 1. Інструмент для SQL

Обидва інструменти з Лекції 1 працюють з тим самим файлом `.db` — оберіть
один (можна тримати й обидва, перемикаючись за потреби).

### Варіант А. DB Browser for SQLite (DB4S) — графічний інтерфейс

Завантажте інсталятор з офіційного сайту
[sqlitebrowser.org/dl](https://sqlitebrowser.org/dl/) — окремі збірки
для Windows, macOS і Linux. Альтернативно, через пакетний менеджер:

```bash
brew install --cask db-browser-for-sqlite   # macOS
sudo apt install sqlitebrowser              # Ubuntu/Debian
```

Після встановлення: відкрийте застосунок **DB Browser for SQLite**
(Spotlight/Launchpad на macOS, чи `open -a "DB Browser for SQLite"` з
терміналу). **New Database** створює файл `.db`, вкладка
**Execute SQL** — де виконуються всі запити нижче.

### Варіант Б. CLI `sqlite3` — командний рядок

- **macOS**: `sqlite3` уже вбудований — відкрийте Термінал і перевірте
  `sqlite3 --version`. Для новішої версії: `brew install sqlite`.
- **Linux (Ubuntu/Debian)**: `sudo apt install sqlite3`.
- **Windows**: `winget install -e --id SQLite.SQLite`, потім у **новому**
  вікні термінала — `sqlite3 --version`. Якщо команда не знайдена —
  завантажте `sqlite-tools-win-*.zip` з
  [sqlite.org/download.html](https://sqlite.org/download.html),
  розпакуйте і запускайте `sqlite3.exe` з цієї папки.

Перевірка, що інструмент готовий (будь-який варіант): відкрийте будь-яку
тестову базу і виконайте `.databases` — має з'явитися рядок з назвою
файлу.

## Приклад: наскрізна демонстрація

Демонстраційний домен — **ветклініка** (тварини, власники, візити). Він
навмисно відрізняється від усіх десяти варіантів вище: копіювати цей код
для власного завдання не вийде, підійде лише сам підхід.

Підключення до `sqlite3` і створення файлу бази:

```bash
sqlite3 vetklinika.db
```

Створення таблиці й перевірка структури:

```sql
CREATE TABLE animals (
    id                 INTEGER PRIMARY KEY,
    name               TEXT NOT NULL,
    species            TEXT NOT NULL,
    breed              TEXT,
    birth_date         TEXT,
    weight             REAL
);

.schema animals
.tables
```

Додавання кількох рядків і перевірка, що дані читаються:

```sql
INSERT INTO animals (name, species, breed, birth_date, weight) VALUES
    ('Барсик', 'кіт', 'британська', '2022-03-14', 4.2),
    ('Рекс', 'пес', 'вівчарка', '2020-06-01', 28.5),
    ('Мурка', 'кіт', 'сфінкс', '2023-01-20', 3.1),
    ('Бім', 'пес', 'дворняга', '2021-11-09', 15.0),
    ('Кіко', 'папуга', 'хвилястий', '2024-02-02', 0.04);

SELECT * FROM animals;
```

```
1|Барсик|кіт|британська|2022-03-14|4.2
2|Рекс|пес|вівчарка|2020-06-01|28.5
3|Мурка|кіт|сфінкс|2023-01-20|3.1
4|Бім|пес|дворняга|2021-11-09|15.0
5|Кіко|папуга|хвилястий|2024-02-02|0.04
```

`SELECT *` тут означає "усі стовпці, усі рядки" — найпростіша можлива
вибірка, лише щоб переконатися, що дані реально збереглися так, як
задумано. Про справжню вибірку з умовами (`WHERE`, `LIMIT`) — уже в
Лекції 2 і Практиці 2.

## Завдання

### Завдання 1. Створення файлу бази й таблиці-вимір 1

Створіть файл бази для свого варіанта (наприклад, `biblioteka.db` для
варіанта "Бібліотека") — командою `sqlite3 назва_файлу.db` у CLI або
через **New Database** у DB Browser for SQLite. Створіть у ньому таблицю
зі свого рядка таблиці варіантів, обравши тип SQLite (`INTEGER`, `TEXT`,
`REAL`) для кожного стовпця самостійно — підказка в таблиці варіантів
лише орієнтовна, важливо, щоб ви усвідомили, чому обрали саме цей тип, а
не просто скопіювали підказку.

### Завдання 2. Наповнення даними

Додайте (`INSERT`) щонайменше **5-6 реалістичних рядків** у свою таблицю
— вигадані, але правдоподібні дані (реальні назви книг/товарів/фільмів
тощо, розумні ціни й кількості, а не випадкові символи).

### Завдання 3. Перевірка структури

Виконайте `.schema` (переконайтеся, що типи стовпців саме ті, які ви
задумали) і `.tables` (переконайтеся, що таблиця саме одна і саме з тією
назвою, яку ви планували).

### Завдання 4. Перевірка даних

Виконайте `SELECT * FROM ваша_таблиця;` і переконайтеся, що всі рядки,
які ви вставили в Завданні 2, читаються коректно й у тих типах, які
очікувались (наприклад, ціни — числа, а не текст у лапках).

### Завдання 5. Письмове пояснення обраних типів

Письмово (кілька речень на кожен стовпець, у текстовому файлі чи
markdown-нотатці) поясніть, чому для кожного стовпця вашої таблиці
обрано саме такий тип SQLite. Спирайтеся на поняття **type affinity** з
Лекції 1: чому, наприклад, кількість екземплярів — `INTEGER`, а не
`TEXT`, хоча SQLite технічно дозволив би записати туди й текст.

## Що здати й оцінюється

Здайте файл бази (`.db`) зі створеною й наповненою таблицею-вимір 1
свого варіанта та письмове пояснення обраних типів (Завдання 5).
Оцінюється відповідність структури таблиці своєму варіанту, коректність
обраних типів і повнота письмового пояснення.

Контрольні питання (готуйтеся відповісти усно):

- Чому SQLite називають файловою, безсерверною СУБД — і що саме це
  означає на практиці для файлу, який ви щойно створили?
- Яка різниця між роботою через `sqlite3` (CLI) і через DB Browser for
  SQLite — коли зручніший кожен із них?
- Що таке type affinity в SQLite і чим це принципово відрізняється від
  типізації стовпців у PostgreSQL?
- Чим стовпець `id INTEGER PRIMARY KEY` відрізняється поведінкою від
  звичайного стовпця типу `INTEGER`?

## Підсумок заняття

- Обрано й зафіксовано варіант, з яким студент працюватиме всі практичні
  заняття курсу.
- Створено файл бази даних і першу таблицю (таблицю-вимір 1) з
  обґрунтовано обраними типами SQLite.
- Таблицю наповнено реалістичними даними і перевірено через
  `.schema`, `.tables` і `SELECT *`.
- Ця таблиця — фундамент схеми варіанта: у Практиці 4 до неї додасться
  друга таблиця-вимір і фактова (журнальна) таблиця зі зв'язками.

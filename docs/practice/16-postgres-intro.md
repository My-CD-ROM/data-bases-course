# Практика 16. Створення бази даних у PostgreSQL (PgAdmin)

*Мета заняття: перенести свою вже готову трьохтабличну схему (з усіма
зв'язками) з SQLite у PostgreSQL — самостійно перекласти `CREATE
TABLE` за відмінностями з Лекції 18, а потім перенести вже наявні
дані через експорт/імпорт CSV.*

## Що знадобиться

Ваш файл `.db` з SQLite (з усіма трьома таблицями й даними, накопиченими
за Практики 1-15) і встановлені PostgreSQL + PgAdmin. Структуру вашого
варіанта (назви таблиць і колонок) шукайте в таблиці варіантів з
[Практики 1](01-sqlite-create.md).

## Приклад: наскрізна демонстрація (переклад однієї таблиці)

```sql
-- було в SQLite:
CREATE TABLE owners (
    id INTEGER PRIMARY KEY,
    last_name TEXT NOT NULL,
    first_name TEXT NOT NULL,
    phone TEXT,
    email TEXT
);
```

```sql
-- стало в PostgreSQL (Query Tool у PgAdmin):
CREATE TABLE owners (
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    last_name TEXT NOT NULL,
    first_name TEXT NOT NULL,
    phone TEXT,
    email TEXT
);
```

Після експорту наявних рядків `owners` із DB Browser for SQLite у CSV
(**File → Export → Table as CSV**, з увімкненим рядком заголовків) і
імпорту цього CSV у щойно створену таблицю PostgreSQL (у PgAdmin:
правий клік на таблиці → **Import/Export Data**, формат CSV, заголовки
є) — **обов'язково** виконати:

```sql
SELECT setval(pg_get_serial_sequence('owners', 'id'), (SELECT MAX(id) FROM owners));
```

— інакше наступний `INSERT` без явного `id` спробує повторити вже
зайняте значення (Лекція 18, розділ 8).

## Завдання

**Завдання 1. Створення бази даних.** У PgAdmin створіть нову базу
даних для свого варіанта (правий клік на сервері → Create → Database).
Дайте їй назву, що відображає ваш варіант (наприклад, `library_db`,
`gym_db`).

**Завдання 2. Переклад трьох CREATE TABLE.** Самостійно перекладіть
структуру всіх трьох таблиць свого варіанта (таблиця-вимір 1,
таблиця-вимір 2, фактова таблиця) із SQLite-синтаксису на PostgreSQL,
застосувавши відмінності з Лекції 18: `GENERATED ALWAYS AS IDENTITY`
замість `INTEGER PRIMARY KEY`, коректні типи (`TEXT`, `INTEGER`,
`REAL`, `BOOLEAN` де доречно), і `FOREIGN KEY` на обох зв'язках
фактової таблиці (без потреби у `PRAGMA` — Лекція 18, розділ 5).
Виконайте всі три `CREATE TABLE` у Query Tool.

**Завдання 3. Перенесення даних.** Для кожної з трьох таблиць:
експортуйте її поточний вміст із SQLite у CSV (DB Browser for SQLite:
**File → Export → Table as CSV**) і імпортуйте цей CSV у відповідну
щойно створену таблицю PostgreSQL через **Import/Export Data** у
PgAdmin. Дотримайтесь порядку: спершу обидві таблиці-вимірювання,
потім фактова таблиця (щоб зовнішні ключі одразу знаходили свої
рядки).

**Завдання 4. Виправлення лічильника id.** Для кожної з трьох таблиць
виконайте `setval(pg_get_serial_sequence(...), MAX(id))` (за зразком
вище) і підтвердіть запитом `INSERT` нового рядка без явного `id`,
що лічильник продовжує нумерацію правильно, а не повторює вже зайняте
значення.

**Завдання 5. Перевірка цілісності перенесення.** Для кожної з трьох
таблиць виконайте `SELECT COUNT(*)` у PostgreSQL і порівняйте з
`SELECT COUNT(*)` тієї ж таблиці в SQLite (до перенесення). Письмово
підтвердьте, що числа збігаються, і додатково спробуйте одну свідому
помилку — `INSERT` рядка з зовнішнім ключем, якого не існує в
таблиці-вимірі, — і зафіксуйте точний текст помилки PostgreSQL.

## Що здати й оцінюється

Здайте SQL-скрипт із трьома перекладеними `CREATE TABLE`, підтвердження
збігу `COUNT(*)` для кожної з трьох таблиць, і точний текст помилки з
Завдання 5. Контрольні питання:

- Чому саме `GENERATED ALWAYS AS IDENTITY`, а не старіший `SERIAL`,
  обрано як основний спосіб автоінкременту в цьому курсі — і чим вони
  відрізняються по суті?
- Чому таблиці-вимірювання потрібно перенести (і створити, і
  заповнити даними) ПЕРЕД фактовою таблицею, а не в довільному
  порядку?
- Що сталося б, якби Завдання 4 (виправлення лічильника) пропустити —
  на якому саме кроці це вилилось би в помилку?

Оцінюється коректність перекладеної структури (типи, автоінкремент,
`FOREIGN KEY`), точний збіг кількості рядків до/після перенесення для
всіх трьох таблиць, і правильно виконане виправлення лічильника
(Завдання 4).

## Підсумок заняття

- Створено нову базу даних PostgreSQL і перекладено в ній повну
  трьохтабличну структуру свого варіанта з коректними типами й
  зв'язками.
- Перенесено всі наявні дані через експорт/імпорт CSV, з перевіркою
  збігу кількості рядків.
- На практиці підтверджено й виправлено пастку "збитого" лічильника
  автоінкременту після імпорту рядків із явними `id`.

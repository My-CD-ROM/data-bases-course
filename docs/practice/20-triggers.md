# Практика 20. Реалізація тригерів

*Мета заняття (фінальна практика курсу): написати два тригери за
Лекцією 22 для своєї бази в PostgreSQL — `AFTER`-тригер, що логує
зміни, і `BEFORE`-тригер, що перевіряє й за потреби блокує операцію —
і на практиці підтвердити, що обидва спрацьовують автоматично, без
жодного явного виклику.*

## Варіант

Ваша база у PostgreSQL з Практики 16. Якщо базу втрачено — поверніться
до Практики 16.

## Приклад: наскрізна демонстрація

```sql
CREATE TABLE animal_log (
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    animal_id INTEGER,
    action TEXT,
    old_status TEXT,
    new_status TEXT,
    logged_at TIMESTAMP DEFAULT now()
);

CREATE OR REPLACE FUNCTION log_status_change() RETURNS TRIGGER AS $$
BEGIN
    IF TG_OP = 'INSERT' THEN
        INSERT INTO animal_log (animal_id, action, old_status, new_status)
        VALUES (NEW.id, 'INSERT', NULL, NEW.status);
    ELSIF TG_OP = 'UPDATE' THEN
        INSERT INTO animal_log (animal_id, action, old_status, new_status)
        VALUES (NEW.id, 'UPDATE', OLD.status, NEW.status);
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_log_status
AFTER INSERT OR UPDATE ON animals
FOR EACH ROW
EXECUTE FUNCTION log_status_change();
```

## Завдання

**Завдання 1. Таблиця журналу.** Створіть допоміжну таблицю-журнал
(за зразком `animal_log` вище) для запису історії змін однієї з
таблиць вашого варіанта — колонки: посилання на змінений рядок, тип
операції, старе й нове значення потрібної колонки, час запису
(`DEFAULT now()`).

**Завдання 2. AFTER-тригер для логування.** Напишіть функцію-тригер
(`RETURNS TRIGGER`, з використанням `TG_OP`, `NEW`, `OLD`) і сам
`CREATE TRIGGER` типу `AFTER INSERT OR UPDATE`, що записує в таблицю-
журнал з Завдання 1 кожну зміну статусу чи іншої важливої колонки
основної таблиці вашого варіанта. Перевірте: виконайте `INSERT` і
`UPDATE` над основною таблицею й підтвердьте запитом `SELECT` з
таблиці-журналу, що записи з'явились автоматично.

**Завдання 3. BEFORE-тригер для перевірки.** Напишіть другу
функцію-тригер і `CREATE TRIGGER` типу `BEFORE INSERT OR UPDATE`, що
перевіряє одну бізнес-умову вашого варіанта (наприклад, ціна не може
бути від'ємною, дата виїзду не може бути раніше дати заїзду) і
блокує операцію через `RAISE EXCEPTION`, якщо умова порушена.

**Завдання 4. Перевірка блокування.** Спробуйте виконати `INSERT`
чи `UPDATE`, що порушує умову з Завдання 3. Зафіксуйте письмово
точний текст помилки і підтвердьте окремим `SELECT`, що рядок НЕ
потрапив (чи не змінився) у таблиці.

**Завдання 5. Підсумкова перевірка обох тригерів разом.** Виконайте
послідовність дій, що одночасно демонструє роботу ОБОХ тригерів:
успішна зміна (яка проходить перевірку Завдання 3 і одразу
залогована тригером Завдання 2) і неуспішна спроба (яка блокується
Завданням 3 і тому НЕ повинна з'явитись у журналі Завдання 2).
Письмово підтвердьте обидва результати одним звітом.

## Що здати й оцінюється

Здайте текст обох функцій-тригерів і `CREATE TRIGGER` (Завдання 2-3),
результати перевірок (Завдання 2, 4, 5), і письмові пояснення до
Завдань 4 і 5. Контрольні питання:

- Чому таблиця-журнал (Завдання 1) заповнюється сама, а не через
  окремий `INSERT`, який довелось би писати в кожному місці програми,
  де змінюється основна таблиця?
- Що б змінилося в поведінці тригера з Завдання 3, якби замінити
  `BEFORE` на `AFTER` — чи заблокувалась би операція так само?
- Тепер, коли курс пройшов і `CHECK` (Лекція 5), і тригери (ця
  лекція) як способи перевірки даних — коли варто обрати саме
  тригер, а не простіший `CHECK`?

Оцінюється коректність обох тригерів (правильне використання `NEW`/
`OLD`/`TG_OP`, правильний вибір `BEFORE` проти `AFTER`), точність
зафіксованої помилки в Завданні 4, і повнота підсумкової перевірки
в Завданні 5.

## Підсумок заняття

- Реалізовано `AFTER`-тригер, що автоматично логує зміни основної
  таблиці свого варіанта в окрему таблицю-журнал.
- Реалізовано `BEFORE`-тригер, що перевіряє бізнес-умову й блокує
  операцію, якщо вона порушена — підтверджено навмисною спробою
  порушення.
- Підтверджено спільну роботу обох тригерів в одній послідовності дій
  — це завершує весь курс: від першої таблиці в SQLite до автоматичних
  тригерів у PostgreSQL на тій самій схемі.

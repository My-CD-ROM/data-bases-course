# Лекція 17. Функції у PostgreSQL

*Подання (Лекція 16) чудово зберігають готовий `SELECT`, але не
вміщують умовну логіку: "якщо вік менше року, то 'малюк', інакше..."
доводиться щоразу переписувати громіздким `CASE`. PostgreSQL дозволяє написати
власну **функцію** мовою PL/pgSQL (з умовами, змінними й повторним
використанням, як у звичайній мові програмування) і викликати її
прямо із SQL, наче вона вбудована.*

## 1. CREATE FUNCTION: власна функція мовою PL/pgSQL

```sql
CREATE OR REPLACE FUNCTION animal_age_in_months(age_years INTEGER)
RETURNS INTEGER AS $$
BEGIN
    RETURN age_years * 12;
END;
$$ LANGUAGE plpgsql;
```

`CREATE FUNCTION ім'я(параметри) RETURNS тип AS $$ ... $$ LANGUAGE
plpgsql;` є базовою формою: параметри в дужках (з типами), тип
результату після `RETURNS`, тіло між парою `$$` (заміняє лапки,
щоб не плутати з текстовими літералами всередині), мова `plpgsql`
(процедурна мова PostgreSQL, найпоширеніша для функцій).

## 2. Викликається прямо в SELECT, як вбудована функція

```sql
SELECT name, age, animal_age_in_months(age) FROM animals;
```

Після створення власну функцію можна використовувати в `SELECT`,
`WHERE` чи будь-де в SQL так само, як `COUNT`, `upper` чи будь-яку
іншу вбудовану функцію: `animal_age_in_months(5)`
повертає `60`, а `SELECT ... animal_age_in_months(age) FROM animals`
обчислює значення для кожного рядка.

## 3. Умовна логіка: IF / ELSIF / ELSE

```sql
CREATE OR REPLACE FUNCTION age_category(age_years INTEGER)
RETURNS TEXT AS $$
BEGIN
    IF age_years < 1 THEN
        RETURN 'малюк';
    ELSIF age_years < 7 THEN
        RETURN 'дорослий';
    ELSE
        RETURN 'старший';
    END IF;
END;
$$ LANGUAGE plpgsql;

SELECT name, age, age_category(age) FROM animals;
```

Саме тут функція виграє в порівнянні з поданням чи згенерованою
колонкою (Лекція 14): `IF`/`ELSIF`/`ELSE` дозволяє виразити
багатоваріантну логіку, яку одним виразом `CASE` теж можна б написати,
але яка стає значно читабельнішою й повторно використовуваною як
іменована функція.

## 4. Функція, що повертає ЦІЛУ таблицю рядків

```sql
CREATE OR REPLACE FUNCTION animals_by_species(p_species TEXT)
RETURNS TABLE(id INTEGER, name TEXT, age INTEGER) AS $$
BEGIN
    RETURN QUERY
    SELECT a.id, a.name, a.age FROM animals a WHERE a.species = p_species;
END;
$$ LANGUAGE plpgsql;

SELECT * FROM animals_by_species('кіт');
```

Функція не обов'язково повертає одне число чи рядок: `RETURNS
TABLE(колонки)` разом із `RETURN QUERY` дозволяє повернути ЦІЛИЙ
набір рядків, і викликати таку функцію можна прямо в `FROM`, як
звичайну таблицю чи подання: результат містить саме ті рядки,
що відповідають параметру.

## 5. Пастка: функція НЕ може сама керувати транзакцією

```sql
CREATE OR REPLACE FUNCTION bad_func() RETURNS VOID AS $$
BEGIN
    UPDATE animals SET status = 'x';
    COMMIT;
END;
$$ LANGUAGE plpgsql;

SELECT bad_func();
```

```text
ERROR: invalid transaction termination
CONTEXT: PL/pgSQL function bad_func() line 4 at COMMIT
```

Функція виконується ВСЕРЕДИНІ транзакції того, хто її викликав
(Лекція 12). Вона не може сама зробити `COMMIT` чи `ROLLBACK`;
помилка виникає саме в момент виклику, а не при
створенні функції. Якщо потрібна логіка, що сама фіксує зміни
частинами, для цього в PostgreSQL є окремий вид об'єкта, **процедура**
(Практики 22-23).

## 6. Змінні, DECLARE і SELECT INTO

Досі функції працювали лише з власними параметрами. У PL/pgSQL можна оголошувати **змінні**: іменовані комірки для проміжних значень. Їх описують у блоці `DECLARE`, який стоїть перед `BEGIN`, а значення з таблиці до змінної читають командою `SELECT ... INTO`. Розглянемо функцію, що формує короткий підсумок про власника:

```sql
CREATE OR REPLACE FUNCTION owner_summary(p_owner_id INTEGER)
RETURNS TEXT AS $$
DECLARE
    v_name TEXT;
    v_cnt  INTEGER;
BEGIN
    SELECT last_name INTO v_name FROM owners WHERE id = p_owner_id;

    IF NOT FOUND THEN
        RAISE EXCEPTION 'Власника з id % не існує', p_owner_id;
    END IF;

    SELECT COUNT(*) INTO v_cnt FROM animals WHERE owner_id = p_owner_id;

    RETURN v_name || ': тварин ' || v_cnt;
END;
$$ LANGUAGE plpgsql;
```

Префікси `p_` для параметрів і `v_` для змінних не обов'язкові, але корисні: вони не дозволяють переплутати їх з назвами колонок. Якщо параметр назвати `owner_id`, а в таблиці є колонка з тією ж назвою, PostgreSQL повідомить про неоднозначність.

Виклик для наявного власника і для неіснуючого:

```sql
SELECT owner_summary(1);
SELECT owner_summary(99);
```

```text
 owner_summary
--------------------
 Петренко: тварин 2

ERROR:  Власника з id 99 не існує
CONTEXT:  PL/pgSQL function owner_summary(integer) line 9 at RAISE
```

Тут використано дві нові речі. Спеціальна змінна `FOUND` після `SELECT ... INTO` дорівнює `true`, якщо запит повернув рядок, і `false` в іншому разі. А команда `RAISE EXCEPTION` перериває виконання функції з повідомленням про помилку; символ `%` у тексті підставляє значення наступного аргументу. Це правильний спосіб повідомити про недопустимі вхідні дані: функція не повертає сумнівний результат, а явно зупиняється.

## 7. NULL у функції: пастка з IF

Повернімось до функції `age_category` із розділу 3. Що вона поверне для тварини, вік якої невідомий (`NULL`)? Порівняння `NULL < 1` не дає ні `true`, ні `false`, а дає невизначений результат, і `IF` трактує його як хибний. Те саме відбувається з `ELSIF`, тож керування доходить до гілки `ELSE`:

```sql
SELECT age_category(NULL);
```

```text
 age_category
--------------
 старший
```

Тварина з невідомим віком стала «старшою»: програма не видала помилки, але результат хибний. Виправити просто: явно обробити `NULL` першою гілкою.

```sql
CREATE OR REPLACE FUNCTION age_category(age_years INTEGER)
RETURNS TEXT AS $$
BEGIN
    IF age_years IS NULL THEN
        RETURN 'вік невідомий';
    ELSIF age_years < 1 THEN
        RETURN 'малюк';
    ELSIF age_years < 7 THEN
        RETURN 'дорослий';
    ELSE
        RETURN 'старший';
    END IF;
END;
$$ LANGUAGE plpgsql;
```

Тепер `age_category(NULL)` повертає `вік невідомий`. Це загальне правило для будь-якого коду, що працює з даними: після кожного порівняння питайте себе, що станеться, якщо значення відсутнє.

## 8. Функція в WHERE та інших частинах запиту

Результат функції можна використовувати не лише в `SELECT`, а й там, де потрібне значення: у `WHERE`, `ORDER BY`, `GROUP BY`. Знайдемо всіх дорослих тварин:

```sql
SELECT name FROM animals WHERE age_category(age) = 'дорослий' ORDER BY id;
```

```text
  name
--------
 Мурка
 Барсик
 Пушок
```

Це зручно, але має ціну. Функція викликається для кожного рядка таблиці, тож на великих таблицях такий запит буде повільнішим за порівняння з готовою колонкою. До того ж індекс (Лекція 13) на колонці `age` для умови `age_category(age) = ...` не допоможе, як і з будь-яким виразом над колонкою.

## 9. Проста функція мовою SQL

Якщо в тілі функції лише один запит, немає потреби в `BEGIN`, змінних і `IF`: достатньо мови `sql`, у якій тіло записується просто як `SELECT`:

```sql
CREATE FUNCTION count_by_species(p_species TEXT)
RETURNS INTEGER AS $$
    SELECT COUNT(*)::INTEGER FROM animals WHERE species = p_species;
$$ LANGUAGE sql;

SELECT count_by_species('кіт'), count_by_species('птах');
```

```text
 count_by_species | count_by_species
------------------+------------------
                2 |                0
```

Запис `::INTEGER` явно приводить результат до цілого типу: `COUNT` у PostgreSQL повертає `BIGINT`, а функцію оголошено як `INTEGER`. Нові версії PostgreSQL приводять тип самі, старіші без цього видавали помилку, тож явне приведення краще лишити. Для одного запиту обирайте `sql`, бо код коротший і читабельніший. Якщо потрібні змінні, умови, цикли чи обробка помилок, обирайте `plpgsql`.

## 10. Перегляд, перевантаження і видалення функцій

У PostgreSQL можуть існувати кілька функцій з однаковою назвою, якщо в них різні типи параметрів. Це називається **перевантаженням** (overloading). Наприклад, щоб передавати вік у частках року (0.5 для цуценяти), поруч із `age_category(INTEGER)` можна створити `age_category(NUMERIC)`, і PostgreSQL за типом аргументу сам вибере потрібну (виклик із голим `NULL` тоді стає неоднозначним і потребує приведення: `age_category(NULL::INTEGER)`). Через це функція ідентифікується не лише назвою, а й списком типів параметрів. Якщо функцій із такою назвою кілька, видалення за самою назвою завершується помилкою:

```sql
DROP FUNCTION age_category;
```

```text
ERROR:  function name "age_category" is not unique
HINT:  Specify the argument list to select the function unambiguously.
```

Потрібно вказати типи: `DROP FUNCTION age_category(NUMERIC);`. Перелік наявних функцій і їхні параметри в `psql` показує команда `\df age_category`, а у `pgAdmin` вони відображаються у вітці **Functions** вашої бази.

Звідси правило: змінюючи наявну функцію, використовують `CREATE OR REPLACE FUNCTION`, але з **тією самою** сигнатурою (назва плюс типи параметрів). Якщо змінити тип параметра, PostgreSQL створить нову, перевантажену функцію, а стара залишиться.

## 11. Запитання для самоперевірки

**Для чого потрібен блок `DECLARE` у функції?**

Він оголошує локальні змінні для проміжних значень. Блок пишуть перед `BEGIN`, кожну змінну з типом.

**Що робить `RAISE EXCEPTION` і чим це краще за повернення спеціального значення на кшталт `-1`?**

Перериває виконання функції з повідомленням про помилку. Помилку неможливо проігнорувати, а спеціальне значення викликач може не перевірити й продовжити роботу з хибними даними.

**Яким буде результат `age_category(NULL)` у функції з розділу 3 і чому?**

`старший`. Порівняння з `NULL` дає невизначений результат, що в `IF` вважається хибним, тож виконується гілка `ELSE`. Потрібна окрема перевірка `IF age_years IS NULL`.

**Коли замість `plpgsql` досить `LANGUAGE sql`?**

Коли тіло функції складається з одного запиту: змінні, умови й цикли не потрібні.

**Чому `DROP FUNCTION age_category` може завершитись помилкою, хоча функція існує?**

Існує кілька перевантажених функцій з цією назвою, і PostgreSQL не знає, яку видалити. Потрібно вказати типи параметрів: `DROP FUNCTION age_category(NUMERIC)`.

## Підсумок

- `CREATE FUNCTION ім'я(параметри) RETURNS тип AS $$ ... $$ LANGUAGE
  plpgsql;`: власна функція, яку можна викликати прямо в SQL, як
  вбудовану.
- `IF`/`ELSIF`/`ELSE` усередині функції дозволяє записати
  багатоваріантну логіку один раз і викликати її за іменем замість
  повторення `CASE` у кожному запиті.
- `RETURNS TABLE(...)` + `RETURN QUERY` дозволяє функції повернути
  цілий набір рядків, а не одне значення.
- Функція не може сама викликати `COMMIT`/`ROLLBACK`: вона завжди
  виконується в межах транзакції викликача; помилка "invalid
  transaction termination" виникає саме при спробі це зробити.
- У функції `NULL` потрібно обробляти явно (`IS NULL`): порівняння з `NULL` в `IF` вважається хибним, і керування йде в `ELSE`.
- Для функції з одним запитом достатньо `LANGUAGE sql`; змінні, умови й помилки потребують `plpgsql`.

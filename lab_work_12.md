# Практична робота 12. Сортування і фільтрація даних

**Варіант 3 — база даних кінотеатру**

## Мета роботи

Навчитися впорядковувати записи за одним і кількома стовпцями, обмежувати кількість результатів, отримувати унікальні значення та застосовувати умови фільтрації `BETWEEN` і `LIKE`.

## Завдання 1. Сортування за одним стовпцем

Для сортування квитків за ціною використано запит:

```sql
SELECT id, hall, showtime, price
FROM tickets
ORDER BY price DESC;
```

Отримано п’ять записів у порядку спадання ціни: 200, 190, 180, 170 і 150. Першим відображається квиток з `id = 2`, оскільки його ціна 200 — найбільша серед наявних. Ключове слово `DESC` задає спадний порядок.

## Завдання 2. Сортування за двома стовпцями

```sql
SELECT id, hall, showtime, price
FROM tickets
ORDER BY hall ASC, showtime DESC;
```

Спочатку записи впорядковано за номером залу за зростанням (`ASC`). Якщо декілька квитків належать до одного залу, додаткове сортування відбувається за часом сеансу за спаданням (`DESC`). Другий стовпець визначає порядок лише всередині груп із однаковим значенням першого стовпця.

## Завдання 3. Обмеження результатів за допомогою LIMIT

```sql
SELECT id, hall, showtime, price
FROM tickets
ORDER BY price DESC
LIMIT 3;
```

Запит повернув три найдорожчі квитки: 200, 190 і 180. Спочатку необхідно застосувати `ORDER BY`, щоб отримати правильний порядок за ціною, і лише після цього `LIMIT 3` залишає перші три рядки. Якщо використати `LIMIT` без потрібного сортування, це не гарантує вибір саме найдорожчих квитків.

## Завдання 4. Унікальні значення та діапазон

### 4.1. Отримання унікальних жанрів

```sql
SELECT DISTINCT genre
FROM movies
ORDER BY genre;
```

Результат містить чотири різні жанри: `Animation`, `Drama`, `Fantasy`, `Sci-Fi`. `DISTINCT` прибирає повтори, тому кожен жанр відображається один раз.

### 4.2. Фільтрація за діапазоном ціни

```sql
SELECT id, price
FROM tickets
WHERE price BETWEEN 150 AND 200
ORDER BY price;
```

Отримано п’ять квитків із цінами 150, 170, 180, 190 і 200. Обрано `BETWEEN`, оскільки потрібно знайти всі значення в числовому діапазоні. Межі включаються до результату. Оператор `IN` був би доречним для перевірки конкретного переліку окремих значень.

## Завдання 5. Пошук тексту за допомогою LIKE

Для перевірки використано два запити:

```sql
SELECT last_name FROM viewers WHERE last_name LIKE 'К%';
SELECT last_name FROM viewers WHERE last_name LIKE 'к%';
```

Для великої кириличної літери `К` знайдено прізвище `Ковальчук` — один запис. Для малої літери `к` записів не знайдено. Отже, у цьому експерименті SQLite розрізняє великі та малі кириличні літери під час порівняння через `LIKE`. Символ `%` означає будь-яку послідовність символів після заданої початкової літери.

## Контрольні запитання

**1. Чому ORDER BY має стояти перед LIMIT?**

Спочатку потрібно впорядкувати всі рядки за заданою ознакою, а потім обмежити результат потрібною кількістю записів. Інакше вибрані рядки не обов’язково будуть найпершими за потрібним критерієм.

**2. Чим IN відрізняється від BETWEEN?**

`IN` перевіряє, чи дорівнює значення одному зі значень у заданому списку. `BETWEEN` перевіряє, чи входить значення в діапазон між двома межами, включно з ними.

**3. Чи важливий регістр кирилиці в SQLite?**

Так, у проведеному експерименті регістр кириличних символів вплинув на результат: `LIKE 'К%'` знайшов один запис, а `LIKE 'к%'` — жодного. Для ASCII-символів поведінка SQLite може бути іншою.

## Висновок

Під час практичної роботи було опрацьовано сортування за одним і кількома стовпцями за допомогою `ORDER BY`, обмеження результатів оператором `LIMIT`, усунення повторів через `DISTINCT`, а також фільтрацію за діапазоном і текстовим шаблоном за допомогою `BETWEEN` та `LIKE`. Експеримент із кирилицею показав, що регістр літер може впливати на результати пошуку.

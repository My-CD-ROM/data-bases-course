## Структура бази даних

У роботі використано наявну базу даних інтернет-магазину одягу з таблицями `products`, `customers` та `orders`. Фактова таблиця `orders` містить інформацію про замовлення, дати, кількість товарів і статуси.

## Завдання 1. ORDER BY за однією колонкою

Використано запит:

```sql
SELECT id, product_id, customer_id, order_date, quantity, status
FROM orders
ORDER BY order_date DESC;
```

Запит сортує замовлення за датою у спадному порядку. Першим є замовлення з найпізнішою датою — **[вкажіть ID і дату першого рядка з результату]**.

Такий порядок дає змогу побачити найновіші замовлення на початку результату.

## Завдання 2. ORDER BY за кількома колонками

Використано запит:

```sql
SELECT id, status, order_date, quantity
FROM orders
ORDER BY status ASC, order_date DESC;
```

Спочатку замовлення сортуються за статусом у порядку зростання, а в межах кожного статусу — за датою від найновішої до найстарішої.

Друга колонка сортування `order_date` визначає порядок записів з однаковим статусом. Без неї порядок дат усередині таких груп не був би визначений запитом.

## Завдання 3. Топ-3 через ORDER BY і LIMIT

Використано запит:

```sql
SELECT id, product_id, customer_id, order_date, quantity, status
FROM orders
ORDER BY order_date DESC
LIMIT 3;
```

Запит повертає три найновіші замовлення.

`ORDER BY` спочатку впорядковує записи за датою, а `LIMIT 3` залишає лише перші три. Якщо прибрати `ORDER BY`, база поверне три рядки без гарантії, що вони будуть найновішими.

Результат: три замовлення з найпізнішими датами — **[запишіть ID і дати трьох рядків із результату]**.

## Завдання 4. DISTINCT та IN

### 4а. Унікальні категорії

Використано запит:

```sql
SELECT DISTINCT category
FROM products
ORDER BY category ASC;
```

`DISTINCT` прибирає повторення категорій. У результаті отримано **[вкажіть кількість унікальних категорій]** унікальних значень.

### 4б. Фільтрація через IN

Використано запит:

```sql
SELECT id, order_date, status
FROM orders
WHERE status IN ('виконано', 'очікує', 'скасовано')
ORDER BY order_date DESC;
```

Оператор `IN` вибирає замовлення, статус яких входить до зазначеного списку. Він доречний, коли потрібно перевірити належність значення до кількох конкретних варіантів.

`BETWEEN` краще використовувати для діапазону значень, наприклад дат або чисел. У цьому завданні обрано `IN`, оскільки фільтрація виконується за переліком статусів.

## Завдання 5. LIKE і регістр кирилиці

Для перевірки використано два запити:

```sql
SELECT name FROM products WHERE name LIKE 'Ф%';
```

```sql
SELECT name FROM products WHERE name LIKE 'ф%';
```

Перший запит шукає назви, що починаються з великої української літери «Ф», а другий — з малої «ф».

У SQLite оператор `LIKE` за замовчуванням не розрізняє регістр латинських символів ASCII, але для кирилиці поведінка інша: велика та мала літери зазвичай не збігаються.

- Кількість збігів для `LIKE 'ф%'`: **[вкажіть результат другого підрахунку]**.

Різниця важлива, оскільки текстові дані українською мовою можуть містити великі й малі літери. Під час пошуку потрібно враховувати регістр, щоб не пропустити потрібні записи.

## Контрольні питання

### 1. Чому ORDER BY потрібно писати перед LIMIT?

`ORDER BY` визначає порядок рядків, а `LIMIT` обмежує кількість результатів. Якщо прибрати `ORDER BY`, запит із `LIMIT 3` не гарантує вибір трьох найбільших або найновіших записів.

### 2. Коли використовують IN, а коли BETWEEN?

`IN` застосовують для перевірки значення на належність до конкретного списку. `BETWEEN` використовують для вибору значень у межах діапазону, включно з його крайніми значеннями.

### 3. Чому важливо перевіряти регістр кирилиці в LIKE?

Тому що SQLite за замовчуванням може по-різному обробляти великі та малі кириличні літери. Через це пошук українських назв і прізвищ може повертати різну кількість результатів.

\# Практична робота №6



\## Тема



Робота з командами оновлення та видалення у SQLite.



\## Варіант



Бібліотека.



\## Студентка



Вовк Марія, група І-23.



\## Мета роботи



Навчитися використовувати команди `UPDATE` та `DELETE` у SQLite, перевірити дію обмежень цілісності даних після зміни та видалення записів, а також перевірити роботу зовнішніх ключів із правилами `ON DELETE`.



\## Завдання 1. UPDATE запису таблиці loans



Було оновлено конкретний запис таблиці `loans` за первинним ключем:



```sql

UPDATE loans

SET return\_date = '2026-09-20'

WHERE id = 6;

```



Для перевірки було виконано:



```sql

SELECT \* FROM loans

WHERE id = 6;

```



Дата повернення для запису з `id = 6` змінилася на `2026-09-20`.



\## Завдання 2. UPDATE значення у таблиці books



Було збільшено кількість примірників книги з `id = 8`:



```sql

UPDATE books

SET copies\_count = copies\_count + 1

WHERE id = 8;

```



\### Чому використано UPDATE, а не DELETE + INSERT?



Команда `UPDATE` використовується тому, що змінюється лише окреме значення вже існуючого запису. Сама книга залишається тією самою, тому видаляти запис і створювати його заново немає потреби.



Також було перевірено обмеження `CHECK`:



```sql

UPDATE books

SET copies\_count = -1

WHERE id = 8;

```



SQLite відхилив зміну через умову:



```text

CHECK constraint failed: copies\_count >= 0

```



Отже, обмеження `CHECK` працює і під час виконання `UPDATE`.



\## Завдання 3. DELETE одного запису



Спочатку кількість записів у таблиці `loans` становила 10.



Було виконано:



```sql

DELETE FROM loans

WHERE id = 10;

```



Після видалення кількість записів стала 9.



Запис із `id = 10` більше не знаходиться в таблиці.



Використання умови `WHERE id = 10` забезпечило видалення лише одного конкретного запису.



\## Завдання 4. Перевірка ON DELETE



Для таблиці `loans` були встановлені такі зовнішні ключі:



```text

book\_id → books.id

ON DELETE RESTRICT



reader\_id → readers.id

ON DELETE CASCADE

```



\### ON DELETE CASCADE



Для читачів використовується `ON DELETE CASCADE`.



Після виконання:



```sql

DELETE FROM readers

WHERE id = 1;

```



пов'язаний із цим читачем запис у таблиці `loans` був автоматично видалений.



Отже, `CASCADE` автоматично поширює видалення батьківського запису на пов'язані дочірні записи.



\### ON DELETE RESTRICT



Для книг використовується `ON DELETE RESTRICT`.



При спробі видалити книгу, яка використовується в таблиці `loans`:



```sql

DELETE FROM books

WHERE id = 2;

```



SQLite не дозволив виконати операцію та повідомив про помилку зовнішнього ключа.



Отже, `RESTRICT` не дозволяє видалити батьківський запис, якщо на нього посилаються записи дочірньої таблиці.



\## Відповіді на контрольні питання



\### 1. Чим відрізняється UPDATE за умовою від UPDATE конкретного рядка?



`UPDATE` з умовою `WHERE` змінює всі записи, які відповідають цій умові. Якщо умова визначає первинний ключ конкретного запису, змінюється лише один рядок.



Наприклад:



```sql

UPDATE books

SET copies\_count = 5

WHERE id = 8;

```



змінює тільки книгу з `id = 8`.



\### 2. Як обмеження цілісності впливають на UPDATE?



Під час `UPDATE` SQLite перевіряє встановлені обмеження. Наприклад, `NOT NULL`, `UNIQUE`, `CHECK` та зовнішні ключі можуть заборонити зміну, якщо нове значення порушує умови таблиці.



У цій роботі обмеження `CHECK (copies\_count >= 0)` не дозволило встановити кількість примірників рівною `-1`.



\### 3. У чому різниця між ON DELETE CASCADE та ON DELETE RESTRICT?



`ON DELETE CASCADE` автоматично видаляє пов'язані дочірні записи після видалення батьківського запису.



`ON DELETE RESTRICT` забороняє видалення батьківського запису, якщо на нього існують посилання з дочірньої таблиці.



\### 4. Що станеться, якщо виконати DELETE без WHERE?



Команда `DELETE` без `WHERE` видалить усі записи таблиці.



Наприклад:



```sql

DELETE FROM loans;

```



видалить усі записи з таблиці `loans`.



Тому перед виконанням `DELETE` потрібно перевіряти умову `WHERE`, щоб випадково не видалити всі дані.



\## Висновок



Під час практичної роботи було освоєно використання команд `UPDATE` та `DELETE` у SQLite. Було виконано оновлення конкретного запису та значення в таблиці книг, перевірено роботу обмеження `CHECK`, видалено конкретний запис за первинним ключем. Також було перевірено роботу зовнішніх ключів із правилами `ON DELETE CASCADE` та `ON DELETE RESTRICT`.



У результаті було підтверджено, що SQLite контролює цілісність даних під час операцій оновлення та видалення.
